# @mica-js/playground

Mica 的交互式示例站点。主页面直接使用 `@mica-js/editor` 的 `createSchematicEditor` 与
`createCanvasEditor`：

- 顶部文档选择在 `runtime-demo/example.cnv`（画布）和 `runtime-demo/example.sch`（原理图）之间切换。
- 画布提供编辑/仿真模式切换，以及撤销、重做、视图缩放、适应内容、视图重置、运行、暂停、单步、复位和下载。
- 编辑模式下可拖动 widget、拖动选框角点调整尺寸；滚轮缩放视图，中键拖动或空格加左键拖动平移视图。
- 原理图提供撤销、重做和下载。
- 右侧集成面板列出文档对象并显示当前选择与属性；属性编辑统一通过 `schematic.setProperties` /
  `canvas.setProperties` 提交，可单独移除覆盖值恢复默认。画布另显示端口绑定和关联原理图，双击对象会
  打开面板并聚焦属性区。
- 下载内容来自应用侧保存的最新初始快照或 `onDidChangeContent` 快照，由 `serializeCanvas` /
  `serializeSchematic` 写出。编辑器只负责文档状态，不执行保存。

## 运行时示例

主页面消费 [playground-components](../../examples/playground-components/) 的 SDK CLI 产物，
`public/runtime-demo` 只保存示例原理图和画布，不维护器件或 Widget 的预编译副本。

电路使用固定板级 `VCC = 5 V` 和接地参考，串联 330 Ω 电阻、LED 与常开按钮，电压表并联在 LED
两端。没有独立电源器件。LED 使用 100 Ω 简化电阻负载；仅正向电流产生亮度，反向不发光，电气模型
仍允许反向电流，不模拟二极管截止或压降。按钮闭合为 1 Ω，断开为 1 GΩ；电压表输入阻抗为 10 MΩ。
电阻、LED 和按钮隐藏引脚名称；电压表仅在符号内显示 `+ / -` 极性标识。

- `demo:button.press -> demo:push-button.press`：按住闭合，松开或取消指针时断开。
- `demo:led.brightness -> demo:led-indicator.brightness`：显示正向电流对应的亮度。
- `demo:voltmeter.voltage -> demo:voltmeter.voltage`：显示 LED 两端电压。

进入仿真模式并运行后，按住按钮点亮 LED，电压表约为 1.16 V；松开后熄灭并回到约 0 V。
主线程只读取 JSON 和 JS，代码只在编辑器的 sandbox 中执行。每个组件的交付产物只有一份 JS 和一份
JSON；依赖与资源全部内联，产物不含运行时模块导入、动态导入或独立资源文件。

## SDK CLI 集成

`dev` / `build` 首先构建 SDK 及其依赖，保证干净工作区中 CLI 入口可用。

- 开发：先执行一次 `mica build`，将组件产物复制到忽略提交的 `public/components`，再启动普通 Vite
  开发服务。可传 `--host`、`--port`、`--strictPort`、`--open`。
- 更新：应用源码由 Vite 正常热更新；组件源码变更后重新运行 Playground `dev`，不自动重建组件。
- 生产：同样先构建组件并复制到 `public/components`，再由 Vite 构建应用并复制静态产物。组件构建失败时
  停止应用构建。部署后通过相同的 `/components/` 路径加载，不依赖独立组件服务。

生成目录和 DDL 类型声明均由仓库忽略，源码是唯一维护入口。

## CT107D

本 playground 不再提供旧 CT107D v1 widget 画布入口：它依赖 legacy `device.json/device.js`，而统一器件包只提供 `package.json/model.js`，不能直接复用。CT107D 的正式宿主是 `examples/ct107d`，在仓库根目录运行：

```shell
pnpm --dir examples/ct107d run workbench:dev
```

不要从统一器件包向本 playground 伪造 legacy 产物。

## 独立 device demo

`pnpm --filter @mica-js/playground dev:workbench` 启动的 `/workbench.html` 展示融合编辑器。
选择轻触开关可体验内存与文件集程序属性：“更换”菜单提供资产库、项目和包内资源；
资产与项目通过宿主对话框选择，编辑器按身份读取并校验，再提交引用。宿主项目选择框可按推荐模板 ID 创建项目，
并支持打开项目及内存装载设置浏览；文件集资产使用 ZIP，项目直接提供文件集。宿主直接传入文档，保存回调写入 localStorage。
这些属性演示程序来源与快照集成，开关模型继续只模拟按键通断。

点击“89C52 示例”打开 `AT89C52 + S1 + D1 + BZ1` 电路。U1 的 `program` 默认从器件包加载
`assets/key-led-buzzer.hex`，同目录提供汇编源码；也可在属性面板选择资产或项目产物。程序装载到
8 KiB 内部 Flash，默认晶振 12 MHz，按经典 12T 机器周期执行仓库既有 8051 译码器生成的指令。
S1 将 P3.2 拉低，固件读取引脚后将 P1.0、P1.1 拉低，分别点亮 D1、使 BZ1 发声；松开后关闭。
蜂鸣器按两端实际电压触发 2 kHz 方波，按键本身只改变电气通断。进入运行模式即可交互，退出运行会释放声音。

此器件示例实现 CPU、内部 RAM、GPIO 锁存、P0 开漏和 P1–P3 的简化弱上拉，显示 DIP-40 全部引脚；
时钟由属性提供，复位由运行时重建实例。定时器、串口、中断、外部总线及外部复位输入尚未建模，
访问相应 SFR、外部存储器指令或 RETI 会明确报错。它用于验证 GPIO 固件闭环，完整外围外设可继续复用并适配既有内核。

编辑态可拖动导线中的某一段，邻接折点随动、连接锚点保持不变；空格将幽灵预览或选中的器件、电源和接地符号顺时针旋转 90°，中键拖动画布。位号、独立网标和符号内嵌网名可独立拖动，位置随文档保存；电源和接地符号用虚线框选中，可旋转或删除。单击尚未连接导线的引脚或端子自动开始画线，已连接时保持选择，手动接线工具仍可追加连接；拖开附着引脚的端子会创建独立锚点和连接导线，后续拖动保持连接。内容修改支持撤销、重做，运行态和只读态保持锁定。

`device-demo.html` 仍作为独立入口保留，展示 `public/device-demo` 中的元数据符号与原理图编辑，不启动
仿真。

## 引脚融合交互原型

`/fusion-demo.html` 以 AT89C52、LED 和 16 个独立轻触开关组成 4×4 矩阵，演示单一场景中的逐引脚接线：

- 场景按封装真实尺寸绘制，1 单位 = 0.2 mm：AT89C52 为 DIP-40（50.8 × 15.2 mm，脚距 2.54 mm，脚号与真实封装一致），16 个 SMD 轻触开关各为 6 × 6 × 5 mm（1.6 × 1.2 mm 四角焊盘、3.5 mm 圆形按帽、12.4 mm 中心距），LED 与 330 Ω 电阻为 SMD 1206（3.2 × 1.6 mm）。
- 每个开关是独立器件（S1–S16，4 个引脚）：1 / 2 为同一触点、3 / 4 为另一触点，器件内部由细线标出短接关系；点击 2 或 4 号脚按 1 / 3 号脚处理，不会误判成第二个网络。
- 每个器件分为四层：抓取层（拖动与选中）、底图（封装外形、丝印、焊盘）、状态覆盖层（发光点、按键闭合、扫描高亮）、引脚层（命中区与脚名）。隐藏底图时其余三层保留。
- 画风为扁平技术图：细线描边、平涂填充，不使用渐变、投影或写实材质；LED 画成两点焊盘加中间发光点，点亮时发光点变红并带光晕；开关画成深色方体、圆形按帽与四角焊盘。
- 只有编辑与运行两种模式：编辑模式同时完成布局与接线，运行模式只观测状态。
- 运行视图的三个显示选项——底图、接线与引脚、位号——在编辑态即可设置，切换到运行后生效；编辑态始终显示底图、导线、引脚与位号。
- 运行模式默认隐藏导线与引脚，只留器件状态层；勾选“运行时显示接线”恢复完整导线和引脚。
- 运行模式可按器件关闭底图（检查器勾选框或全局开关）。底图关闭后只保留状态覆盖层与位号，单片机这类纯逻辑器件可完全退出画面。
- 位号（U1 / S1–S16 / D1 / R1）可单独隐藏，取消“运行时显示位号”后 LED 只留 ON/OFF、电阻只留 330Ω、开关只留按帽上的按键字符。
- 滚轮以鼠标位置为中心缩放，按钮相对适应视图缩放 0.25–32 倍；中键或空格 + 左键拖动平移，适应画布恢复视图。
- 双击芯片或点击检查器的“放大引脚”进入 180% 视图；实际缩放达到 150% 后显示 MCU 脚名和脚号，低倍率点击 MCU 引脚先聚焦再接线。
- 导线 0.9 屏幕像素，命中宽度 8 屏幕像素；引脚命中区域最小 11 屏幕像素，并限制为不超过脚距的 85%，避免邻脚抢占点击。缩放和平移不修改网络。
- 矩阵网络按总线绘制：每一行有一条行总线，行内 4 个开关的 1 号脚引出短支线接入；每一列有一条列总线，列内开关的 3 号脚引出短支线接入，再由一条引线接到 MCU 的 P1.0–P1.7。
- 运行时 P1.0–P1.3 扫描行、P1.4–P1.7 读取列，P2.0 低电平驱动 LED；按住任一开关点亮，松开熄灭，支持指针和空格 / Enter。断开任一行或列，该行或列的开关无法识别。
- 接线在编辑模式完成：点击两个引脚建立或合并网络；点击网络查看成员和断开。供电通过理想网标表示，禁止直接合并 +5V 与 GND。
- 导出完整引脚、网络成员、以 mm 标注的尺寸和每个开关各自的 `press` 绑定 `89c52-keys-led.demo.json`；重置恢复初始场景。

这是交互设计原型，运行采用本地矩阵扫描逻辑，未执行 8051 固件、未接入仿真内核；时钟和复位由
演示逻辑提供。导出为独立演示格式，不作为现有 `.sch` / `.cnv` 加载；拖动包含器件碰撞检查，
导线使用简化折线，尚无障碍物绕线。按键识别演示独立单键通路，不模拟多键鬼键与模拟电压。

仅预览此原型时，无需构建组件，在仓库根目录运行：

```bash
pnpm --filter @mica-js/playground exec vite --host 127.0.0.1 --port 5198 --strictPort
```

打开 `http://127.0.0.1:5198/fusion-demo.html`。

## 板外器件接线与装配原型

`/mount-demo.html` 用 three.js 演示“板内电路 / 板外形 / 线束”三层分离：

- 板是装配视图里的一个器件：切面尺寸 76 × 60 mm，双击板打开它的 2D 电路文档（内嵌 `/fusion-demo.html`），板内走线继续用原编辑器编辑。
- 接头（connector）是一等数据：每个器件下挂 `connectors[]`，带 `kind`（排针排母 / FPC 座 / JST 端子 / 散线端子）、`pitch`、`gender`、`contacts`、`mates` 与线缆形态；引脚用 `connector` 归属到接头。
- 校验分三层：接头能不能插（形态、芯数）→ 引脚角色是否匹配（+5V 与 GND 不短接、电源接 GPIO 提示）→ 系统级拓扑（同一接头的芯必须落在同一个板端接头、排线线序固定不能跳接、器件引脚只能接一根）。
- 线束以“一次接头插合”为单位渲染：一束 = 一根主干 + 两端散开的单芯，电气仍是逐芯网络。侧栏与检查器按 `CX1…` 列出每一束、芯数与跨距。
- 端子按真实形态建模，而不是球形顶点：排针是黑塑料条 + 方针 + 焊盘，排母是金属框插孔，FPC 座是 ZIF 壳体 + 金手指触点 + 翻盖，JST 是带卡扣的塑料壳；接线点在金属顶端。
- 圆线单芯外径 0.34 mm 量级，细到不像管线；点选靠同轴的不可见拾取代理，端子优先于线缆响应点击。
- FPC 排线是实体扁带：截面宽度 = 该接头触点跨距、厚度 0.32 mm，正面贴印刷导体纹理（芯数可数）、背面是均质聚酰亚胺、两侧有基材切边；两端有金手指、pin 1 标记与加强板直段。
- 排线按标准长度件处理：给定弧长（30 / 50 / 100 mm）反解走向，两端加强板段不允许弯折；直线跨度超过线长时在检查器里报“线长不足”并画出绷直状态。
- 3D 场景有器件标签跟随投影、选中高亮（器件体与线束分别着色）、轨道相机与滚轮缩放；运行模式下舵机摆臂与电机轴动起来。
- 2D 编辑器视图用同一份数据与同一套束线路由：圆线束主干 + 扇出、排线画成 5.4 mm 宽的扁带并用沿长度方向的 8 根导体线区分芯号，引脚与线束坐标完全一致。
- 器件可用真实 GLB 模型替换占位盒体：模型用 `GLTFLoader` + `DRACOLoader`（解码器在 `public/draco/`）加载，按最长边归一成 mm、居中、按 `PART_MODELS` 里的姿态与抬升量摆到器件基准面上；M1 是 TT 电机本体加轮胎（轮胎挂在输出轴端，运行模式沿 X 轴转动），Q1 是 HC-SR04 超声波模块。模型几何与材质进缓存，场景重建时不会重复加载也不会被销毁。
- 模型文件放在 `public/models/`：`tt-motor.glb`、`tt-wheel.glb`、`ultrasonic.glb`（约 30 MB，主要来自 2K PBR 贴图）。

打开 `http://127.0.0.1:5198/mount-demo.html`。

## 运行

在仓库根目录运行：

```bash
pnpm --filter @mica-js/playground dev
```

开发服务器地址以终端输出为准。打开首页即可使用主示例；`/device-demo.html` 打开独立器件演示。
