.. _spec-model:

================================================
核心模型
================================================

本章定义器件仿真中的基本对象及其关系。后续语言、IR 和运行时章节使用同一组术语，并在此基础上细化各操作的行为。

.. _spec-device-definition:

器件定义与实例
------------------------------------------------

**器件定义** 描述一种器件的属性、资源和行为，由一个共享 ``DeviceIR`` 模型及其配对的 JavaScript 工厂组成。模型可由 DDL 编译或 TypeScript Builder 构造，两种来源具有相同地位。

模型声明器件的引脚、状态、存储和通信端点，以及这些资源如何随输入和时间变化。JavaScript 工厂创建实例的适配对象，通过仿真接口参与消息交换、资源初始化和动态 IR 生成。

器件库通过显式登记关联器件类型标识、模型与 JavaScript 工厂。登记的 ``id`` 用于装配引用，与 ``model.name`` 相互独立；模型名称用于定义及诊断，不参与自动配对或库类型标识唯一性检查。若模型来自 DDL，模型名称取文件内唯一 ``device`` 的声明名称；枚举、记录和函数位于器件内部，DDL 不使用模块、导入、导出或跨文件复用。文件名和显示名称各自保留其用途。

**器件实例** 是器件定义在一组属性下创建的运行对象。每个实例拥有独立的状态、存储、通道和 JavaScript 适配对象；同一定义的多个实例可以复用编译结果。

同一定义的两个实例分别拥有各自的通道队列。向其中一个实例发送消息，只影响该实例的队列。

**属性** 是实例创建时确定、在该实例生命周期内保持不变的静态配置，统一称为 ``props``。模型声明属性类型与默认值，装配时完成校验和补全，配对 JavaScript 通过 ``ctx.props`` 读取同一份结果。

.. _spec-board:

板与装配
------------------------------------------------

**板（Board）** 是一组器件实例及其电气网络的平坦装配。器件是装配的最小单元；板独立记录实例标识、器件类型、属性和连接关系。

**网络** 表示一组引脚之间的等电位连接。连接没有输入、输出方向，电气结果由接入网络的各个引脚共同决定。

板级装配可为网络显式指定固定对地电位：地网为 0 V，理想电源网为创建时确定的有限电压。它们是板内建的参考约束，不需要器件或工厂。器件通过普通引脚接入，不直接引用电源或地；网络或引脚仅仅命名为 ``GND``、``gnd`` 不产生接地关系。

装配根据器件定义与结构化网表生成装配 IR，再生成板级执行代码，并为每个实例创建配对的 JavaScript 对象。``.ddl`` 文件定义单个器件，板级实例与连接由装配输入表达；器件工厂由各实例直接复用。

装配成功意味着实例引用、属性和引脚连接已经完成静态校验，默认值、常量、资源配置及初值已经完成创建期求值，器件体断言全部通过，所有器件工厂已经初始化完成。全板检查先于资源建立与任何工厂调用。``createBoard`` 仅在全部工厂成功后交付 ``ready`` 的板；首次推进才进行初始电气求解、建立观察基线并调度 ``process start``。初始化失败必须清理，不能交付半成品。

宿主装配输入的 ``instances`` 与 ``nets`` 必填，均允许空数组；省略实例 ``props`` 时采用 ``{}``，器件登记的 ``model`` 为 ``DeviceIR``。可选字段仅在省略时采用默认值，显式 ``undefined`` 或 ``null`` 按原值校验；``null`` 只在语言允许可空的位置合法。装配输入与错误码的主定义见 :doc:`/javascript/host`。

SDK 根入口面向宿主，``/device`` 面向器件适配，``/model`` 提供共享 IR 与 Builder，``/ddl`` 提供 DDL 编译；精确宿主合同见 :download:`contracts/host.d.ts <contracts/host.d.ts>`。

.. _spec-shared-ir:

描述、生成与执行
------------------------------------------------

**共享 IR** 是 DDL 和 TypeScript Builder 共同产生的中间表示。它描述资源引用、值计算、控制流及执行效果。

两种来源的 IR MUST 使用同一套资源绑定、类型检查和效果校验规则。

DDL 以声明和过程体描述器件行为；Builder 以程序方式构造共享 IR。

动态生成的执行块仍属于当前器件实例。它可以引用该实例的资源并调用语义函数，与 DDL 过程共享同一份状态和存储。

生成 IR 与执行 IR 是两个阶段。构造状态写入操作时，只产生该操作的描述；对应的状态更新发生在仿真运行时执行该操作时。

模型的可观察行为包括资源变化、仿真时间、采样、消息和模型故障结果。编译器的内联、执行合并与缓存优化 MUST 保持这些行为一致。实际工作量防护用于避免宿主被持续占用；优化可以改变其计数及超限位置，未触发防护的执行仍须保持模型行为一致，见 :doc:`execution/scheduling`。

.. _spec-resource-ownership:

资源与访问边界
------------------------------------------------

**资源** 是具有实例身份和生命周期的对象。**值** 是在表达式、局部变量和消息中传递的数据。

.. list-table:: 实例资源与相关值
   :header-rows: 1
   :widths: 23 77

   * - 名称
     - 作用
   * - ``state``
     - 保存可变状态；写入后，后续读取立即可见。
   * - ``memory``
     - 保存固定长度的可变字节区，使用显式读写操作访问。
   * - ``derived``
     - 表达只读派生值，读取时反映依赖当前已生效的结果。
   * - ``pin``
     - 提供双向电气端点，包含当前意图及只读采样结果。
   * - channel
     - 提供单向、带类型、有界的消息队列。
   * - notification
     - 提供无业务负载、可合并的通知端点。

``state`` 声明显式给出类型和创建期初值，保存 ``number``、``bool``、``string``、具名枚举、扁平记录、``bytes`` 及其可空形式。``derived`` 还可产生 ``sample``、``intent`` 及其可空值，依赖静态无环。资源本身不是这些值类型。

资源归器件实例所有。同实例的过程和 JIT 入口默认共享 ``state``、``memory``，也可以更新同一引脚的意图。普通函数通过调用它的入口访问这些资源。具体可见性与交错规则见 :doc:`execution/sharing`。

实例内共享不扩展为跨实例私有访问。板和其他器件通过已定义的连接与通信机制交互，而非直接读写该实例的内部状态。

配对 JavaScript 按 context 授予的接口访问实例。``public memory`` 授予只读用途的借用访问，``loadBytes`` 提供受控代码装载；生成 IR 可以引用私有资源，不代表普通 JavaScript 获得这些资源的直接读写权限。

运行时保存的执行位置、剩余耗时和恢复帧属于内部执行数据，与器件显式声明的 ``state`` 区分。

.. _spec-execution-entry:

执行入口与同步片段
------------------------------------------------

**执行入口** 是由仿真运行时调度的行为，可以是 DDL 过程，也可以是通过 ``attachJit`` 注册的 JIT 入口。

DDL 以可选且唯一的 ``process start { ... }`` 声明启动过程，以 ``process name on source { ... }`` 声明其余过程。触发源是静态资源路径，具体范围见 :doc:`/execution/index`；过程由运行时调度，不能作为普通函数调用。

普通函数同步执行，属于调用它的入口；函数调用本身不形成新的调度入口。

**同步片段** 是入口从开始或恢复执行，到实际挂起、过程运行结束或逻辑 JIT 指令结束之间的一段连续同步执行。片段内，其他入口 MUST NOT 插入执行。显式 ticks(0) 同样结束片段；边界处理函数正常返回不单独结束片段。

是否结束片段取决于操作是否真正挂起。例如，从非空通道接收消息可以立即完成；从空通道接收消息则挂起当前过程，允许其他入口运行。

同一仿真时刻的就绪入口按稳定顺序执行。相同装配、注册顺序和输入条件下，共享资源的更新顺序保持可复现。

例如，一个片段先读取计数值再加一写回，两步之间没有其他入口插入。若读取后发生实际等待，其他入口可以在等待期间修改计数值；恢复后，局部变量仍保存等待前读到的值。

**JIT 指令** 是模型定义的一次器件指令，可以包含多个 IR 操作和等待阶段。编译块是生成与缓存单位，一条指令和一个编译块都可能跨越多个同步片段。

普通状态赋值更新状态后继续执行当前路径；``redirect`` 显式终止当前 JIT 路径，在指定延时后重新进入指令边界。状态更新与控制转向具有不同的执行效果。

.. _spec-electrical-intent:

电气意图与采样
------------------------------------------------

**电气意图** 描述引脚向网络贡献的电阻支路或它们的组合。器件通过改变内部引脚间电阻表达信号，例如将输出经电阻接到供电或地引脚；理想电源由板提供。空意图表示释放该引脚的支路。

**采样** 是网络求解后得到的只读结果，包含电压、按接收引脚阈值解释的逻辑电平，以及网络状态。

意图表达“器件施加什么”，采样表达“网络实际得到什么”。输出引脚读取的同样是网络结果，而非自己写入的输出值。

每个 pin 只有一份当前意图，后一次赋值完整替换前一份。同一网络上不同 pin 的支路则共同参与求解。

同步片段内可以连续更新意图；电气求解与采样发布发生在片段结束的调度边界。片段内读取采样，获得上一次求解结果。

例如，一个引脚拉低，另一个引脚通过电阻上拉，两者共同决定网络电压。将前者释放后，上拉支路仍然存在。

.. _spec-js-ddl-boundary:

JavaScript 与 DDL 的交互
------------------------------------------------

每个器件实例都具有 JavaScript 适配对象。它与 DDL 在同一仿真 Worker 内协作，界面或其他宿主服务可以位于 Worker 之外。

**通道消息** 捕获发送时的值，不携带可变 memory 的活引用。**通知** 用于表达“需要重新读取或处理”，同批重复通知可以合并。

JS 与 DDL 按仿真批次交换消息。一次正常推进包含以下阶段：

#. 注入此前由 JavaScript 暂存的输入。
#. 推进仿真，执行器件行为并记录输出。
#. 清理 DDL 本批未读输入，取出并清空输出。
#. 调用器件的同步钩子 ``sync``，交付输出并允许暂存下一批输入。

同步钩子中新产生的输入属于下一批。已经接收到局部变量中的值，以及等待过程的执行位置，跨批次保留。

通道是按批次交换的队列；本批未读输入在批次结束时清理。因此，推进切片的长度既影响外部反馈延迟，也影响输入能够被消费的数量。

消息快照和 memory 借用视图具有不同生命周期。``ReadonlyBytes`` 是可跨推进和销毁留存的只读值快照，也用于字节属性。``BorrowedBytes`` 是本代可复用的借用句柄，销毁后失效；其内容只在限定稳定期内有效，``loadBytes`` 可以提前结束稳定期，异步留存应先复制。字节接口与稳定期主定义见 :doc:`/memory`。通知只记录事件，存储的历史内容需要由模型显式保存。

.. _spec-lifecycle-model:

生命周期与故障
------------------------------------------------

实例创建时，运行时准备 DDL 资源，再调用 JavaScript 工厂完成初始化。注册 JIT 入口只建立执行关系，后续由 ``runUntil`` 驱动运行。

``random()`` 为每个实例提供独立随机流，返回 ``[0, 1)`` 内的有限 ``number``。相同种子与相同调用顺序可复现；普通函数可以调用，纯函数、派生表达式与创建期表达式不能调用。算法与测试向量见 :doc:`/execution/index`，宿主种子及实例派生方式见 :doc:`/javascript/host`，DDL 不提供重新设种子的操作。

板只有 ``ready``、``faulted`` 与 ``disposed`` 三种公开状态。销毁先使所有 context 失效，再按实例逆创建顺序清理；每实例先释放已返回的适配对象，再逆注册顺序清理 SDK 资源。清理尽力进行，每个步骤至多尝试一次；结束即为 ``disposed``，即使清理汇总抛错，再次销毁也无操作。``time``、``status`` 与诊断信息仍可读，其余板能力失效；晚到的异步结果必须按实例代次隔离，见 :doc:`/javascript/lifecycle`。

**器件异常** 是模型定义的状态变化或控制路径，由模型自身处理。**运行时故障** 是模型或框架无法继续满足执行合同的情况，例如未捕获的器件 JavaScript 异常。

运行时首故障使整板先进入 ``faulted``，再同步分发唯一一次 ``onDidError``，保留已经发生的时间、状态修改和外部副作用。恢复只能销毁旧板并用 ``createBoard`` 创建新对象。恢复边界、后续上报、宿主监听器异常隔离及创建失败清理见 :doc:`/errors`，事件与精确接口以 :doc:`/javascript/host` 为主定义。

器件异常与运行时故障分别由模型和框架处理，二者使用不同的控制路径。
