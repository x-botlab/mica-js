# IR 引脚 I/O、采样与观察合同

> **来源**：[#25](https://github.com/x-botlab/mica-js/issues/25) · **同步**：2026-10-25
> **实现**：[`packages/device/src/observe/`](../../packages/device/src/observe/) · [`packages/device/src/pins/`](../../packages/device/src/pins/)
> **相关**：[IR 核心](./device-ir.md) · [引脚声明](./device-pins.md) · [电源域](./device-power-domains.md) · [电气模型](./electrical-model.md) · [虚拟时间](./time-model.md)

器件用 IR 操作访问已声明的引脚与采样组。内核负责输出意图提交、电气解析、采样快照、触发事实捕获与普通入口投递；器件 IR 负责通信状态机、内部功能选择、寄存器与业务行为。

## 资源与标量表达

引脚、采样组与观察绑定通过静态符号引用，在链接时绑定到当前实例的授权资源。链接期验证资源类别、指令的资源访问权限、参数与结果类型、入口签名与作用范围。

引脚与组的位宽在实例创建时确定。值采用核心已有标量；组采样的多个数据分块静态展开，作者层对象在降低阶段拆分。主动采样与捕获载荷采用值结果，浮空、门控与门限诊断由内核分别保存。下文操作名为文本记法，序列化与宿主绑定由执行格式合同承接。

## 门控采样结果

就绪判据与门控时序由[电源域](./device-power-domains.md)提供。主动采样受供电或输入门控时，**数字返回 `0`，模拟返回正零**；组采样逐成员采用门控结果，内核保存对应原因。门控采样保持数字逻辑记忆与浮空阶段；已捕获载荷仍按本文观察合同投递。

## 数字输出与采样

| 操作                        | 参数                  | 结果                        |
| --------------------------- | --------------------- | --------------------------- |
| `pin.write_digital pin`     | `bool level`          | 空结果                      |
| `port.write_digital group`  | 固定数量的 `u32` 分块 | 空结果                      |
| `pin.sample_digital pin`    | 空                    | `u32 value`                 |
| `port.sample_digital group` | 空                    | 固定数量的 `u32 value` 分块 |

数字写入更新引脚输出意图；输出模式、输出使能、供电门控与绑定驱动模型共同决定该意图对网络的贡献，推挽与开漏的物理含义由[电气模型](./electrical-model.md)规定。

单引脚采样使用 bit 0，其余位填零。数字取值采用[电源域](./device-power-domains.md)的门限解释与逻辑记忆，浮空默认值采用[电气模型](./electrical-model.md)，门控返回采用上节规则。采样读取本次相关解析后的解释结果，内核分别保存物理、门控与门限原因。

### 组位序与原子性

- 组成员顺序确定 bit 0 至 bit W-1，按低位优先拆分为 `ceil(W / 32)` 个 `u32` 分块，尾块超出 W 的高位填零。
- 组输出先验证全部成员引用、访问权限、分块数量与尾块高位，再**原子提交**全部输出意图；校验失败时保留提交前的全部意图。提交成功后各引脚分别接受自己的供电与输出门控。
- 多个独立引脚写入分别具有提交点与可观察边界；组写入只有单次原子边界。编译优化依据可观察行为等价证明选择合并方式。
- 组采样的所有分块来自同一相关网络快照；整个操作完成后才执行下一条 IR 操作。同一组采样内的同一引脚对应同一次读取。
- 跨域成员的就绪状态分别由[电源域](./device-power-domains.md)提供，逐位返回采用上节门控规则。

## 模拟电压输出与采样

| 操作                     | 参数          | 结果          |
| ------------------------ | ------------- | ------------- |
| `pin.write_voltage pin`  | `f64 voltage` | 空结果        |
| `pin.sample_voltage pin` | 空            | `f64 voltage` |

输出值采用有限 `f64` 电压（单位 V）。绑定电气模型提供参考、输出范围与供电约束，允许时电压可以取负值；写入在提交前校验有限性与声明范围，超出约束按模型异常合同保留此前已提交效果。

`write_voltage` 更新电压输出意图。门控就绪时，`sample_voltage` 对确定网络返回实际解析电压，对浮空网络返回确定性合成电压，两者都作为器件可用输入；内核分别保存物理状态与采样诊断。

浮空模拟输入的版本、阶段种子、时间混合、扰动幅度、供电限幅与延后初始化唯一由[电气模型](./electrical-model.md)维护；算法提供本次采样时刻的电压，门控返回采用上节规则。编译与优化必须保留算法声明的网络、供电、阶段与时间依赖。

观察载荷在触发时按值捕获，稍后投递时沿用原捕获值。相同快照内的重复资源调用同一电气取值合同。ADC 的量化、饱和、钳位、基准、转换时长与寄存器行为由器件 IR 表达；确定电压处于数字门限区间时，模拟采样仍返回实际电压。PWM 平均与器件特有滤波由显式器件采样模型表达。

## 写入提交与相关采样

器件 IR 的 I/O 操作在当前入口内按程序顺序执行。写入校验完成后提交意图，并在后续相关采样或触发捕获前完成必要的门控、网络贡献与解析。

接收业务通过后续普通入口执行，触发事实在形成时捕获；接收入口取得捕获值，需要当前值时执行新的显式采样。同一虚拟时刻可以包含多个有序提交与解析阶段，同刻先高后低形成的可观察变化按实际顺序保留，每个阶段的组内原子性与阶段之间的顺序分别保持。

外部 JS、Worker 或 UI 更新在执行合同规定的接纳边界进入。硬件等待时间与器件内部配置延迟由普通定时事件表达；作者层配置合并在提交 IR 操作前完成。

## 显式配置指令

配置状态、枚举名称、初始值与意图保存关系由[引脚声明](./device-pins.md)定义。本节唯一维护对应指令的标量签名与编码；`pin` 为静态引脚引用，各指令返回空结果。

| 指令                                           | 标量参数       | 写集与生效边界                 |
| ---------------------------------------------- | -------------- | ------------------------------ |
| `pin.set_mode pin, mode`                       | `u8 mode`      | 当前引脚输出模式，逐条立即生效 |
| `pin.set_output_enabled pin, enabled`          | `bool enabled` | 当前引脚输出使能，逐条立即生效 |
| `pin.set_pull pin, pull`                       | `u8 pull`      | 当前引脚内部偏置，逐条立即生效 |
| `pin.configure pin, mode, outputEnabled, pull` | `u8, bool, u8` | 三项完整配置，一次原子替换     |

| 参数       | 标量类型 | 编码                                                  |
| ---------- | -------- | ----------------------------------------------------- |
| 输出模式   | `u8`     | `0` high-z、`1` push-pull、`2` open-drain、`3` analog |
| 输出使能   | `bool`   | 当前主动输出控制                                      |
| 内部上下拉 | `u8`     | `0` none、`1` up、`2` down                            |

单项指令逐条立即生效并保留其余配置、两类输出意图及其就绪状态，连续单项修改的中间网络变化具有可观察性；`pin.configure` 在单个提交点形成完整配置后的驱动贡献。四条指令复用同一套参数、权限与最终配置约束校验。作者层对象配置降低为 `pin.configure`，单字段设置采用对应单项指令，完整参数来自器件状态或 `pin.get_config`。

### 观察控制

`observe.configure binding, enabled, edges` 返回空结果。`binding` 为静态观察绑定引用，`enabled` 为 bool，`edges` 为 `u8`：`0` 状态变化、`1` 上升沿、`2` 下降沿、`3` 双沿。静态绑定确定来源、目标入口、载荷与观察种类；状态或模拟观察固定使用 `edges = 0`，数字边沿观察使用 `1/2/3`。参数编码与绑定种类匹配校验先于提交，失败时保留原配置并产生模型异常。

观察配置原子更新启用与选择状态，并重建基线——每次显式配置都具有该效果，即使参数相同。供电或采样门控关闭期间保存配置，恢复时按生命周期规则重建基线；关闭观察保留已捕获事件。

### 只读查询

| 指令                         | 返回值                                 |
| ---------------------------- | -------------------------------------- |
| `pin.get_config pin`         | `u8 mode, bool outputEnabled, u8 pull` |
| `pin.get_digital_intent pin` | `bool ready, bool level`               |
| `pin.get_voltage_intent pin` | `bool ready, f64 voltage`              |

查询读取当前已提交配置与保存的意图。等待首次提交时 `ready = false`，数值槽填零；就绪后采用保存的意图。查询不改变数字输入记忆与浮空阶段，实际网络取值由采样指令负责。

## 静态观察绑定

观察资源声明来源引脚或固定组、目标普通入口、载荷布局与观察种类。观察种类包括数字变化、数字边沿与模拟状态或电压变化。

载荷由声明的标量组成，可包含捕获时刻、数字数据分块、模拟电压与匹配边沿编码；采样原因保留在内核诊断中。时间采用整数皮秒的 `f64`。数字边沿编码采用 `u8`：`0` 状态观察、`1` 上升沿、`2` 下降沿。

选通观察可以同时声明触发引脚与额外捕获的引脚或固定组；链接期校验全部捕获资源与载荷布局。触发时从同一相关网络快照取得标量，浮空与门控成员按采样规则形成数值。绑定目标在链接期确定，每次触发按值捕获载荷，调度器按虚拟时间与稳定顺序投递。

触发选择使用 `rising`、`falling`、`both` 等作者层名称，在降低阶段形成标量配置。数字状态变化与匹配边沿分别保留：持续启用的状态观察可以收到数据或内部采样状态变化，载荷保留当次值结果，边沿字段标识该次是否匹配触发条件。

关闭观察以其提交点划分捕获范围：提交前已捕获并排队的事件保留载荷继续投递，提交后停止新的捕获。实例销毁时按执行实例合同清理待执行事件。

## 边沿基线与恢复

| 解析过程               | 基线与投递                                           |
| ---------------------- | ---------------------------------------------------- |
| 首次启用，当前电平确定 | 建立当前基线，后续变化进入边沿比较                   |
| `0 → 1`                | 按当前触发选择捕获上升沿                             |
| `1 → 0`                | 按当前触发选择捕获下降沿                             |
| 确定值 → 门限区间      | 输入取值由电源域合同提供；边沿基线置为待建立         |
| 浮空进入               | 按电气合同取得默认输入值并重建基线，仅按状态观察处理 |
| 浮空退出               | 按当前输入解释结果重建基线，仅按状态观察处理         |
| 待确定区间 → 确定值    | 以当前值重新建立基线，后续确定跃迁进入比较           |
| 供电或输入观察恢复     | 以当前解析值重新建立基线                             |
| 显式提交观察配置       | 按该配置的提交点与基线重建规则执行                   |

每次确定跃迁都更新基线，触发选择决定边沿字段的匹配结果；`0 → X → 1` 等过程通过中间的基线重建分开表达。域电压变化引起的门限移动可以形成确定逻辑跃迁，按相同规则捕获。去抖、滤波、挂起位、IRQ 屏蔽、脉宽与周期测量由器件 IR 的状态与定时事件表达。

## 供电、生命周期与拓扑

供电状态、必需引用校验、门控与域恢复顺序统一按[电源域](./device-power-domains.md)执行，公共生命周期入口调度见 [IR 核心](./device-ir.md)。当前采样读取该提交点已生效的就绪状态。

采样恢复后观察按上表建立基线，关闭期间的变化保持当时物理历史。浮空阶段登记与恢复时的初始化由[电气模型](./electrical-model.md)负责，已捕获事件始终使用原载荷。拓扑原子更新按[内部可控连接](./device-topology.md)执行，相关网络重新解析后形成采样与观察结果。

实例结束时结束相应绑定与入口接纳；已交付载荷与外部持有的值快照保持原内容。

## 效果、异常与优化

参数校验、状态读写、引脚意图、网络变化、捕获事实、事件 ID 分配与释放、事件顺序及外部通知共同构成可观察效果。

模型异常保留此前已提交效果，并按执行合同报告故障边界。组操作的校验阶段先于组意图提交；电气解析判定驱动电压不相容时立即报告模型异常并暂停仿真，记录相关网络、贡献来源与故障现场，采样采用正常数值返回路径。强弱贡献优先级、多源相容判据、容差与结果电压唯一由[电气模型](./electrical-model.md)维护。

内核可以内联、特化、打包或融合实现，优化产物必须保持效果、触发快照与异常顺序，并在依赖变化时重新校验。

## 领域能力示例

延时拉低输出：

```ir
func onTimer() {
  pin.write_digital pin.OUT, false
  return
}
```

电压意图与实际采样：

```ir
func setVoltage(%target: f64) {
  pin.write_voltage pin.AOUT, %target
  %voltage = pin.sample_voltage pin.AIN
  state.store lastVoltage, %voltage
  return
}
```

初始化与普通调用：

```ir
func initialize() {
  call drive(false)
  pin.configure pin.OUT, 1, true, 0
  %now = event.now
  %deadline = float.add %now, 1000.0
  %timer = event.at onTimer, %deadline, true
  return
}
```

## 对照验证

| 场景                         | 预期结果                                                    |
| ---------------------------- | ----------------------------------------------------------- |
| 读取方主动采样时门控         | 数字 `0`；模拟正零，阶段与 V0 初始化条件保持                |
| 事件已捕获后关闭观察器       | 已排队事件保存，后续捕获停止                                |
| 门限区间与浮空值             | 门限区间返回记忆；浮空返回 `0` 并保留记忆；进出浮空重建基线 |
| 连续单项配置与完整配置       | 前者逐条生效并保留中间变化，后者一次原子更新三项            |
| 分组成员位号稀疏（`0/3/15`） | 器件 IR 重建稀疏布局，chunks 按成员顺序                     |
| 分组超过 32 位               | 按有序 `u32` chunks 传递，布局与原子性遵守本规范            |

端到端解析、捕获与解释执行／编译执行对照由实现验证。静态观察声明的具体编码载体，以及拓扑、供电观测、外部消息等功能的指令签名在各自合同中维护。
