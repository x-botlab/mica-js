================================================
引言
================================================

目的
------------------------------------------------

Mica 以器件为单位组织电路仿真。每种器件由共享 IR 模型和 JavaScript 工厂共同描述；模型可由 DDL 编译或 TypeScript Builder 构造，多个器件实例通过网表装配为一块板。

Device Description Language，简称 DDL，是描述器件资源和行为的语言。每个 UTF-8 ``.ddl`` 源文件恰好声明一个 ``device``，枚举、记录和函数均位于该器件内部；DDL 不提供模块、导入、导出或跨文件复用。源文件与名称规则见 :doc:`/language/lexical`。器件作者用 DDL 表达状态变化、电气行为和时间关系，用 JavaScript 连接外部消息、装载数据，并在需要时生成动态执行代码。

DDL 与 TypeScript Builder 产生同一套中间表示，简称共享 IR。两种描述方式遵守相同的资源、类型和执行规则，使手写器件行为与动态生成的行为可以共同执行。

本规范将这些约定组织为可实现、可校验的合同，供器件作者、工具作者和仿真运行时实现者共同使用。

适用范围
------------------------------------------------

本规范覆盖以下内容：

* 器件定义、静态属性、实例资源和板级装配。
* DDL 的值、表达式、函数、过程、同步响应及其共享 IR 语义。
* 引脚的电气意图、网络求解和采样结果。
* 虚拟时间、执行调度、资源共享和条件等待。
* 器件 JavaScript 与 DDL 之间的通道、通知和批次交换。
* JIT 执行入口的注册、动态 IR 生成、执行边界与代码失效。
* 生命周期、错误报告、故障恢复、宿主执行隔离边界和一致性校验。

本规范规定仿真资源和操作的通用语义；器件模型使用这些机制定义自身行为。

例如，运行时校验存储操作的范围，模型决定何时执行该操作，以及操作前后发生哪些状态变化。

规范用语
------------------------------------------------

正文使用以下关键词表示约束强度：

.. list-table::
   :header-rows: 1
   :widths: 28 72

   * - 关键词
     - 含义
   * - **MUST（必须）**
     - 实现或调用方需要满足的强制要求。
   * - **MUST NOT（不得）**
     - 实现或调用方需要遵守的禁止性约束。
   * - **SHOULD（应当）**
     - 默认采用的行为；偏离时需要有明确理由。
   * - **SHOULD NOT（不应）**
     - 默认避免的行为；采用时需要有明确理由。
   * - **MAY（可以）**
     - 在保持其他约束的前提下允许选择的行为。

定义、字段说明和执行顺序共同构成合同。关键词用于强调需要明确约束强度的要求，不要求每句话重复标注。

示例用于展示正文规则的组合方式。标明为示意的名称、数据和参数只服务于该示例；平台默认值由对应条款明确规定。

描述执行顺序时，“先于”指仿真中的可观察顺序；描述耗时时，指仿真时间。宿主执行代码所花的实际时间是另一项度量。

规范状态
------------------------------------------------

当前版本是首版实现基线。语言、共享 IR、Builder、资源、执行、电气、宿主 SDK 与实例随机派生的合同已经整合；同步响应提供发布边界上的显式采集与不可挂起执行，失控计算由宿主隔离与外部终止。

基线冻结表示这些合同可作为实现和验收依据。后续调整行为时，MUST 同步修订相关正文、文法、类型附件、示例和一致性场景。实现任务选择的内部结构与优化方式须保持合同的可观察行为。

规范中的行为是实现需要达到的目标。当前实现是否符合这些要求，需要由对应的一致性测试验证；既有原型和样例检查不能替代该验证。
