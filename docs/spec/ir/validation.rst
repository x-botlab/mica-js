.. _spec-ir-validation:

================================================
校验、诊断与来源
================================================

DDL、Builder 与手工 IR 输入共享校验规则。TypeScript 类型检查提供构造期辅助，执行前仍 MUST 核对结构、类型、引用、控制流与效果。两种来源不会获得不同的资源权限。

校验入口与阶段
------------------------------------------------

.. code-block:: typescript

   declare function validateDeviceIR(input: unknown): DeviceIR;
   declare function validateBlockIR(input: unknown): BlockIR;

入口接受当前 :doc:`schema` 的普通数据对象。成功返回捕获的递归不可变快照；后续修改调用方的数组、节点、字节输入或来源对象不改变该结果。结构中不接收宿主函数作为模型操作。

``validateDeviceIR`` 检查自包含定义及其全部声明。``validateBlockIR`` 先检查不依赖实例的结构、结果、局部与路径；引用的资源和函数在绑定当前实例时继续检查。校验过的未绑定块不能直接执行。schema 声明不是可信标记，类型断言或手工填写 pure / type 字段不能绕过检查。

.. list-table:: 阶段与检查责任
   :header-rows: 1
   :widths: 18 44 38

   * - 阶段
     - 检查
     - 失败边界
   * - construct
     - 当前方法输入、已知类型、句柄归属、可见作用域、生命周期与终结路径后追加。
     - 当前 Builder 失败并关闭；不返回部分结果。
   * - finalize
     - 完整 schema、声明及类型引用、静态依赖与调用图、控制流、效果及可判定的资源约束。
     - finish 或独立 validate 入口失败。
   * - bind
     - 当前实例资源、类别、真实函数签名、JIT 目标、首条位置、入口 / 代次 / 代码版本归属及依赖分析结果的接纳。
     - 拒绝相应装配或动态块；故障影响按调用所在生命周期处理。

可以提前确定的错误可以提前报告；不要求故意推迟到后阶段。独立 validate 入口的结构与定义检查使用 finalize。未解析引用必须在接纳为可执行代码前完成检查。

完整检查要求
------------------------------------------------

#. schema 检查字段、标记、数组、编号与节点组合；可变共享对象不能成为通过校验后修改结果的通道。
#. 声明检查名称唯一、合法类型位置、参数及字段重复、前向引用匹配、启动入口唯一、端点方向与配置，以及创建期图、derived 图、同步调用图无环。input channel 的接收位置按静态过程归属检查单消费者；同一过程可以多次接收，两个不同过程接收同一通道则拒绝，且检查先于任何器件工厂调用，见 :doc:`/channels`。
#. 值与局部检查结果类型、定义先于使用、支配关系、区域可见性、Local 初始化与独立执行体边界；资源形参保持资源类别和当前实例归属。
#. 控制流检查分支穷尽、模式重复、最近循环跳转、函数正常返回路径、计算区域 yield 与路径终结后的后缀。普通同步计算回调返回 void 时，生成控制流的全部路径必须已经终结；仍有正常结束路径时报告缺失 yield / 产值（IR_CONTROL_FLOW），不得将 undefined 当成模型值。纯与创建期计算回调仍须返回 Operand。
#. 效果检查沿完整静态调用图传播，包含短路右侧和所有分支；不能用某次输入下分支未选中作为放宽上下文的依据。
#. reaction 检查 sourcePath 非空、静态资源类别和 sourceType 与最终路径类型一致；notification、intent / intent? 及资源引用拒绝。previous / current 与所有 capture 名称唯一且满足遮蔽规则。每项捕获计算正常返回声明的可比较类型、遵守纯规则并有独立编号空间；捕获不能引用任何 reaction 绑定。reactionValue / reactionCapture 只能在所属响应体及其词法子区域使用，核对 binding 判别值、index 为非负安全整数且在 captures 范围内、结果 type 与源或捕获类型一致。辅助函数不继承绑定作用域。响应体只允许无值 return 或自然结束，禁止 returnValue、等待、receive、redirect 及 JIT 专有控制操作，效果限制沿所有被调用函数传播。
#. pin.initial 检查计算结果严格为非可空 intent、所有正常路径 returnValue；效果限制递归覆盖短路、分支、循环、断言消息与 pure 调用链。允许本实例直接 pin 引用与资源形参传递，拒绝运行资源读取。全部 pin 预绑定及引用的归属 / 范围检查先于任何工厂调用；resistor 参数在创建期求值时按电气合同检查。直接或间接的不存在引用、跨实例引用分别按引用与作用域错误拒绝，数值合法性失败拒绝创建。
#. JIT 检查块的相邻边界、每指令独立局部范围、等待尾位置与缺少目标入口的 redirect 调用路径。

资源数值的动态条件继续在相应操作执行处检查；静态类型 number 不替代时长、偏移、消息长度或支路参数的值校验。创建期求值成功后才进入相应资源建立阶段。

上下文效果
------------------------------------------------

.. list-table:: 构造体允许的效果
   :header-rows: 1
   :widths: 22 40 38

   * - 构造体
     - 允许
     - 专门限制
   * - 创建期
     - 常量、属性、器件常量、局部计算、控制流、断言与满足创建期限制的 pure 调用。
     - 普通创建期体拒绝资源引用；拒绝运行资源读取、资源写入、消息、时间读取、随机、等待与转向。pin.initial 的专用引用能力见下一行。
   * - pin.initial
     - 创建期计算能力，另有本实例直接 pin 引用、resistor 与 intent 组合；pure 调用链可传递 pin / memory 资源形参引用。
     - 全部调用链只读取属性、常量及值形参；资源引用只标识身份，不读取 state、derived、sample 或 memory 内容与长度。返回非可空 intent。
   * - pure fn / derived
     - 语言规范的纯读取集合、局部计算、控制流、断言、纯调用与值构造。
     - derived 正常返回值；不产生资源效果，不读取 now 或 random。
   * - reaction capture
     - 与 pure fn 相同的纯读取、局部计算、控制流、断言及纯调用，返回可比较值。
     - 每项计算独立，不能访问 previous / current 或其他 capture；结果拒绝 intent 及资源。
   * - reaction body
     - 普通同步读取、state / memory 写入、intent 更新、output 发送 / 通知、now、random、assert 和同步调用。
     - 拒绝等待、receive、redirect 及 JIT 专有控制操作，包含辅助调用的传递效果。
   * - 普通 fn
     - 当前实例的同步读取、更新、消息发送、now、random 与同步调用。
     - 不挂起；可能 redirect 的函数只能在已绑定 JIT 路径使用。
   * - process
     - 普通同步效果，另有 wait 和 input channel receive。
     - 拒绝 redirect、JIT elapse / waitUntil / stop。
   * - JIT 指令
     - 普通同步效果，另有 elapse、尾部 waitUntil、stop 和 redirect。
     - 拒绝过程 wait / receive；保留逻辑指令边界，检查合并遵守 :doc:`/jit/throughput` 的执行模式合同。
   * - 同步计算子区域
     - 所属上下文允许的同步效果，包括局部计算与内部循环。
     - 不挂起，不返回外层函数，也不跳转区域外的循环；允许绑定调用产生的跨层 redirect。

while 只提供一种条件构造形式，采用对应上下文的同步计算能力。普通路径条件可写入资源或调用普通 fn；pure 与创建期条件分别保持各自限制。

效果从实际操作推导，输入声明只表达需要满足的约束。依赖来源从完整读取和调用图收集，资源形参在绑定时展开。动态存储索引保守订阅整个 memory，派生与等待沿静态依赖传递，具体复查阶段见 :doc:`/jit/interrupts`。反应源路径的最终类型必须可比较；intent 与 intent? 拒绝作为触发源。

reaction 的 schema 要求 name、非空 sourcePath、sourceType、previous、current、captures 与 body 完整存在；绑定名称为合法标识符，captures 允许空数组，单项 value 为独立 ComputationIR。字段缺失、非法 binding 判别值或非整数编号属于 IR_SCHEMA；源或捕获类型不匹配、不可比较结果属于 IR_TYPE；不存在的资源或静态成员属于 IR_REFERENCE；跨执行体句柄或在 capture / 函数中读取 reaction 绑定属于 IR_SCOPE；同步效果越界属于 IR_EFFECT。Builder 的 capture 回调对象键集合必须与描述名称完全一致，额外或缺失回调在构造阶段拒绝。

reaction 的验收包括：首次源观察不执行捕获；不同 reaction 的捕获均先于任一响应；捕获按文本顺序且不读取响应写入后的值；每次已发布变化独立保留旧值、新值；下一边界才处理响应导致的变化；响应体、条件、消息和辅助调用均不能绕过同步效果限制。该检查适用于 DDL、Builder 与手工 IR 三种来源。

可空证明
------------------------------------------------

``isNone``、none 的相等比较、not、短路和条件控制流建立路径事实。局部槽赋值更新事实；分支汇合只保留可达路径的共同事实，循环入口和出口按语言规范汇合首次路径、回边、continue 与 break。

``nonNull`` 要求对应值在当前位置已证明非空；缺少证明报告 IR_TYPE。它只是经证明的类型收窄，不是可能在运行时失败的强制解包。sample 等可空字段先取得值结果，再检查该结果。

Value 是读取快照，后续资源写入或挂起不改变其内容和证明。新的资源读取即使名称相同也不继承旧结果的证明。读取 Local 可利用当前槽事实，但保存的旧 Value 与之后槽的新值分别分析。

错误对象
------------------------------------------------

构造、完成及绑定校验失败抛出 ``BuildError``，包含至少一条 Diagnostic。单次追加操作通常即时报告一项；finish 可汇总多个独立错误，按声明、区域和操作的结构顺序稳定排列。

.. list-table:: Diagnostic 字段
   :header-rows: 1
   :widths: 22 78

   * - 字段
     - 合同
   * - code
     - 固定英文分类码，见下表。
   * - message
     - 英文可读说明；具体句子不是逐字兼容接口。
   * - phase
     - construct、finalize 或 bind。
   * - path
     - 当前输入的结构路径，数组位置从零计数；根为 []。
   * - source
     - 可选原始来源；没有源文件的生成代码可以只有 label。
   * - related
     - 有序相关信息数组，无附加信息时为空；每项含英文 message、path 与可选 source。

.. list-table:: 固定分类码
   :header-rows: 1
   :widths: 30 70

   * - 分类码
     - 使用条件
   * - IR_SCHEMA
     - 不符合节点字段、判别值或基础结构。
   * - IR_TYPE
     - 类型、运算、签名、声明位置或非空证明不匹配。
   * - IR_SCOPE
     - 句柄归属、支配关系或局部可见性错误。
   * - IR_CONTROL_FLOW
     - 非法跳转、不可达后缀、未穷尽选择、缺失正常返回或 yield。
   * - IR_EFFECT
     - 所在上下文禁止的读取、写入、调用或挂起效果。
   * - IR_REFERENCE
     - 名称不存在、类别不匹配、声明重复或资源归属错误。
   * - IR_LIFECYCLE
     - 关闭后使用、重复完成或失败后继续构造。
   * - IR_DEPENDENCY
     - 创建期、derived 或同步调用图中的非法依赖环。
   * - IR_JIT_BOUNDARY
     - 无效指令分组、块位置不匹配或 waitUntil 尾位置不合法。

单个原因同时违反多项要求时可以报告其最直接的类别；固定码用于分类，不要求实现制造重复诊断。已发生构造失败的 Builder 关闭，后续使用报告生命周期错误。

位置与来源
------------------------------------------------

SourceInfo 的文件位置包含 URI 和左闭右开范围。行列从 1 开始，列按 UTF-16 代码单元计数；范围结束不早于开始。可选 label 标识生成器或翻译片段，无源码时允许只提供 label。

``withSource(info, emit)`` 为回调中新生成的节点设置默认来源，结束后恢复外层默认。显式节点来源优先于默认来源。这个辅助调用不新增运行时操作，也不建立可延长句柄生命周期的局部作用域；其回调提供临时有效的构造视图。

DDL 编译器保留源码来源；Builder 可以按生成片段标注。JIT 额外保留指令 pc / nextPc，内部内联与降低保留可追溯的来源和调用关联。结构 path 始终定位当前输入，source 可以定位优化前或生成前的原始输入。

运行时错误边界
------------------------------------------------

独立校验失败本身没有仿真副作用。运行时 translate 期间的构造或绑定失败属于 JIT 框架故障，按 :doc:`/errors` 使整板 faulted；不能通过捕获并继续使用失败 Builder 交付无效块。其他装配与执行错误保持所属章节的合同。

本章冻结 IR 构造诊断。板级错误事件、宿主监听器与完整发布布局见 :doc:`/javascript/host`。普通类型、范围、资源与 assert 检查保持有效；非终止代码由宿主隔离边界处理。
