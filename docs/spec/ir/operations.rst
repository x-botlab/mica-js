.. _spec-ir-operations:

================================================
操作与执行效果
================================================

本章规定 IR 操作的执行效果；精确节点字段和类型见 :doc:`schema`，Builder 方法见 :doc:`builder-api`。操作必须同时满足结构、类型和所属上下文的效果约束。

计算、读取与写入
------------------------------------------------

常量与计算遵守 :doc:`/language/types` 和 :doc:`/language/expressions`。资源读取取得当前可见值，写入分别遵守 state 即时生效、intent 整体替换等规则，见 :doc:`resources`。

存储操作和消息操作先按所属合同完成值、范围及负载检查，再施加相应效果。不能通过存储操作的字节大小推导普通数值算术的隐式回绕，也不能把无效消息当作队列溢出而静默处理。

时间依赖读取
------------------------------------------------

now 在 IR 执行到该操作时读取板级当前仿真时间，不是构造期或 JIT 翻译期常量。它只读且不挂起，但带有时间依赖，不能放入 pure fn、derived、创建期计算或等待谓词。

同一同步片段内可复用相同时间值；优化 MUST NOT 跨实际挂起移动读取或用旧结果替代恢复后的读取。读取本身不创建时间事件或依赖订阅，完整合同见 :doc:`/language/builtins`。

随机序列效果
------------------------------------------------

random 返回一个 number 并消耗本实例的随机序列状态。它是独立的有状态效果，不能归入纯计算、从未选中的分支提前求值，或因重复表达式而消除调用。普通函数、过程和 JIT 路径共享所属实例的序列，其他实例的调用不消耗该序列。

结果范围、生命周期与纯性检查见 :doc:`/language/builtins`。算法与测试向量见 :doc:`/execution/random`，宿主种子配置见 :doc:`/javascript/host`；random 节点只表达执行处的一次取值及序列消耗。

控制流与调用
------------------------------------------------

顺序结构保留操作顺序，条件结构只执行选中路径，match 选中分支后结束该次选择。同步调用在当前入口中完成，其参数求值保留源码顺序。

调用语义函数的 IR 保留该函数的资源效果和可能的控制转向效果。内联前后，同一资源的读写结果、控制转向跳过的路径及诊断行为应保持一致。

资源修改完成后发生的错误不自动回滚此前效果。整体故障状态与恢复规则由 :doc:`/errors` 定义，IR 的块结构本身不构成事务。

等待与恢复
------------------------------------------------

可恢复操作区分立即完成与实际挂起：立即完成继续当前同步片段；实际挂起保存恢复位置、局部值与尚未完成的时间或条件，然后允许调度器处理其他入口。

恢复从尚未完成的位置继续，**MUST NOT** 重放已经完成的调用、写入或发送。资源在挂起期间可能变化；恢复后的新读取取得当前可见值，保存的局部值仍保留原值。

时间范围和调度阶段见 :doc:`/execution/index` 与 :doc:`/execution/scheduling`。同刻阶段优先于各阶段内的稳定入队顺序，不能用一个全局 FIFO 取代阶段关系。

JIT 指令操作
------------------------------------------------

指令是模型定义的一次执行单位，可以包含多个 IR 操作和多个耗时阶段。一个编译块可以包含多条指令，每条指令仍具有 :doc:`/jit/execution` 定义的逻辑边界。

``elapse`` 表示一个显式耗时阶段，期间运行时仍可处理其他模型事件并在推进终点暂停。阶段已到期与该阶段后续代码开始执行是两个动作；终点处的 JIT 代码恢复由 :doc:`/jit/execution` 规定。

``waitUntil`` 绑定纯同步布尔谓词：先检查条件，条件已满足则立即完成；未满足则登记依赖并挂起，通过复核避免检查与订阅之间丢失唤醒。它必须位于当前指令的尾路径，该指令也是当前块的最后一条；允许 if / match 尾分支，但其外层不能有可执行后缀，循环与计算子区域内拒绝，见 :doc:`schema`。依赖变化及唤醒见 :doc:`/jit/interrupts`。

``stop`` 终止当前 JIT 入口，不能代替可恢复的条件等待。代码版本改变本身不唤醒等待，活动恢复状态与块缓存分别处理，见 :doc:`/jit/code-memory`。

控制转向
------------------------------------------------

``redirect`` 更新当前入口绑定位置、结束当前路径并接管转向延时。它跨过同步函数调用层，跳过所有未执行的正常路径后缀；已生效的资源效果与已消费时间保留。

控制转向即使指向同一位置，也产生路径终止效果。普通位置状态赋值，包括边界钩子中的赋值，只更新值，不产生该控制效果。实现 **MUST NOT** 仅凭位置值是否变化判定是否发生转向。

控制转向效果沿函数调用图传播，在缺少绑定目标入口的上下文中由校验器拒绝。延时与重新进入边界的顺序见 :doc:`/jit/interrupts`。

一致性检查
------------------------------------------------

* DDL 与 Builder 对同一资源操作产生相同结果和检查失败。
* 保存局部值、等待恢复与消息发送不会因块重建而重复发生。
* sample 的边界可见性不会被计算合并提前。
* 直接位置赋值继续当前路径，redirect 跳过后缀；目标值相同时仍可区分。
* 优化保留指令边界与片段交错；工作量预算统计实际执行，跳过计算不补扣，验证要求见 :doc:`/conformance`。
