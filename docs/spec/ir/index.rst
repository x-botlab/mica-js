================================================
共享 IR
================================================

共享 IR 描述资源引用上的值计算、控制流与执行效果。DDL 编译和 TypeScript Builder 构造都产生这套语义，经校验和实际实例绑定后，执行端据此生成并运行仿真代码。

一个执行语义
------------------------------------------------

两种来源的 IR **MUST** 遵守相同的类型、资源绑定和效果检查。来源不同不改变 state 的即时可见性、引脚意图的提交与采样时序、消息快照或控制转向。

IR 以有序操作、结果编号和结构化区域表达资源引用、常量与计算、同步调用、资源效果及可恢复执行。节点字段和 TypeScript 内存结构由 :doc:`schema` 固定；首版不承诺持久化格式或跨版本交换兼容。

Builder 构造出一个写入操作时，只生成描述。实际资源更新发生在执行阶段。同样，翻译过程中发现模型自定义的异常路径，应生成届时执行的行为，而非提前产生仿真副作用。

绑定与校验
------------------------------------------------

资源引用绑定到具体器件实例中的资源。通过名称构造的引用在绑定或编译时解析，并检查名称、类型及操作权限。错误不能因来源为动态代码而绕过检查。

同步函数的资源访问与控制效果归调用入口。一个实例可以有多个共享资源的入口，绑定模型不能据此强制每个资源只有一个入口 owner；共享顺序见 :doc:`/execution/sharing`。

校验包括函数调用参数、只读资源的赋值目标、派生依赖无环、等待位置和 JIT 控制转向上下文。可以静态确定的失败在执行前报告；数值范围等动态检查在操作发生时执行，见 :doc:`/errors`。

语义保持
------------------------------------------------

编译器可以内联函数、合并计算或复用缓存，但 **MUST** 保持资源变化、时间、采样、消息、控制转向和故障的可观察结果。实现优化不能通过改变同步片段、重放已执行前缀或返回陈旧派生值改变模型行为。

JIT 还需保留逐指令边界，见 :doc:`/jit/execution` 和 :doc:`/jit/interrupts`。reaction 保留每次发布的源快照，以及全部捕获先于全部响应的轮次边界。代码版本与活动恢复状态的关系由 :doc:`/jit/code-memory` 定义。

:doc:`resources` 定义操作对象，:doc:`operations` 定义执行效果；:doc:`schema` 和 :doc:`validation` 提供结构及检查合同，:doc:`builder` 与 :doc:`builder-api` 定义构造语义和完整签名。执行、电气与宿主接口的运行时边界分别由 :doc:`/execution/index`、:doc:`/electrical` 与 :doc:`/javascript/host` 维护。
