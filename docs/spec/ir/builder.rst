================================================
TypeScript Builder
================================================

Builder 用程序方式构造 :doc:`index`，使动态生成的行为与 DDL 使用同一套类型、资源与执行规则。本章规定构造语义；:doc:`builder-api` 定义完整方法与类型投影，:doc:`schema` 定义结果结构，:doc:`validation` 定义校验和诊断。

.. toctree::
   :maxdepth: 1

   builder-api

构造视图
------------------------------------------------

通用定义 Builder 声明属性、资源、函数和过程。声明使用描述对象，函数与过程的行为由构造回调表达；形参在函数体回调中表现为值句柄。

声明在定义完成时已经确定。JavaScript 可以按固定配置批量生成声明，但生成的运行时控制流不能新增资源。允许前向引用，定义完成时统一解析重名、类型和效果。

JIT Builder 是绑定当前实例后的受限视图，只构造执行块并引用已有实例资源。翻译期间不得通过该视图新增资源或入口。

同步函数、过程与 JIT 指令视图共用值和操作模型，分别按上下文开放能力：同步函数生成同步代码，过程允许生成时间等待与通道接收，JIT 指令遵守自身耗时和尾部等待规则。

资源采用明确操作方法，而非要求作者填写 IR 节点。state、derived、memory、pin、channel 等操作均沿用各自所属合同。

构造与运行
------------------------------------------------

JavaScript 翻译函数同步取得当前位置与代码视图，使用 Builder 描述指令，最后返回共享 IR 块。构造调用只追加描述；IR 所描述的资源读取、状态修改、函数调用与耗时发生在仿真执行阶段，区别于翻译时读取代码视图。

翻译依赖当前位置、代码及固定配置。需要随运行状态变化的行为在生成的 IR 中执行，不能通过翻译期间读取运行状态替代。入口注册及翻译约束见 :doc:`/jit/index` 和 :doc:`/jit/execution`。

值、类型与局部槽
------------------------------------------------

动态值句柄表示运行时执行到该操作取得的结果。资源再次变化不会使已有句柄重新读取；需要当前值时，显式生成新的读取操作。

例如，生成“读取 x 得到 a；写入 x；将 a 写入 y”，执行时 y 获得该次读取的结果，而非写入后的 x。

句柄携带 TypeScript 类型。资源和函数名称继续使用 ``string``；无法从名称静态推导的结果，调用方显式提供期望类型，绑定时与真实声明核对。

类型描述沿用 DDL 的标量、可空值、具名枚举、记录和字节值规则；类型推导辅助构造，统一 IR 检查决定最终合法性。语言规范的 number、string、bytes、pure fn 与资源参数规则见 :doc:`/language/types`、:doc:`/language/functions`。具名类型描述提供字段与成员推导，完成时仍核对真实声明与定义归属。

已知类型的操作实参可以直接接收合法常量并提升为 IR 常量。``null`` 按期望可空类型解释，不能凭一个裸 null 推定其完整类型。

需要可变局部量时使用显式局部槽。局部槽 MUST 有合法初值，执行到声明处时初始化；循环体中的声明每次执行都重新初始化，循环外的槽可以保存累计结果。

局部槽属于本次调用或入口的执行数据，不是实例共享 state。实际挂起时，其内容和需要恢复的值一并保存。

控制流与求值位置
------------------------------------------------

Builder 提供结构化条件、while、无限循环及最近一层循环的 break、continue。底层块参数与跳转不作为首版公开构造要求。

JavaScript 的 if 和循环决定生成什么；运行时路径通过 Builder 控制结构表达。动态句柄不得作为普通 JavaScript 运算结果使用。实现可提供类型或构造诊断，但不能承诺拦截任意 JavaScript 的对象真假判断。

条件和过程体回调在构造期间执行。while 使用独立条件构造回调，生成的条件区每轮运行时重新执行；外层生成的读取则继续代表外层该次读取。

while 条件使用所属上下文的同步计算视图：普通路径允许合法同步效果，pure 和创建期条件分别保持自身限制。条件不得挂起，也不能返回外层函数或跳转外层循环。此处采用统一 while，不另设副作用版本；捕获外层 Builder 或辅助调用不能绕过实际上下文限制。

普通操作保留构造顺序。对已经取得的两个布尔值运算不产生隐式短路；需要延后右侧时，通过 and / or 的显式构造回调生成对应区域。select 同样只执行选中计算分支；语句型 if / match 的分支结果仍可通过外层 Local 传出。

普通同步计算回调接受 Operand 或 void；只有生成控制流的全部路径终结时才接受 void。仅部分路径 redirect 时，回调仍须为其余正常路径返回 Operand，Builder 只在正常路径生成 yield。纯与创建期计算回调仍须返回 Operand。仍有正常路径却未产值时，由 Builder / IR 报告缺失 yield / 产值，不把 undefined 当作值；构造回调的 JavaScript 返回并不等同于生成控制流终结，详见 :doc:`builder-api`。

无返回值调用继续使用 ``call``；取得单个结果使用独立调用操作，并给出期望返回类型。记录可以作为一个返回值，首版不引入多返回值接口。

作用域与完成
------------------------------------------------

子作用域可引用可见外层值和局部槽；只在某个分支生成的临时值 MUST NOT 从分支外引用。公共分支结果使用外层局部槽传出。

函数、过程及独立 JIT 块之间不复用局部句柄。每条 JIT 指令独立拥有局部作用域；指令内的值和槽可跨其等待保留，指令之间通过实例 state 或 memory 传值。翻译期的 JavaScript 常量可以复用于多条指令。

函数返回、break、continue、stop 等终结当前路径后继续追加操作，报告构造错误。条件只有一条分支终结时，另一条仍可继续；全部分支终结后，外层路径也终结。

可能发生 redirect 的同步调用不等于必然终结，继续路径与控制转向路径的效果分别保留。

构造回调返回后，其 Builder 关闭；根构造器完成或构造失败后也关闭。再次追加操作或重复完成报告构造错误。

定义结果可以按装配规则复用；已绑定 JIT 块的复用仍遵守入口缓存隔离，不因句柄规则扩大权限。

分层校验
------------------------------------------------

构造时检查可见作用域、Builder 生命周期和已知类型；完成时检查完整控制流、返回路径及效果；绑定时核对名称、实际资源和函数签名。

同一错误可以被提前发现。TypeScript 检查通过不替代共享 IR 校验，构造失败不返回可执行结果，也不产生仿真资源副作用。

JIT 翻译与构造
------------------------------------------------

完整 JitBlockBuilder、JitInstructionBuilder 与 InstructionBoundary 使用 :doc:`builder-api` 的声明附件，不在本章重复定义。BlockIR 的字段见 :doc:`schema`。下面仅展示宿主翻译边界；BorrowedBytes 沿用 :doc:`/memory` 的借用接口，精确 SDK 投影见 :doc:`/javascript/host`；此处代码视图只在本次同步翻译期间有效。

.. code-block:: typescript

   interface JitTranslateInput {
     readonly pc: number;
     readonly code: BorrowedBytes;
   }

   type JitTranslate = (
     input: JitTranslateInput,
     builder: JitBlockBuilder,
   ) => BlockIR;

``JitTranslateInput`` 提供当前位置和借用代码视图，``JitTranslate`` 定义同步构造并返回共享 IR 块的函数。入口选项引用这一类型，注册结构见 :doc:`/jit/index`。

pc 与 nextPc 记录当前指令位置和顺序后继位置；首条位置、相邻边界与独立指令作用域按 schema 校验。耗时参数接受常量或动态 Value，阶段开始后使用已经捕获的时长。

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - 调用
     - 已确认语义
   * - ``instruction``
     - 添加带逻辑边界的指令；回调构造其行为，而非执行该指令。
   * - ``call``
     - 生成同步 DDL 函数调用，名称在绑定或编译时解析，参数与函数签名检查匹配。
   * - ``elapse``
     - 生成显式耗时阶段，数值合法性使用统一时间规则。
   * - ``waitUntil``
     - 生成纯布尔谓词等待，名称、函数签名、效果与尾位置需要校验。
   * - ``stop``
     - 生成入口停止操作。
   * - ``finish``
     - 完成当前块的构造并取得共享 IR 块。

名称引用使用 string，不要求为每个实例生成名称联合类型。常量与动态句柄使用完整 Operand / Argument 合同；null 按绑定目标签名解释，复合值常量按类型捕获快照。IR、校验器与 Builder 由 ``@mica-js/simulator/model`` 导出，通用器件及 JIT 宿主类型由 ``@mica-js/simulator/device`` 导出；公开入口的完整布局见 :doc:`/javascript/host`。

组合示例
------------------------------------------------

以下片段假设当前位置与所需常量已由翻译过程取得，``advance`` 是实例内已声明的同步函数：

.. code-block:: typescript

   builder.instruction({ pc, nextPc: pc + 1 }, instruction => {
     instruction.call("advance", 1);
     instruction.elapse(2);
   });
   return builder.finish();

生成这一块不会立即调用 ``advance``，也不会立即推进时间。运行到该指令时才按源码构造顺序执行。示例中的位置增量与耗时都是模型参数，不是平台默认值。

共享约束
------------------------------------------------

IR 调用归当前 JIT 入口，使用同实例资源及 :doc:`/execution/sharing` 的顺序规则。``waitUntil`` 的检查、订阅与恢复，以及 ``stop`` 的终止效果由 :doc:`operations` 和 :doc:`/jit/interrupts` 定义。

redirect 可直接生成，也可由同步调用传播。直接生成终结当前路径；可能转向的辅助调用保留正常路径。JIT 只提供 elapse 和尾部 waitUntil，不提供过程 receive / wait；发送和通知保持普通同步效果。

代码版本变化时，已执行前缀与恢复帧保留必要状态，旧块后缀的重新选择规则见 :doc:`/jit/code-memory`。Builder 不能通过重新构造一块来绕过该恢复合同。

结果与验证
------------------------------------------------

finish 交付公开可检查且不可变的 DeviceIR 或 BlockIR，不交付可执行 JavaScript。手工 IR 输入通过同一 validate 接口检查并捕获快照；已校验块仍需运行时绑定后才能执行。

构造、完成与绑定诊断使用 :doc:`validation` 的 BuildError 和固定分类码，消息为英文。类型声明与正反样例验证构造接口；运行时行为仍由 :doc:`/conformance` 的一致性场景提供后续实现证据。
