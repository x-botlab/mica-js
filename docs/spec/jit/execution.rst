================================================
指令与恢复
================================================

指令分组明确位置、顺序后继和操作顺序。它是恢复与边界检查的语义单位，而非不可分割的事务。

指令分组
------------------------------------------------

.. code-block:: ts

   builder.instruction({ pc: address, nextPc: address + 2 }, instruction => {
     instruction.call('update', 1);
     instruction.elapse(1000);
   });
   return builder.finish();

``pc`` 表示该分组的起始位置，``nextPc`` 表示顺序后继位置；这些名称来自接口，不规定模型必须采用何种地址布局。

分组回调在生成期间执行，用于构造 IR。``call`` 表示仿真执行时调用已绑定同步函数。

开始指令时，运行时保存该分组的位置与后继信息，先将绑定 state 设为 ``nextPc``，再按顺序执行指令体。

因此，正常语义函数读取的位置默认是顺序后继；需要原始指令位置时，生成者将 ``pc`` 作为普通常量传给函数。

耗时与副作用
------------------------------------------------

``elapse(duration)`` 表达一个不可由普通边界条件提前截断的耗时阶段。duration 接受常量或动态值，在执行到该操作时捕获并校验；阶段开始后的资源变化不修改已捕获时长。模型其他入口仍可在该期间运行，推进调用也可在阶段中暂停。

``call`` 与 ``elapse`` 的排列定义效果与耗时的先后。先调用再耗时，效果发生在耗时之前；先耗时再调用，效果发生在耗时之后。

等待期间的条件变化在依赖中生效，JIT 边界处理留到当前指令完成后。

使用 ``waitUntil`` 表达可被条件满足解除的等待，而非将它等同于固定时长消费，见 :doc:`interrupts`。

零时长 ``elapse`` 校验时长后立即完成，不挂起，不增加仿真时间，也不形成额外采样发布或让出边界。普通边界处理函数正常返回后继续当前指令片段；每条指令完成时仍形成逻辑边界，处理该指令产生的模型反应后再进入下一边界。

正常完成
------------------------------------------------

一条指令完成后，运行时检查实际位置和代码版本。

实际位置仍匹配旧块顺序路径且代码版本有效时，可以继续块内后继；否则按当前资源重新选块。

同一块内每条指令都保持逻辑指令边界，不仅在进入块时检查一次。

普通语义函数或其他入口改写位置时，当前路径继续执行；在当前指令完成后按最终位置决定后续路径。

边界钩子普通赋值后正常返回时，按该钩子返回后的最终位置准备新指令，不能使用钩子调用前的旧位置。

暂停与恢复
------------------------------------------------

恢复数据包含执行位置、剩余时间、所属代码版本、已保存局部值及必要等待订阅。这些是运行时内部状态，不作为额外可共享的 DDL 字段。

推进暂停、代码版本失效或新一批输入到达，均不得导致已经执行的指令前缀被重放。

当前指令等待期间，其他入口可以更新共享状态。恢复后重新读取共享资源时观察新值，局部保存值则保持原值。

``runUntil(T)`` 的终点限制见 :doc:`/execution/scheduling`。即使耗时恰好在 ``T`` 完成，其后代码也留到下一次目标大于 ``T`` 的推进。

停止与取消
------------------------------------------------

``stop()`` 永久终止当前注册的执行，直至该注册被释放或所属板销毁。它不表示条件等待，也不因代码写入、位置更新或后续推进而重新启动。停止保留注册与代码装载权限；需要从初始状态运行时，先 ``dispose`` 销毁旧板，再创建独立新板。

显式释放入口取消其恢复状态及等待订阅，并释放缓存所持资源；释放同一存储的最后绑定时撤销装载权限。已经发生的资源写入和外部副作用保持有效，新板独立建立缓存，见 :doc:`/javascript/host`。

``stop`` 终结当前路径，随后继续在该路径追加操作属于构造错误。条件分支的路径终结与外层继续规则由 :doc:`/ir/builder` 统一规定。可能执行 ``redirect`` 的函数调用本身不视为必然终结；未转向的正常返回路径继续执行后续操作。
