================================================
代码版本与缓存
================================================

代码 memory 仍是实例内的普通字节存储。绑定 JIT 后，其成功写入还参与代码版本跟踪和已生成路径的失效。

缓存身份
------------------------------------------------

每次 ``attachJit`` 注册独立拥有缓存，按代码版本和指令位置定位执行块。重新初始化通过销毁旧板后创建新板完成；新板重新建立缓存，不沿用旧板的代码版本、执行块或恢复状态。

同一代码 memory 被多个入口绑定时，写入使相关绑定的旧版本块失效；已绑定执行块不默认在实例或入口之间共享。

当前版本不设块数量上限。此规则描述缓存生命周期，不要求某种内部缓存数据结构。

代码变化
------------------------------------------------

DDL 存储操作或 ``loadBytes`` 对代码存储的成功非空写入 MUST 更新该 memory 的版本，使相关旧块立即失去再次进入的资格。

旧版本块从可进入缓存中移除，不积累可进入的历史版本。

当前活跃指令的恢复数据独立保留所需旧执行内容和局部状态，持续到指令完成或入口被取消。

``loadBytes`` 的签名引用 :download:`host.d.ts <../contracts/host.d.ts>`；授权、阶段和范围校验见 :doc:`/memory` 与 :doc:`/javascript/host`。工厂先绑定后装载，``idle`` 包括其话题回调可装载，``sync`` 及其嵌套话题、翻译和清理阶段禁止装载。

合法非空代码写入即使字节相同也产生失效；非空成功装载还结束同一存储的借用内容稳定期。校验失败不部分写入、不改变代码版本或稳定期；空装载仍校验全部条件，通过后不改变字节、版本或稳定期。

分组写入多次是否合并版本号属于内部表示选择；可观察的失效与恢复行为必须一致。

当前指令
------------------------------------------------

代码写入不回滚或重放当前指令。恢复后先完成当前指令剩余阶段与耗时，再抛弃旧块未执行后缀，按实际位置与新版本继续。

若执行在条件等待中，单独修改代码不使等待解除；满足条件后完成等待并重新选择路径。

若当前路径已通过 ``redirect`` 进入延时，仍完成相应延时，再使用当前代码版本进入边界。

例如，一条指令先写状态，再消费 4 ps。在消费 2 ps 后暂停并修改后续代码，继续时只消费剩余 2 ps；状态写入不重复，其后按新版本执行。

修改代码保持绑定位置与停止状态。已停止入口不会因为代码变化而自动重新启动。

与资源变化的区别
------------------------------------------------

普通 state 更新、条件变化或 ``redirect`` 不自动改变代码版本。

条件使模型改变执行路径时，已有相同版本、相同位置的缓存块仍可使用。

位置与版本共同决定后继路径有效性；资源权限和共享规则保持 :doc:`/execution/sharing` 的定义。

释放
------------------------------------------------

活跃指令完成或取消后，释放仅为其保留的旧执行内容。

``stop`` 结束当前执行并清理等待与恢复数据，但保留注册及其装载权限，当前注册不会重新启动。显式释放注册或销毁所属板时释放其缓存持有资源；同一存储最后一个绑定释放后撤销装载权限。旧 context 在销毁后失效，不能影响新板；新板的注册独立建立缓存。

编译器可以优化缓存与恢复数据表示，但 MUST 保留运行位置、剩余耗时及已经发生的副作用。同刻工作量计数跨缓存失效与块重建保留；实际跳过计算的优化可改变新增计数，见 :doc:`/execution/scheduling`。
