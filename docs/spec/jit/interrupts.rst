================================================
边界条件与控制转向
================================================

模型通过派生条件、边界处理函数和条件等待，表达对动态执行路径的影响。运行时提供这些机制，不解释条件的器件领域含义。

边界钩子
------------------------------------------------

.. code-block:: ts

   beforeInstruction: {
     when: 'ready',
     call: 'handle_ready',
   }

``when`` 引用本实例 bool 条件资源，``call`` 引用本实例无参、无返回值的同步函数。精确 ``InstructionHook`` 签名引用 :download:`host.d.ts <../contracts/host.d.ts>`。同步处理函数及 JIT 路径不能 ``receive``，通道消费只在过程内发生，见 :doc:`/channels`。

每次允许进入新指令时，边界按以下顺序执行：

#. 当前指令完成，当前时刻前序事件和反应已经按调度规则处理。
#. 确认目标时间允许继续执行，读取 ``when``。
#. 条件为 false 时跳过处理函数；为 true 时调用处理函数一次。
#. 处理函数正常返回时，按最终位置和当前代码版本准备指令；若发生 ``redirect``，转入对应延时与重入路径。
#. 选取有效缓存块或同步生成新块，再开始指令。

正常返回不原地重复调用钩子，即使条件仍为 true。条件是否清除由模型修改源状态决定。

处理函数可以普通赋值，包括修改绑定的 ``pc`` state；普通赋值继续其余语句，不等同于控制转向。

使用 derived 汇总多个依赖时，运行时读取已生效的布尔结果；派生维护规则见 :doc:`/language/declarations`。

控制转向
------------------------------------------------

.. code-block:: text

   redirect(target, delay: duration);

这是内置控制操作的专用写法：``target`` 使用位置参数，``delay`` 使用可选命名项。普通函数调用则全部使用位置实参或全部使用命名实参，不能混用。

``target`` 为有限 number，表示新的绑定位置；位置的模型含义及合法内容由生成器判断。``delay`` 是合法非负时长，省略时为 0。

执行 ``redirect`` 时：

#. 将当前 JIT 入口的绑定位置设为 ``target``。
#. 终止当前指令或边界钩子的剩余路径，跨过所有同步辅助调用返回层。
#. 跳过尚未执行的正常操作和耗时，保留已经发生的状态变化与意图。
#. 消费 ``delay``，结束后重新进入指令边界。

即使 ``target`` 等于原顺序位置，也必须结束当前路径。比较位置数值不能替代该控制效果。

已经实际消耗的时间保留。模型在原正常耗时之前控制转向时，仅执行转向路径显式规定的后续耗时。

delay 期间依赖可以变化，但该延时先完成，再重入边界；它不因条件变化提前结束。

``redirect`` 作用于当前 JIT 上下文，不是取消其他入口的接口。

可能调用 ``redirect`` 的函数带有相应控制效果，校验器 MUST 沿调用关系传播它。只有已绑定 JIT 的指令或边界钩子调用路径可使用该效果。

从普通 process 或其他缺少目标 JIT 上下文的路径调用时，绑定或 IR 校验拒绝该路径。

条件等待
------------------------------------------------

``instruction.waitUntil(predicate)`` 接收本实例显式声明为 pure fn、无参且返回 bool 的函数名称。构造签名见 :doc:`/ir/builder-api`。

纯函数沿调用图只调用纯函数，可读取 ``props``、``state``、``derived``、``pin.sample`` 和 ``memory`` 长度或内容；允许局部更新、循环和断言，也可构造或合并 ``intent`` 值。它不写资源或通道，不等待、不控制转向，也不调用 ``random``、``now``；构造意图值与向引脚赋予意图是不同操作。内置纯函数可用；语言不提供读取时钟或宿主随机源的隐式纯操作。

waitUntil MUST 位于所属指令的尾路径，该指令 MUST 是块的最后指令。允许 if / match 的尾分支；该位置之后各外层区域不能有可执行后缀。循环及计算子区域内拒绝，详见 :doc:`/ir/schema`。

运行时 MUST 保持条件检查与等待建立之间不丢失唤醒。进入等待时先检查谓词；已为 true 则立即完成，不额外让出。为 false 则建立观察、保存恢复位置并结束片段。该边界的求解与变化检测也必须纳入复核，不能遗漏检查与建立观察之间的更新。

依赖变化只标记需要复查。当前时刻模型阶段的已就绪事件与反应处理至队列清空后，按等待注册顺序检查所有待复核谓词；完成这组检查后才允许 JIT 恢复。为 false 则继续等待，为 true 则解除订阅并记录本次等待完成。之后的条件变假不撤销已完成的等待，即使其后执行因推进终点延后。

等待依据稳定点的当前条件，而非每个中间片段的历史边沿。模型阶段稳定前暂时为 true、随后变为 false，不使已挂起等待完成；需要保留短暂变化时，模型显式记入状态。

谓词依赖沿所有分支、pure fn 调用与 derived 静态传递收集；资源形参按实际绑定展开。订阅粒度为：

* state 的整个值。
* memory 的整个存储区，包括常量或动态索引读取与 copyBytes。
* pin 的整个 sample。

属性、器件常量和固定 memory 长度不需要更新订阅；仅依赖这些静态值且为 false 的谓词可保持等待直至入口释放或所属板销毁。对动态读取不按某次执行选中的分支或地址缩小静态依赖，未选中的分支也须合法。

资源更新使依赖失效；派生依赖沿无环图传递。实现可以细化内部订阅或合并同一稳定点的复核；除工作量防护差异外，须保持资源级保守依赖下的等待结果及模型错误行为，不能因漏订阅丢失唤醒。实际执行的复核及循环按 :doc:`/execution/scheduling` 计数，跳过的计算不补扣额度。纯性、资源归属或依赖图无法确认时，在执行前拒绝，不以运行期猜测替代校验。

代码版本变化不单独唤醒条件等待，醒来后再按版本规则选取后续路径。

条件等待和边界进入条件相互独立：等待结束不代表边界处理函数一定执行，仍需读取 ``when``。

条件满足于推进终点时，只记录就绪状态；后续 JIT 执行受 :doc:`/execution/scheduling` 的终点规则约束。
