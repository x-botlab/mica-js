================================================
MCU 执行模式
================================================

本章定义 CPU 指令推进与外设事件之间的可见性合同。``BoardOptions.execution`` 省略时为 ``'throughput'``，``'precise'`` 提供逐指令精确调度；两种模式共享指令操作、恢复状态、资源权限和模型错误规则。字段签名见 :download:`host.d.ts <../contracts/host.d.ts>`，创建校验见 :doc:`/javascript/host`。

模式与时间预算
------------------------------------------------

精确模式在每条指令的逻辑边界完成同步反应闭包、模型队列与下一指令钩子检查，保持 :doc:`execution`、:doc:`interrupts` 和 :doc:`/execution/scheduling` 的逐指令交错。``polling`` 声明在此模式下仍须合法绑定，但执行实际循环，不采用其快进语义。

吞吐模式允许在受保护的 CPU 执行段内合并调度检查，以 ``cpuQuantum`` 限定由此增加的 CPU 观察和中断响应延迟。预算单位为整数 ps，范围为 1..10_000_000，默认 10_000_000，即 10 μs。精确模式同样校验该字段，但其值不参与推进。

外设状态在时刻 t 生效后，吞吐模式 MUST 在不晚于 t + cpuQuantum 的可执行检查点使 CPU 获得重新观察状态及检查中断的机会。该上界只计模式引入的额外延迟；架构中断屏蔽、正在进行的不可抢占指令耗时或模型显式等待，仍按器件模型完成后才允许相关执行。到达推进终点时，适用下述终点规则。

预算是上界，不是固定时间步或强制抖动。运行时 MAY 因下一外设事件、资源观察者、钩子或推进目标采用更短的执行段；具备条件时也可维持与精确模式相同的事件视界。

外设与 CPU 的观察
------------------------------------------------

定时器、引脚电气变化、通信收发和其他模型事件 MUST 保持器件模型规定的精确仿真时间。吞吐模式的预算只作用于 CPU 的观察与执行检查；事件的时间戳、同刻阶段、稳定队列顺序、同步反应的捕获屏障及响应顺序保持 :doc:`/execution/scheduling` 的合同。

CPU 在两次观察之间 MAY 错过未锁存 GPIO 的中间变化。例如，引脚先上升再下降，后一次 CPU 读取可直接获得低电平。需要保留该变化的器件模型使用锁存状态、IRQ pending 或 FIFO 表达它；运行时 MUST 按模型执行这些锁存、排队和溢出行为，而非以 CPU 的最终采样覆盖它们。通信事件按精确时间到达 FIFO，CPU 何时读取与事件何时到达是两个动作。

``runUntil(T)`` 在两种模式下均保持目标时间 T，处理 T 到期的普通模型事件及反应后交付批次。运行时 MUST NOT 在 T 开始新 JIT 指令、调用边界钩子或恢复后续 JIT 代码。量子不得使板时间越过 T；在 T 完成耗时或满足条件时仅保存就绪状态，后续代码留到目标大于 T 的推进。

休眠与轮询
------------------------------------------------

模型以 ``waitUntil`` 表达 WFI 一类等待时，运行时在条件为 false 时订阅实际依赖，通过事件驱动的时间跳跃推进到后续事件或目标时刻。两种模式均保持 :doc:`interrupts` 的稳定点复核、无丢失唤醒及终点规则；休眠不要求逐周期调用宿主代码。

吞吐模式提供自动识别和显式声明两种轮询路径：

* 自动识别只适用于经 IR 与调用效果证明无副作用的自循环；证明须覆盖所有循环路径、资源依赖及可观察错误。仅有相同 PC、循环次数或历史执行形态不足以建立证明。证明不足时执行原路径。
* 器件作者通过 ``JitOptions.polling`` 声明指定循环头具有空闲等待语义。每项包含有限 number ``pc`` 与字符串 ``predicate``；同一注册中的 PC 互异，谓词绑定本实例显式声明的无参、返回 bool 的 ``pure fn``。省略表示无声明，空数组有效；显式 undefined、null、未知字段或无效绑定均拒绝。

显式声明在选定当前 PC、即将开始该指令前生效。谓词为 true 时正常执行指令；为 false 时保持 PC 在该循环头，循环体不执行，按谓词的实际资源依赖等待，直到条件满足后允许继续。其依赖收集、订阅与稳定点复核采用 ``waitUntil`` 的规则；边界钩子的检查和控制转向仍遵守 :doc:`interrupts`。

显式声明是器件作者对模型空闲语义的定义，等价于在循环头引入条件等待；它不是运行时对任意循环隐藏增加的启发式。作者应仅为等待期间可以省略循环体的路径作此声明。精确模式忽略这项快进声明并运行原循环；显式 ``waitUntil`` 在两种模式下均按条件等待执行。

受保护的执行段
------------------------------------------------

运行时 MAY 将纯数值、无外部事件影响的连续路径编译或批量执行。进入和继续执行段时须维护资源依赖、事件视界、代码版本与恢复位置守卫：

* 能证明 ``beforeInstruction.when`` 在整个段内恒为 false 时，可合并该条件的检查；否则在每条指令检查钩子，或回退到逐指令路径。钩子正常赋值、redirect 及其调用效果保持原顺序。
* 资源存在观察者、同步反应或其他入口依赖，路径含可观察效果，或守卫失效时，运行时 MUST 在相应检查点发布已发生效果并完成应有的反应和队列，或回退到保持合同的路径。模型效果不能仅因位于编译块内被当作纯数值计算。
* 代码成功写入使后续指令立即失去使用旧版本的资格。已经开始的指令仍按旧执行内容完成剩余阶段，已执行前缀不重放，当前指令未执行的后缀只完成一次；其后按实际 PC 和有效版本选路，见 :doc:`code-memory`。
* 检查点与回退须保留局部值、剩余耗时、共享资源读取和错误发生顺序。后续路径可能失败不构成提前失败的理由；在等待、事件或目标边界前，不得提前执行后续断言、非法访问或其他可观察效果。恢复时仅从未完成的位置继续。

这些优化保留逻辑指令身份与故障位置；精确模式还保留每条指令的调度边界。吞吐模式仅在本章定义的 CPU 可见性和显式轮询语义范围内改变交错。

工作负载与性能口径
------------------------------------------------

设计目标是典型 100 MHz MCU 在 1%、10%、30% 有效工作负载下，配合 1 kHz IRQ 与 115200 baud UART 的仿真吞吐。有效工作负载指执行有用指令的占比，其余时间可由 WFI 或轮询等待组成；实际吞吐取决于指令、访存、事件密度、观察者与设备模型。该目标不等价于满负载每秒执行 100 M 个周期的承诺。

性能证据 MUST 区分虚拟时钟经过的周期、休眠周期、轮询跳过周期和实际执行指令消耗的周期，并注明执行模式、cpuQuantum、有效工作负载、IRQ 与 UART 配置。以跳过的空闲周期计入仿真时间，不能将其报告为实际执行吞吐。这些口径约束测量报告，不新增板对象的公开统计字段。

验收检查
------------------------------------------------

.. list-table:: 模式合同验收
   :header-rows: 1
   :widths: 42 58

   * - 条件与操作
     - 可观察结果
   * - 省略模式与预算；另传 precise、边界预算及非法值。
     - 默认 throughput、10 μs；precise 仍拒绝非法预算，未知字段及显式 undefined、null 均拒绝。
   * - 外设在执行段中更新 GPIO、锁存 IRQ 或 UART FIFO。
     - 外设时间与队列精确；CPU 在预算内获得检查机会，GPIO 中间态可错过，锁存和 FIFO 按模型保留。
   * - 同一模型切换 precise，包含逐指令钩子及同步反应。
     - 保持逐指令边界与既有反应顺序；polling 声明不跳过实际循环。
   * - WFI、显式轮询及自动识别分别等待依赖变化。
     - WFI 两模式均精确；吞吐模式声明为 false 时 PC 留在循环头且循环体无效果；自动识别仅快进可证明的无副作用自循环。
   * - 等待或耗时在 T 到期，推进目标为 T。
     - 模型事件与反应完成，JIT 后续效果及钩子延至更大目标。
   * - 执行段加入观察者或非恒 false 钩子，等待期间写代码或在未来路径安排错误。
     - 检查点或回退保留观察、钩子与故障顺序；当前指令一次完成旧路径，其后使用新代码。
