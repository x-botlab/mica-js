================================================
MCU 执行模式
================================================

本章定义 CPU 指令推进与外设事件之间的可见性合同。``BoardOptions.execution`` 省略时为 ``'throughput'``，``'precise'`` 提供逐指令精确调度；两种模式共享指令操作、恢复状态、资源权限和模型错误规则。字段签名见 :download:`host.d.ts <../contracts/host.d.ts>`，创建校验见 :doc:`/javascript/host`。

模式与时间预算
------------------------------------------------

精确模式在每条指令的逻辑边界完成同步反应闭包、模型队列与下一指令钩子检查，保持 :doc:`execution`、:doc:`interrupts` 和 :doc:`/execution/scheduling` 的逐指令交错。``polling`` 声明在此模式下仍须合法绑定，但执行实际循环，不采用其快进语义。

吞吐模式允许在受保护的 CPU 执行段内合并调度检查，以 ``cpuQuantum`` 限定由此增加的 CPU 观察和中断响应延迟。预算单位为整数 ps，范围为 1..10_000_000，默认 10_000_000，即 10 μs。精确模式同样校验该字段，但其值不参与推进。

外设状态在时刻 t 生效后，吞吐模式 MUST 在不晚于 t + cpuQuantum 的可执行检查点使 CPU 获得重新观察状态及检查中断的机会。该上界只计模式引入的额外延迟；架构中断屏蔽、正在进行的不可抢占指令耗时或模型显式等待，仍按器件模型完成后才允许相关执行。到达推进终点时，适用下述终点规则。

预算是上界，不是固定时间步或强制抖动。运行时 MAY 因下一外设事件、资源观察者、钩子或推进目标采用更短的执行段；具备条件时也可维持与精确模式相同的事件视界。

外设与 CPU 的观察
------------------------------------------------

定时器、引脚电气变化、通信收发和其他模型事件 MUST 保持器件模型规定的精确仿真时间。吞吐模式的预算只作用于 CPU 的观察与执行检查；事件的时间戳、同刻阶段、稳定队列顺序、同步反应的捕获屏障及响应顺序保持 :doc:`/execution/scheduling` 的合同。

CPU 在两次观察之间 MAY 错过未锁存 GPIO 的中间变化。例如，引脚先上升再下降，后一次 CPU 读取可直接获得低电平。需要保留该变化的器件模型使用锁存状态、IRQ pending 或 FIFO 表达它；运行时 MUST 按模型执行这些锁存、排队和溢出行为，而非以 CPU 的最终采样覆盖它们。通信事件按精确时间到达 FIFO，CPU 何时读取与事件何时到达是两个动作。

``runUntil(T)`` 在两种模式下均保持目标时间 T，处理 T 到期的普通模型事件及反应后交付批次。运行时 MUST NOT 在 T 开始新 JIT 指令、调用边界钩子或恢复后续 JIT 代码。量子不得使板时间越过 T；在 T 完成耗时或满足条件时仅保存就绪状态，后续代码留到目标大于 T 的推进。

休眠与轮询
------------------------------------------------

模型以 ``waitUntil`` 表达 WFI 一类等待时，运行时在条件为 false 时订阅实际依赖，通过事件驱动的时间跳跃推进到后续事件或目标时刻。两种模式均保持 :doc:`interrupts` 的稳定点复核、无丢失唤醒及终点规则；休眠不要求逐周期调用宿主代码。

吞吐模式提供自动识别和显式声明两种轮询路径：

* 自动识别只适用于经 IR 与调用效果证明无副作用的自循环；证明须覆盖所有循环路径、资源依赖及可观察错误。仅有相同 PC、循环次数或历史执行形态不足以建立证明。证明不足时执行原路径。
* 器件作者通过 ``JitOptions.polling`` 声明指定循环头具有空闲等待语义。每项包含有限 number ``pc``、字符串 ``predicate``，并可选携带 ``consume`` 与 ``wait``；同一注册中的 PC 互异。``predicate`` 绑定本实例显式声明的无参、返回 bool 的 ``pure fn``；``consume`` 绑定本实例声明的无参、无返回函数；``wait.delay`` 绑定无参、返回 number 的 ``pure fn``，``wait.advance`` 绑定接收一个 number 形参且无返回的函数。省略 polling 表示无声明，空数组有效；显式 undefined、null、未知字段或无效绑定均拒绝。

显式声明在选定当前 PC、即将开始该指令前生效。谓词为 true 时，运行时先调用一次 ``consume``（若声明），再正常执行指令；为 false 时保持 PC 在该循环头，循环体不执行，并按谓词与 ``wait.delay`` 的实际资源依赖等待。

声明 ``wait`` 时，运行时在同一依赖上下文中调用 ``wait.delay`` 取得到下一次设备时间事件的时长。时长大于 0 时，运行时在 ``当前时间 + duration`` 安排一次设备事件；事件到期后先复核依赖，依赖已变化则直接重新排队 JIT，否则调用一次 ``wait.advance(duration)``、完成边界发布并重新排队 JIT。``wait.advance`` MAY 修改设备状态与 PC，以把执行转入设备服务入口。时长等于 0 时，JIT 保持等待，直到依赖变化、目标时刻或其它板级事件唤醒。

``consume``、``wait`` 及其函数绑定仅在吞吐模式生效；精确模式校验声明并执行实际循环。等待期间的依赖收集、订阅与稳定点复核采用 ``waitUntil`` 的规则；边界钩子的检查和控制转向仍遵守 :doc:`interrupts`。

显式声明是器件作者对模型空闲语义的定义，等价于在循环头引入条件等待；它不是运行时对任意循环隐藏增加的启发式。作者应仅为等待期间可以省略循环体的路径作此声明。精确模式忽略这项快进声明并运行原循环；显式 ``waitUntil`` 在两种模式下均按条件等待执行。

忙等延时
------------------------------------------------

以寄存器递减表达的延时环（``subs``/``bne`` 一类）不等待任何资源，只消耗时间；``polling`` 的等待语义不适用。器件作者通过 ``JitOptions.delays`` 声明这类环：键为环头 PC，值包含 number 状态名 ``counter`` 与正整数 ``cycles``，表示每轮把该状态减一并消耗 ``cycles`` ps。同一注册中的 PC 互异，``counter`` 绑定本实例声明的 number 状态；可选 ``pending`` 声明按累加器计时的外设，``state`` 与 ``period`` 绑定本实例 number 状态，``active`` 绑定无参 bool ``pure fn``。省略表示无声明，未知字段、非 Map 值或无效绑定均拒绝。精确模式忽略该声明并逐轮执行。

声明成立的语义前提：环内除 ``counter`` 的递减外没有其他可观察效果，也没有会影响出口条件的资源读取；因此第 k 轮与第 k+n 轮的唯一差别是时间与 ``counter``。运行时据此在环头把可折叠轮次折叠为一次时间推进与一次状态写入，再正常执行最后一轮，由该轮产生真实标志与出口分支。未声明 ``pending`` 或 ``active`` 为 false 时，可折叠轮次为 ``counter - 1`` 与剩余时间窗取整结果的最小值；窗口不足一轮时执行原路径。

声明 ``pending`` 且 ``active`` 为 true 时，令 ``remaining = period - state``。服务边界前的可折叠预算为 ``remaining > 0 ? floor((remaining - 1) / cycles) : 0``，并与 ``counter - 1``、推进目标、下一事件及执行段终点取最小值。减一保留真实边界轮，消除会跨过服务边界的额外一轮；该边界轮仍由原 IR 决定何时请求服务并执行其真实尾部。折叠后的状态与时序与逐轮执行一致，包括 ``counter`` 的可观察值和环外指令的时刻。

折叠不得越过推进目标、下一事件或执行段终点：可折叠轮次按剩余时间窗取整，窗口不足一轮时执行原路径。``counter`` 在折叠后与其他状态写入一样经过脏位提交，因此观察者、钩子与代码版本守卫仍按 :doc:`execution` 与 :doc:`interrupts` 的规则生效。

标记合块与循环折叠
------------------------------------------------

器件通过同步翻译的 ``markDirectSpan`` 与 ``markDirectLoop`` 报告候选；标记只缩小编译器搜索范围，不进入返回块，也不保存推进时限。同一 PC 的合块与循环标记互斥。运行时仅在吞吐模式、主 ``code`` 内存、当前单 JIT Direct 准入、没有待处理队列、待发布批次或待恢复指令，且已声明的定时状态合法时消费标记。``directTiming.blocked`` 为 true、观察者或等待掩码冲突、入口钩子依赖不可省略、代码版本失效或候选形状无法证明时，执行该逻辑 PC 的普通指令；普通 Direct 可用时优先使用它，否则使用通用体。非法、重复、冲突或无法证明的标记只拒绝该优化，不重放已发生效果。

执行候选前，运行时在边界检查完成后、首条前缀写入前读取当前时间 ``t``。宿主上限为 ``min(runUntil 终点, 下一模型事件时刻, 当前执行段终点)``；当前执行段未设独立终点时视为无穷。``directTiming.service`` 提供有效状态且 ``deadline > 0`` 时，服务绝对上限为 ``t + max(0, deadline - elapsed)``，并夹到宿主上限；``deadline`` 为 0 表示无定时服务，不形成服务上限，服务上限不大于 ``t`` 时不进入优化。运行时以这些上限的最小值作为优化视界 ``H``。``H`` 只控制优化准入；普通指令仍使用实际宿主截止及其自身的服务与结算规则。

``markDirectSpan`` 选择返回块中从 ``pc`` 开始、含 ``2–8`` 条连续指令的合块：纯固定时长前缀后接一条普通 GPIO/SFR 终结写。每条前缀指令的 ``nextPc`` MUST 等于下一条成员 PC，终结写及后续 PC MUST 保留普通入口。编译器 MUST 从绑定后的规范 IR 证明前缀无控制转向、无异常、无可观察中间发布、内存访问有界，且各条 ``elapse`` 为正整数常量。运行时仅在 ``t + prefixDurationPs < H`` 时执行前缀；前缀按原耗时顺序累加，不产生单独发布点。

到达终结写原起始时刻时，运行时经该指令已有的普通 Direct 入口执行终结写，保留其原提交、``publishCheckpoint``、电气求解、捕获先于反应体及异常冲刷。前缀、终结写与后缀沿用原时刻和发布点。``runUntil`` 目标落在前缀内或恰在终结写开始时，不产生终结写；目标前已完成的效果正常可见，终结写及后续代码留到目标更大的推进。终结写的后缀 MAY 越过 ``H``，继续按原期限与结算规则执行。

``markDirectLoop`` 标记以 ``pc`` 为环头的自回跳循环。``spin`` 无计数器；``decrement8`` 每轮把一个计数字节减一，并在新值非零时自跳。``maskedByte`` 计数地址按 ``(selectorByte & mask) | bits`` 计算，绑定时 MUST 穷举选择字节并确认每个结果都落在计数内存内。循环 MUST 有固定轮时长 ``d``，出口只依赖该计数器，尾部时间账可归纳，且没有其他可观察效果或影响轮次的读取。

设 ``H > t``，``Ktime = floor((H - t - 1) / d)``，否则为 ``0``。``decrement8`` 在退出轮之前至多折叠 ``Kdata = (r === 0 ? 256 : r) - 1`` 轮，取 ``k = min(Ktime, Kdata)``；``spin`` 取 ``k = Ktime``。``k > 0`` 时，以标准脏位提交路径写入 ``(r - k) & 255``，PC 保持环头，精确推进 ``k * d``，并按原尾部规则累积时间与服务状态。``spin`` 仍按原节拍推进时间驱动外设。

折叠 MUST 保持逐轮语义：可见计数器或 ``Rn``、PC、时间、服务累加量与中断状态都与逐轮执行一致。首版仅在中断保护计数为零、无挂起中断、无 UART 唤醒、T0 边沿或 IAP 待处理事件，且计数写目标没有相关观察者时折叠；处于保护窗口倒计时的轮次交给原指令。折叠后由普通单轮入口执行边界轮，处理到期服务与循环的普通轮次，``decrement8`` 还执行最后一次递减；若 ``runUntil`` 落在该轮中间，按原指令在真正开始时写入计数状态（``decrement8``）与 PC 并捕获 ``resume``，到期后执行尾部一次。该入口 MUST NOT 在同一函数内递归进入同一折叠。

逐指令 IR 是语义基准。优化仅覆盖可证明的候选；未标记、形状不符或运行时失配时执行逻辑 PC 的原指令，且不重放已执行的前缀或轮次。

受保护的执行段
------------------------------------------------

运行时 MAY 将纯数值、无外部事件影响的连续路径编译或批量执行。进入和继续执行段时须维护资源依赖、事件视界、代码版本与恢复位置守卫：

* 能证明 ``beforeInstruction.when`` 在整个段内恒为 false 时，可合并该条件的检查；否则在每条指令检查钩子，或回退到逐指令路径。钩子正常赋值、redirect 及其调用效果保持原顺序。
* 资源存在观察者、同步反应或其他入口依赖，路径含可观察效果，或守卫失效时，运行时 MUST 在相应检查点发布已发生效果并完成应有的反应和队列，或回退到保持合同的路径。模型效果不能仅因位于编译块内被当作纯数值计算。
* 代码成功写入使后续指令立即失去使用旧版本的资格。已经开始的指令仍按旧执行内容完成剩余阶段，已执行前缀不重放，当前指令未执行的后缀只完成一次；其后按实际 PC 和有效版本选路，见 :doc:`code-memory`。
* 检查点与回退须保留局部值、剩余耗时、共享资源读取和错误发生顺序。后续路径可能失败不构成提前失败的理由；在等待、事件或目标边界前，不得提前执行后续断言、非法访问或其他可观察效果。恢复时仅从未完成的位置继续。

这些优化保留逻辑指令身份与故障位置；精确模式还保留每条指令的调度边界。吞吐模式仅在本章定义的 CPU 可见性和显式轮询语义范围内改变交错。

工作负载与性能口径
------------------------------------------------

设计目标是典型 100 MHz MCU 在 1%、10%、30% 有效工作负载下，配合 1 kHz IRQ 与 115200 baud UART 的仿真吞吐。有效工作负载指执行有用指令的占比，其余时间可由 WFI 或轮询等待组成；实际吞吐取决于指令、访存、事件密度、观察者与设备模型。该目标不等价于满负载每秒执行 100 M 个周期的承诺。

性能证据 MUST 区分虚拟时钟经过的周期、休眠周期、轮询跳过周期和实际执行指令消耗的周期，并注明执行模式、cpuQuantum、有效工作负载、IRQ 与 UART 配置。以跳过的空闲周期计入仿真时间，不能将其报告为实际执行吞吐。这些口径约束测量报告，不新增板对象的公开统计字段。

验收检查
------------------------------------------------

.. list-table:: 模式合同验收
   :header-rows: 1
   :widths: 42 58

   * - 条件与操作
     - 可观察结果
   * - 省略模式与预算；另传 precise、边界预算及非法值。
     - 默认 throughput、10 μs；precise 仍拒绝非法预算，未知字段及显式 undefined、null 均拒绝。
   * - 外设在执行段中更新 GPIO、锁存 IRQ 或 UART FIFO。
     - 外设时间与队列精确；CPU 在预算内获得检查机会，GPIO 中间态可错过，锁存和 FIFO 按模型保留。
   * - 同一模型切换 precise，包含逐指令钩子及同步反应。
     - 保持逐指令边界与既有反应顺序；polling 声明不跳过实际循环。
   * - WFI、显式轮询及自动识别分别等待依赖变化。
     - WFI 两模式均精确；吞吐模式声明为 false 时 PC 留在循环头且循环体无效果；带 wait 的声明在设备事件到期后执行一次 advance；自动识别仅快进可证明的无副作用自循环。
   * - 显式轮询谓词由 false 变为 true。
     - 运行时先执行一次 consume，再从同一 PC 正常执行指令；consume 的写效果在指令前可见。
   * - 等待或耗时在 T 到期，推进目标为 T。
     - 模型事件与反应完成，JIT 后续效果及钩子延至更大目标。
   * - 执行段加入观察者或非恒 false 钩子，等待期间写代码或在未来路径安排错误。
     - 检查点或回退保留观察、钩子与故障顺序；当前指令一次完成旧路径，其后使用新代码。
   * - 标记合块覆盖 2、8 条指令，并在前缀内、终结开始及尾部前后 1 ps 推进。
     - 严格视界内仅提交纯前缀，终结写沿用原起始时刻、后缀和发布点；目标落入前缀或恰在终结开始时无终结写，失配时只执行逻辑 PC 的原指令。
   * - 标记循环与 ``DJNZ``/``SJMP $`` 在预算小于一轮、等于一轮、相差 1 ps 及服务到期时推进。
     - 仅折叠严格在视界前完整结束的轮次；计数器、PC、时间、服务累加与中断限制逐轮一致，边界轮执行原 IR，不从同一函数递归进入折叠。
   * - paced 的 ``pending`` 余量为 ``0``、``cycles - 1``、``cycles``、``cycles + 1``。
     - 使用修正预算 ``remaining > 0 ? floor((remaining - 1) / cycles) : 0``，不与服务边界轮重叠；真实边界轮仍由原 IR 请求服务。
