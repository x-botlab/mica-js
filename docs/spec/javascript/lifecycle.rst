================================================
生命周期与话题
================================================

本章规定运行时何时调用工厂、同步钩子与释放操作，以及 context 的资源归属和代次。器件接口见 :doc:`interfaces`，板与诊断事件的主定义见 :doc:`host`，精确宿主签名见 :download:`/contracts/host.d.ts </contracts/host.d.ts>`；错误、部分交付与清理失败见 :doc:`/errors`。

创建与就绪
------------------------------------------------

工厂调用的前置条件和顺序由 :doc:`/assembly` 定义：运行时完成全板静态校验和创建期求值，包括属性、默认值、常量、资源配置及初值；再检查器件体创建期断言，全部通过后建立全板实例资源与初始引脚支路，随后按 ``instances`` 顺序同步调用每个 ``create(ctx)``。初始意图的 pin 引用可前向绑定，支路在任何工厂前存在，但首次电气求解仍在首次推进。

工厂读取补全后的 ``ctx.props``，建立实例局部状态，订阅话题，并返回具有 ``sync(batch)`` 和 ``dispose()`` 的适配对象。属性在实例生命周期内固定。宿主省略 ``props`` 时采用 ``{}``；属性默认值只在字段省略时补全，显式 ``undefined`` 或 ``null`` 按原值校验，只有语言允许可空的位置接受 ``null``。

``attachJit`` 仅在工厂初始化期间注册执行入口。注册建立执行关系，实际执行由之后的 ``runUntil`` 驱动，相关契约见 :doc:`/jit/index`。

全部工厂成功完成才构成装配就绪，``createBoard`` 此时交付 ``ready`` 的板。运行时不再调用第二个 JavaScript 器件启动钩子；DDL 的可选 ``process start { ... }`` 是由仿真运行时调度的启动过程，不是工厂回调。首次推进先完成初始电气求解和观察基线，再排入启动过程、注入本批输入并开始执行，见 :doc:`/execution/scheduling`。需要全体实例就绪的消息，由宿主在成功取得模拟器后发布。

同步调用约束
------------------------------------------------

器件工厂、``sync``、器件话题回调与 ``dispose`` MUST 同步返回。Promise 或其他 thenable 返回值构成接口违约，运行时不等待其完成；故障处理与后续 rejection 的接收见 :doc:`/errors`。宿主话题与板事件监听器的返回任务不适用器件钩子的 thenable 违约规则，由宿主自行管理异步任务及 rejection，见 :doc:`host`。

钩子可以显式启动异步工作。异步使用借用数据前必须取得自有副本，并自行捕获异步错误；上报入口为 ``ctx.reportError(error)``。启动异步工作不会延长同步钩子的有效阶段，也不改变借用期限。

话题广播
------------------------------------------------

``board.topics`` 与 ``ctx.topics`` 使用同一 ``TopicBridge`` 合同，共享板内话题广播域，不自动添加实例前缀。话题名和 ``unknown`` 负载由订阅方校验并解释；运行时不自动复制 payload，各回调接收同一次发布的负载。

``onDidReceive`` 是项目 core 的真实 ``Event<TopicMessage>``，订阅返回可单独释放的 ``Disposable``。宿主通过 ``board.topics`` 建立的订阅归板所有，器件通过 ``ctx.topics`` 建立的订阅归实例所有。工厂创建期间发布的话题立即广播，不缓存、不向稍后创建的订阅者补发；初始化广播不是全板就绪通知。

发布按订阅注册顺序同步广播，允许嵌套发布。每次分发使用该次注册快照：新增订阅从下一次分发生效，已在快照中的订阅即使中途释放仍在本轮调用。嵌套发布使用其自身的注册快照；整板故障后停止后续器件回调的要求优先于快照规则。

宿主话题回调异常按非致命 ``onDidDiagnostic`` 报告，并继续其他允许的回调。在 ``ready`` 时通过守卫并开始投递的合法 ``publish`` 中，器件回调抛错、thenable 返回或首次有效 ``reportError`` 由运行时捕获，先使整板 ``faulted``，再同步分发首个 ``onDidError``，停止后续器件回调；``publish`` 自身正常返回，不向发布者重抛已捕获的器件异常，嵌套发布同样适用。发布者自身的参数、失效或已故障后的新发布错误仍抛出。若投递发生在 ``sync`` 中，当前 JavaScript 栈可以返回，但后续 ``sync`` 停止，当前 ``runUntil`` 失败。运行时通过包装监听器实现异常归属与隔离，不能依赖 ``Emitter.fire`` 自动隔离；诊断监听器异常由 ``console.error`` 兜底且不递归分发，见 :doc:`/errors`。

话题是 JavaScript 侧广播，并非 DDL 通道的消费确认。回调中调用输入端点只是暂存输入，其注入时机由 :doc:`/channels` 定义；回调不会让 DDL 在当前 JavaScript 栈中立即运行。整个话题及板事件分发栈内禁止推进或销毁同一板，以 ``INVALID_CALL_STATE`` 的 ``SimulationError`` 拒绝。封锁只限同板；板 A 的回调可以操作独立板 B，调用仍遵守 B 自身的守卫。守卫依次检查 context 或对象有效性、当前阶段与同板重入、所需板状态，最后检查参数；已销毁板的 ``dispose`` 优先无操作返回。宿主调用被拒绝本身不使板故障；该异常逸出器件回调时仍按器件故障处理，见 :doc:`host`。

推进与同步
------------------------------------------------

:doc:`/channels` 是批次阶段的单一事实来源。本章仅规定适配对象在其中的生命周期职责：

* 两次推进之间，工厂或话题回调可以通过输入端点暂存下一批输入。
* 正常推进完成本批执行和通道清理后，运行时向各适配对象同步交付 ``sync(batch)``。
* ``sync`` 读取输出快照和同步点最终存储，可以发布话题或暂存下一批输入。
* ``sync`` 产生的新输入属于下一批，不能被此前本批输入清理覆盖。

``sync`` 按装配输入的 ``instances`` 顺序依次调用；单个 FIFO 的消息顺序与跨器件消息排序是不同承诺。部分交付后失败时，后续 ``sync``、未交付输出和已发布副作用均按 :doc:`/errors` 处理。

目标时间的处理以 :doc:`/execution/index` 为准，同刻阶段顺序、同步片段与派生值读取见 :doc:`/execution/scheduling`。本章不把同步交付边界解释为所有 DDL 过程在终点暂停；普通函数属于调用它的入口，实例内共享与可见性见 :doc:`/execution/sharing`。

资源归属
------------------------------------------------

通过 context 建立的 SDK 资源 MUST 自动归当前实例所有，包括话题订阅和 JIT 注册。工厂尚未返回就失败时，运行时仍能找到并释放这些资源，不能只依赖成功返回的适配对象来追踪它们。

器件可以提前释放订阅；实例清理时不得再次执行同一个已经尝试的底层释放步骤。适配对象和所属资源的尽力清理、错误汇总与 at most once 要求见 :doc:`/errors`。

器件自行建立的定时任务、外部请求等由器件负责管理，通常在 ``dispose`` 中释放或取消；失败工厂必须自行处理其外部资源。context 的自动归属仅覆盖由它创建的资源。

销毁与代次
------------------------------------------------

每个 context、输入端点和 ``BorrowedBytes`` 句柄绑定创建时的实例代次。板只公开 ``ready``、``faulted`` 与 ``disposed`` 三种状态。``faulted`` 后须销毁旧板，再由 ``createBoard`` 创建新对象，恢复边界见 :doc:`/errors`。新板独立执行创建期求值、资源建立和工厂初始化。非终止执行及宿主容器外强制终止的边界见 :doc:`/execution/scheduling`；强制终止不等同于本章的正常销毁。

``dispose`` 以及创建失败后的清理按以下顺序执行：

#. 先使全板所有 context 失效，拒绝新的 SDK 副作用。
#. 按实例创建顺序的逆序清理；失败工厂尚未返回适配对象时，直接清理其 SDK 资源。
#. 对每个已有适配对象的实例，先调用 ``adapter.dispose()``，再按注册顺序的逆序清理该实例的 SDK 资源。
#. 某一步失败时继续剩余步骤；每一步至多尝试一次，已经提前释放或失败的步骤也不重试。
#. 清理结束进入 ``disposed``，即使汇总清理错误后抛出 ``SimulationError``。再次 ``dispose`` 为无操作。

创建同步失败时，运行时直接抛出含主 ``RuntimeDiagnostic`` 的 ``SimulationError``，清理等附加错误归入 ``related``；所有初始化失败路径都必须清理，且不得交付半成品。工厂自身建立的外部资源仍由器件在失败路径负责释放。

销毁后 ``time``、``status`` 和诊断信息可读，板事件不再分发；其他板能力、context、输入端点与借用句柄失效。旧 context 的发送输入、发布话题、受控写入等副作用操作 MUST 抛出带稳定 ``code`` 的 ``SimulationError``。旧异步任务不能经由旧 context 影响新板。

旧 context 的 ``reportError`` 是特例：仅产生过期诊断，正常返回，不改变新板状态。原板仍可分发诊断时使用 ``onDidDiagnostic``，板事件分发停止后通过 ``console.error`` 兜底。当前板首次有效上报与故障后附加上报的区别见 :doc:`/errors`。

``BorrowedBytes`` 句柄在同一实例代次内可复用，销毁后失效；句柄有效不等于其内容跨推进稳定，``loadBytes`` 可以提前结束内容稳定期。``ReadonlyBytes`` 属性与消息快照、调用方拥有的字节副本可跨推进及销毁留存。字节主定义见 :doc:`/memory`。

一致性核对
------------------------------------------------

生命周期的一致性检查关联 :doc:`/conformance`：

* 后创建实例收不到此前初始化广播；装配成功后的广播可送达所有仍有效的订阅。
* 工厂注册资源后抛错：先使所有 context 失效，再按逆序清理；附加清理错误不覆盖初始化主因。
* ``sync`` 按 ``instances`` 顺序调用，暂存的输入在下一批注入，不被本批清理删除。
* 话题按注册顺序同步嵌套广播；宿主 listener 异常隔离，器件异常后停止后续器件分发。
* 销毁先使所有 context 失效，再逆序释放；失败步骤不重试，汇总抛错后仍为 ``disposed``，再次销毁无操作。
* 旧任务上报仅产生过期诊断，正常返回且不影响新板；事件停止后使用 ``console.error``。
* ``ReadonlyBytes`` 跨推进和销毁保持稳定，``BorrowedBytes`` 销毁后失效。

宿主方法、事件类型与稳定错误码统一引用 :doc:`host`，不另设生命周期专用宿主接口。
