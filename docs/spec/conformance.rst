.. _spec-conformance:

================================================
校验与一致性
================================================

本章规定如何将规范条款转为可验证要求。文档中的预期结果是实现的验收目标，不表示当前运行时已经通过相应测试。

校验阶段
------------------------------------------------

.. list-table::
   :header-rows: 1
   :widths: 20 45 35

   * - 阶段
     - 校验内容
     - 失败边界
   * - 定义检查
     - 声明、类型、静态表达式、派生依赖及函数效果。
     - 定义在参与装配或执行前被拒绝。
   * - 装配绑定
     - 类型标识、实例与 pin 引用、props、资源类别、入口和函数签名。
     - 全板静态错误先于工厂调用；工厂错误按生命周期清理。
   * - IR 检查
     - 操作类型、实例资源归属、同步调用效果、JIT 上下文及等待尾位置。
     - 无效块在产生模型副作用前被拒绝。
   * - 操作边界检查
     - 时间、地址、完整范围、存储值及消息输入。
     - 该次非法操作保持其目标不变；故障范围按错误合同确定。
   * - 运行时检查
     - 钩子同步返回、代码失效、恢复位置、同刻工作量和实例代次。
     - 保留已发生状态，按故障或失效对象规则报告。

DDL 与 Builder 生成的 IR MUST 满足相同校验要求。Builder 提供额外类型提示，不替代运行时检查。

校验器可提前报告可证明的错误，但不得因提前生成模型后续路径而提前执行该路径的模型行为。

诊断要求
------------------------------------------------

错误诊断应能定位所属定义、实例、资源和阶段；运行时错误携带当前仿真时间及原始原因。

存在源码位置或生成位置映射时，诊断 SHOULD 保留它，帮助关联 DDL 与动态生成路径。

IR 构造与校验使用 :doc:`ir/validation` 的固定分类码、英文消息和来源结构。统一运行时错误事件和主因、清理错误的关系见 :doc:`errors`，精确板级事件字段与类型附件见 :doc:`javascript/host`。

下列场景标识用于规范验收追踪，而非运行时错误码。

资源与执行场景
------------------------------------------------

.. list-table::
   :header-rows: 1
   :widths: 15 45 40

   * - 标识
     - 前提与操作
     - 必须观察到的结果
   * - ``C-01``
     - 同一定义创建两个实例，分别读写同名 state 与 memory。
     - 可变资源彼此独立。
   * - ``C-02``
     - 同实例两个同时就绪入口各无等待地对同一计数加一。
     - 按稳定执行顺序累计两次，读改写之间不插入另一入口。
   * - ``C-03``
     - 一个入口读取状态后实际等待，期间另一个入口更新状态。
     - 恢复的局部值仍为旧值，重新读取获得最新值。
   * - ``C-04``
     - 一个片段连续替换同一 pin 的 intent。
     - 只有最终意图参与边界求解；片段内 sample 保持上次结果。
   * - ``C-05``
     - 越界执行多字节存储写入，之前已有一次成功写入。
     - 非法操作没有部分写入，之前成功写入保持有效。
   * - ``C-06``
     - 两个不同 pin 分别贡献到供电引脚和地引脚的电阻，输出经装配同网。
     - 网络结果由全部支路共同决定，不按写入次序选择一条支路。

批次与生命周期场景
------------------------------------------------

.. list-table::
   :header-rows: 1
   :widths: 15 45 40

   * - 标识
     - 前提与操作
     - 必须观察到的结果
   * - ``C-07``
     - 本批输入只消费一部分，sync 中再次发送输入。
     - 旧未读输入清理，新输入保留至下一批；过程恢复位置保留。
   * - ``C-08``
     - JS 发送记录或字节后修改原对象。
     - DDL 获得发送时值，输出消息快照跨推进与销毁保持有效。
   * - ``C-09``
     - 同批多次通知，随后在 sync 读取 public memory。
     - 通知时间为最后发送时间；读取内容为同步点最终状态。
   * - ``C-10``
     - ``Overflow.error`` 通道溢出，JS 捕获发送异常。
     - 整板仍为 faulted，溢出消息未入队，既有状态保留。
   * - ``C-11``
     - A.sync 已交付，B.sync 未捕获异常，C 尚未调用。
     - A 与 B 已发生副作用保留，C 不调用，本次推进失败，余下输出不补发。
   * - ``C-12``
     - 工厂先创建 SDK 资源再抛错，或某清理步骤失败。
     - SDK 资源仍有实例归属；清理继续尝试其他步骤，各步骤至多尝试一次。
   * - ``C-13``
     - 销毁旧板并创建新板后，旧 context 的异步结果调用输入端点或 reportError。
     - 旧副作用被拒绝，旧 reportError 仅为过期诊断，新板不被标故障。

JIT 场景
------------------------------------------------

.. list-table::
   :header-rows: 1
   :widths: 15 45 40

   * - 标识
     - 前提与操作
     - 必须观察到的结果
   * - ``C-14``
     - 初始化注册 JIT，但尚未推进。
     - 资源绑定完成，尚无指令执行副作用。
   * - ``C-15``
     - 钩子直接赋值位置并正常返回，条件仍为 true。
     - 按最终位置准备指令，不在原地重复钩子。
   * - ``C-16``
     - 嵌套同步函数 redirect 到等于顺序后继的位置。
     - 仍跨调用层终止剩余路径，只执行转向指定耗时，已发生副作用保留。
   * - ``C-17``
     - 指令等待期间修改代码或绑定位置。
     - 当前指令正常完成，不重放前缀；后续按实际位置与有效版本继续。
   * - ``C-18``
     - waitUntil 挂起期间改代码，随后依赖才满足。
     - 改码不单独唤醒；依赖满足后完成指令并按新版本选路径。
   * - ``C-19``
     - 模型事件、指令阶段同时于 T 到期，推进目标恰好为 T。
     - 模型事件及反应生效，JIT 后续代码和边界钩子延至下一次目标大于 T 的调用。
   * - ``C-20``
     - 拆分同刻推进调用或重建编译块，执行持续的零时间控制转向循环。
     - 返回宿主和块重建不重置已用额度，持续工作受到同刻防护；不同优化配置的总计数与超限位置可以不同。

Builder 构造场景
------------------------------------------------

以下要求检查构造语义；方法名及具体签名的评审不改变这些结果。

.. list-table::
   :header-rows: 1
   :widths: 15 45 40

   * - 标识
     - 前提与操作
     - 必须观察到的结果
   * - ``C-21``
     - 生成读取 x 为 a、写入 x、再将 a 写入 y。
     - 构造时无仿真副作用；执行时 y 保存该次读取结果。
   * - ``C-22``
     - 分支使用外层局部槽传出结果，循环条件区重新读取该槽。
     - 只执行选中分支，条件每轮重新执行，局部初始化在声明执行位置发生。
   * - ``C-23``
     - 使用分支专属临时值、另一函数的局部槽，或前一 JIT 指令的临时值。
     - 作用域校验拒绝非法引用；同指令实际等待后的合法引用保持有效。
   * - ``C-24``
     - 回调结束、构造完成或失败后继续使用 Builder，或在终结路径后追加操作。
     - 报告构造错误，不返回可执行的无效结果。
   * - ``C-25``
     - 以字符串名称及错误期望类型读取资源或取得函数结果。
     - 绑定时与真实声明核对并拒绝不匹配，TypeScript 通过不能替代此校验。
   * - ``C-26``
     - 普通循环条件同步写入，另在 pure 条件写资源、条件区等待或同步函数生成等待。
     - 普通同步写入合法；pure 写资源及同步区挂起拒绝；受限 JIT 视图不能新增实例资源。

DDL 首版语言场景
------------------------------------------------

下列场景验证语言合同，需由后续编译器、IR 与执行实现提供证据；文档构建不等于这些场景已经执行通过。

.. list-table::
   :header-rows: 1
   :widths: 15 45 40

   * - 标识
     - 前提与操作
     - 必须观察到的结果
   * - ``C-27``
     - 解析单 device 文件，并尝试第二个 device、文件级 record 或 import。
     - 自包含文件合法，其他结构拒绝；device 内类型与函数可前向引用。
   * - ``C-28``
     - 对照 LF / CRLF、可选 BOM、中文字符串与 UTF-16 列定位，尝试非法转义或标识符。
     - 合法文本模型相同；诊断保留准确文件与 1 基行列；非法词法拒绝。
   * - ``C-29``
     - 计算除零、NaN 比较、正负零及幂；分别提供溢出字面量与显式 Infinity。
     - 普通算术沿约定结果，NaN 不等于自身；溢出字面量拒绝，Infinity 常量合法。
   * - ``C-30``
     - 对小数、非有限值、超 32 位值执行位运算，并将相同值用于地址操作。
     - 位运算按 ToInt32 / ToUint32 与低 5 位移位量；地址仍按原值严格校验。
   * - ``C-31``
     - 在实参、二元、记录字段、列表、&& / || 和三元分支内放置可观察同步调用。
     - 按源码从左到右，仅计算实际选中路径；命名实参不按形参顺序重排。
   * - ``C-32``
     - 重赋值 const、参数、只读字段，或遮蔽可见成员；对照合法 let 和兄弟作用域。
     - 非法更新与遮蔽拒绝；let 更新有效，兄弟块可独立复用局部名。
   * - ``C-33``
     - 对局部可空值使用复杂条件和提前返回，另尝试直接沿资源路径复用先前收窄。
     - 合法局部路径收窄；赋值更新事实；资源先存局部再检查，挂起不刷新保存值。
   * - ``C-34``
     - 构造两个同字段但不同名记录、空记录、枚举与含 NaN 的记录。
     - 保持具名身份和只读字段；记录按字段相等，NaN 字段不获得引用身份捷径；枚举无数值转换。
   * - ``C-35``
     - 构造 bytes[] 和 bytes[0, 255]，随后使用小数或越界元素，并索引 string / bytes。
     - 合法值是独立只读快照；元素不截断；非法索引不返回 none 或宿主 undefined。
   * - ``C-36``
     - 声明 bytes 端点 maxLength，发送实际长度较小和超长的字节值。
     - 上限属于端点而非值类型；按实际长度检查，校验先于溢出策略。
   * - ``C-37``
     - pure fn 经辅助调用尝试写资源、等待、random 或调用普通 fn；另构造递归调用图。
     - 效果与无环调用检查拒绝；局部更新、循环、纯读取及断言仍合法。
   * - ``C-38``
     - 属性默认值和 const 前向依赖，实例覆盖默认；另构造环并提供全部属性值。
     - 合法无环依赖在创建期求值，提供值替代默认；有环定义始终拒绝，工厂前检查配置和断言。
   * - ``C-39``
     - 无启动过程、一个 process start，以及两个启动过程或 process run 无 on。
     - 前两者合法；重复或隐式启动形式拒绝，过程不能普通调用。
   * - ``C-40``
     - match 枚举、bool、可空值和字符串，尝试缺分支、重复模式、兜底后追加或路径终结后语句。
     - 穷尽且无贯穿；错误结构拒绝，非空分支收窄；loop / while 的返回证明遵守合同。
   * - ``C-41``
     - await 独立语句、局部初始化和赋值；另嵌入算术、实参、return 或同步 fn。
     - 只接受过程内完整等待位置；ticks 无值，receive 返回负载类型；恢复不重放前缀。
   * - ``C-42``
     - state 使用创建期初值，derived 经 pure fn 读取 runtime 资源；另把 runtime 读取移入初值。
     - 前两种符合上下文；创建期 runtime 读取拒绝，derived 依赖图成环也拒绝。
   * - ``C-43``
     - 直接 pin / memory 传参，并尝试资源局部、资源返回、端点传参及板级参考的直接引用。
     - 仅允许约定的直接引用与资源形参；板级参考不进入器件资源，resistor 目标只接受本实例 pin。
   * - ``C-44``
     - 两实例显式使用相同四字初始状态执行相同 random 调用；额外消耗另一实例序列，再销毁并重建板。
     - 值有限且位于 [0, 1)，流独立、相同调用序列可复现，新板从配置初始流开始；按 :doc:`/execution/random` 的固定向量验证。
   * - ``C-45``
     - 反应源使用静态字段路径，再尝试运算、调用、动态索引或输出通知。
     - 仅合法可观察源接受；bool 源不是隐式 true 条件，触发合并、稳定值比较与 intent 源拒绝按 :doc:`/execution/scheduling`。
   * - ``C-46``
     - 对照优先级、-2 ** 2、带括号幂、带分隔符字面量及错误混用的实参。
     - 幂右结合且拒绝未括号的一元左值；字面量分隔位置受检；普通调用不混用参数形式。

时间读取场景
------------------------------------------------

.. list-table::
   :header-rows: 1
   :widths: 15 45 40

   * - 标识
     - 前提与操作
     - 必须观察到的结果
   * - ``C-47``
     - 同一同步片段调用两次 now，保存第一次结果，显式等待 1000 ps 后再次读取。
     - 前两次时间相同，后一次比保存值大 1000；旧局部不刷新，读取自身不推进时间。
   * - ``C-48``
     - pure fn 经辅助调用读取 now，或在 derived、创建期和等待谓词中使用。
     - 沿调用图拒绝时间依赖；普通 fn、process 与 JIT 执行路径可以读取，读取不注册唤醒。
   * - ``C-49``
     - 提前生成包含 now 的 IR，执行期间跨等待恢复，并比较优化前后的多个实例读取。
     - 时间在实际执行处取得，同一板级时刻一致；不返回构造时间或跨挂起缓存的旧值，随机序列不被消耗。

这些场景是后续实现的验收要求，不表示本次文档构建已经验证运行时行为。

IR 结构与构造接口场景
------------------------------------------------

以下场景定义后续 IR 校验器、Builder 与执行器的验收目标。声明附件的 tsc 检查只覆盖 TypeScript 层，不能作为这些行为已经实现的证据。

.. list-table::
   :header-rows: 1
   :widths: 15 45 40

   * - 标识
     - 前提与操作
     - 必须观察到的结果
   * - ``C-50``
     - 手工按 schema 构造定义或块，校验成功后修改输入节点、数组、来源或字节数据。
     - 返回结果保持捕获的不可变语义；手工对象不获得额外权限。
   * - ``C-51``
     - 常量节点包含 NaN、无穷大、负零、枚举、记录与 bytes，另构造无目标类型 none 或非法字节。
     - 保留合法数值与具名身份；错误类型及字节拒绝，不通过 JSON 丢失数值信息。
   * - ``C-52``
     - 操作引用未定义、重复、分支外或另一指令的结果 / Local 编号。
     - schema 或作用域校验拒绝；可见外层引用与同指令跨挂起值合法。
   * - ``C-53``
     - 创建期配置从属性计算长度，定义多次实例化；另在创建期经 pure fn 读取运行资源。
     - 每实例按自身属性执行生成计算；构造回调只运行在生成期；非法读取拒绝。
   * - ``C-54``
     - 从两个名称相同但属于不同定义的类型描述或资源句柄构造输入。
     - 归属检查拒绝非法复用；前向具名描述完成时核对实际成员与字段。
   * - ``C-55``
     - Builder 从记录对象和字节子视图捕获常量，后修改宿主数据；另给记录额外字段。
     - 只捕获输入时内容，字节按视图范围复制；记录常量严格拒绝额外字段。
   * - ``C-56``
     - and / or / select 的未选中区域包含普通同步效果，assert 成功时消息区域含效果。
     - 运行时只执行选中区域，成功断言不求消息；不得提前消耗 random。
   * - ``C-57``
     - 普通 while 条件调用每次递增计数的 step，循环体含 continue；另在 pure 条件写资源或条件中等待。
     - 条件每轮重新执行且 continue 回到条件；pure 写入与任何条件挂起拒绝。
   * - ``C-58``
     - 计算区域 yield、区域内部循环 break；另用 yield 冒充调度让出、return 外层函数或跳转外层循环。
     - yield 只交付区域结果，不让出调度；跨区域的非法控制拒绝。
   * - ``C-59``
     - nonNull 使用路径证明、Local 赋值与循环汇合；另复用另一次资源读取的旧证明。
     - 只接受当前有效证明，快照跨挂起保留；新读取不继承证明，不生成强制解包。
   * - ``C-60``
     - 将 pin / memory 形参传入辅助函数，对照伪造板级参考、端点和普通字符串的非法资源实参。
     - 仅匹配资源引用合法；资源身份与普通 string 值不混淆。
   * - ``C-61``
     - JIT 动态 elapse 开始后，其他入口修改其时长来源；redirect 使用动态 target / delay。
     - 已开始阶段使用捕获时长；转向使用执行处数值，按既有延时与边界合同恢复。
   * - ``C-62``
     - waitUntil 位于末条指令的 if / match 尾分支；另在外层追加后缀、下一指令或放入循环。
     - 合法尾分支接受；非法后缀及循环位置拒绝；立即满足也不执行额外后缀。
   * - ``C-63``
     - JIT 块为空、边界非有限、首 pc 不匹配或相邻不连续；对照合法小数或非单调位置。
     - 前者拒绝；合法有限位置不被额外整数、递增或唯一约束拒绝。
   * - ``C-64``

     - 旧板销毁后，旧 context 发送、发布、装载或 reportError；新板使用相同实例 ID 正常运行。
     - 旧副作用拒绝，reportError 正常返回且仅过期诊断；新板时间、状态、种子、订阅和缓存均不被污染。
   * - ``C-124``
     - 编译器件生成的 context/factory/batch 类型与宿主创建代码，并加入错误 payload、旧 reset 和不可留存借用赋值。
     - 精确正向类型通过，预期误用在 tsc 中拒绝；范围、调用阶段与真实名称仍需运行时检查，类型通过不是仿真执行证据。

整合边界场景
------------------------------------------------

以下场景补齐模型来源、错误包装、调用优先级与计算区域终结在整合复核中发现的交叉边界。

.. list-table::
   :header-rows: 1
   :widths: 15 45 40

   * - 标识
     - 前提与操作
     - 必须观察到的结果
   * - ``C-125``
     - 以不同登记 ID 注册相同名称的模型，其中一个仅由 Builder 构造，工厂用通用 SDK 泛型注解；另重复同一登记 ID。
     - ID 与 model.name 独立，不要求 DDL 源码或额外类型名字段；合法模型均能装配，重复登记报 INVALID_CONFIGURATION、phase 为 library。
   * - ``C-126``
     - 创建时分别提供非法 props、seed、randomState、未知配置字段及无效模型；另使创建期 assert 失败。
     - 创建入口均抛 SimulationError 且不交付板；配置原因用 INVALID_CONFIGURATION，模型校验用 MODEL_VALIDATION_FAILED，创建期求值及断言失败用 MODEL_EXECUTION_FAILED、phase 为 assembly；已有专用分类码时保留。原始参数或模型校验异常引用保留于 error.diagnostic.cause，工厂调用次数为零。
   * - ``C-127``
     - disposed 板 runUntil(NaN)、faulted 空闲板 runUntil('x')、错误事件回调内同板 runUntil('x')，以及失效 context 用非法字节源装载。
     - 对象失效优先 OBJECT_DISPOSED；其次阶段或同板重入优先 INVALID_CALL_STATE，再按所需状态报 BOARD_FAULTED，合法状态下才检查参数；重复 dispose 仍无操作，无重复故障事件。
   * - ``C-128``
     - 在 ready 板 publish，器件监听器分别抛原始异常、返回 thenable 或 reportError；覆盖嵌套发布及 sync 内发布。
     - 先 faulted，再同步首个 onDidError，停止后续器件分发，合法 publish 正常返回；sync 后运行时停止后续交付，runUntil 抛 SimulationError。已故障板上的下一次 publish 直接拒绝。
   * - ``C-129``
     - 普通计算回调全部路径 redirect 而返回 void，或一条路径 redirect、另一条正常返回 Operand；另让仍可正常结束的路径漏返回值。
     - 前两种生成合法终结或产值区域，漏产值以 IR_CONTROL_FLOW 拒绝，不把 undefined 当常量；纯计算回调的无值返回在 tsc 中拒绝。
   * - ``C-130``
     - 检查具名枚举、null、缺省和必填 props、NaN 及无穷数值，普通 JS 尝试改变 ctx.props；记录多个实例的工厂调用顺序。
     - 合法属性在模型与工厂侧一致，非法属性在工厂前拒绝；属性不可变具有运行时保护，不仅是 TS readonly；工厂严格按 instances 顺序调用。
   * - ``C-131``
     - 用无原型字典及 __proto__ 自有字段装配；对照空 ID、空白 ID、大小写和 Unicode 编码不同的 ID。
     - 查找只使用自有字段，不触发原型行为；空字符串拒绝，非空字符串原样保留，不裁剪或规范化；声明存在的属性仍按类型校验。
   * - ``C-132``
     - 在板 A 的 sync、话题或错误监听器中推进或销毁独立板 B；再通过 B 的回调尝试重新进入仍忙碌的 A。
     - B 不因 A 的调用阶段被全局封锁；重新进入 A 被拒绝。捕获该拒绝后两板各自保留原状态，未捕获异常仍按所属器件或宿主回调规则处理。
   * - ``C-133``
     - 实现后分别从根入口、/device、/model、/ddl 和器件生成模块导入公开符号，检查根入口加载依赖。
     - 公开导出符合宿主章节的职责表，开发与发布子路径一致，根入口不隐式加载 Langium；规范附件本地 tsc 通过不替代真实发布入口检查。

同步响应与宿主隔离场景
------------------------------------------------

以下场景区分同步 reaction、可合并的普通 process 以及宿主执行隔离。源码、IR 和 Builder 均须覆盖同一行为；无限计算场景仅允许在可从外部终止的执行容器中验证。

.. list-table::
   :header-rows: 1
   :widths: 15 45 40

   * - 标识
     - 前提与操作
     - 必须观察到的结果
   * - ``C-134``
     - 声明 reaction，绑定源 old/new 与多个采集项；对照省略 capture、source 为 input notification、源为 intent、计算式源、重复名称及遮蔽。
     - 合法静态可比较值源接受；非法源及名称拒绝。源绑定和采集绑定只读，仅在本响应体可用，采集项不能相互引用或读取 old/new。
   * - ``C-135``
     - 源按不同轮发布 0→1→2；另重复发布 NaN、正负零、相同记录或 bytes 内容。
     - 响应分别得到 (0,1)、(1,2)，稳定相同值不触发；只有采集项依赖变化、源不变时也不触发。
   * - ``C-136``
     - 普通入口 A 在 data=高时发布 clock 上升沿，已就绪普通入口 B 随后发布下降沿或将 data 改低。
     - A 后立即完成边界采集与同步锁存闭包，再执行 B；上升沿不被合并，采集的 data 保持高，B 不污染采集值。
   * - ``C-137``
     - D 触发器以 clock、clear 记录作为源，采集 data；同轮 clock 与 clear 一起变高，或仅 data 改变。
     - 记录变化只触发一次，响应体可明确清零优先；仅 data 变化不触发。初始高时钟不伪造上升沿。
   * - ``C-138``
     - 同轮响应 A 写 state、memory 与 pin.intent；B 在后面直接读取这些资源，并读取此前已采集的值。
     - 全轮采集先完成；B 的直接状态和存储读取观察 A 的写入，采集值仍是原值；sample 保持该轮已发布快照，响应之间不求解。
   * - ``C-139``
     - 同轮多个响应改写同一 pin，或将 state 0→1→0；另通过不同轮分别发布 0→1→0。
     - 同轮仅最终意图及状态形成下一发布，不产生中间边沿；跨轮变化分别触发 reaction。普通 process 逐轮观察但合并排队，已排队任务不因终值回原值取消。
   * - ``C-140``
     - 响应修改自身观察源或依赖另一响应的源；存在普通任务已就绪。
     - 下一轮按新发布源重新采集并同步执行，不递归、不使用 process 忙碌补跑标志；有限闭包完成后才执行普通任务。无限反馈交由宿主容器终止。
   * - ``C-141``
     - 多实例、多声明同时触发，多个采集项可能断言失败；另使后面的响应体抛框架错误。
     - 源比较按实例和声明顺序，采集按项书写顺序；采集首错误立即故障，本轮任何响应体都不执行。响应体错误停止后续响应，保留此前资源效果及已发布快照。
   * - ``C-142``
     - 初始化建立源基线，capture 中放置仅触发时失败的断言；另使初始源的 derived 求值失败。
     - 无初始事件则不求 capture、不执行响应；初始源失败则首次推进故障且不执行 start，不在 createBoard 中提前执行该模型行为。
   * - ``C-143``
     - 早创建实例的 start 发布变化，触发尚未执行自身 start 的另一实例 reaction。
     - 同步响应先运行，后续 start 可观察其已生效状态；不能依赖自身 start 先执行。初始输出和未知输入策略由器件明确表达。
   * - ``C-144``
     - 在 reaction 中读写 state、memory、intent，调用同步函数，使用 now/random/assert，发送输出；另直接或间接等待、receive、redirect。
     - 同步效果接受，禁止效果沿调用图在执行前拒绝；输出进入原批次，不在边界内调用宿主 sync。响应体 return 只结束本次响应。
   * - ``C-145``
     - 同步响应产生瞬时 true，后续普通任务又置 false；另在目标时刻 T 到期普通事件触发响应。
     - JIT waitUntil 在整个模型阶段稳定后复查，不以瞬时 true 完成；T 的普通事件及响应闭包在 sync 前完成，JIT 后续执行仍受终点规则限制。
   * - ``C-146``
     - 采集 bytes、sample、具名记录和可空值，随后改变其读取的 memory 或 sample；对照采集 intent、资源引用及有副作用表达式。
     - 合法结果保持独立不可变值，bytes 按快照语义读取，不保存全板状态；非法类型或效果拒绝。分配失败立即按框架故障处理，不用空值替代。
   * - ``C-147``
     - 从 TypeScript 及普通 JavaScript 创建选项，尝试传入已移除的 sameTimeBudget 字段。
     - 类型合同拒绝该额外字段；运行时按未知配置字段拒绝，不启用隐式默认计数或旧预算诊断。
   * - ``C-148``
     - 对照 DDL 与 Builder 声明同一 reaction，包括 old/new、空采集、多项采集、函数调用及禁止效果。
     - 产生等价共享 IR 与诊断；不允许用不同的资源读取、非快照捕获或 process 合并机制替代 reaction。

差异验证
------------------------------------------------

对同一组输入，比较正常完成或报告模型错误的 DDL 路径、等价 Builder 路径及不同优化配置的状态、时间、消息和模型错误位置。宿主基于实际耗时的容器终止单独验证，不作为确定性模型错误或跨实现一致性结果。

对内部纯执行路径改变推进切片时，已发生行为应遵守恢复和终点规则；涉及外部反馈的路径还受批次边界影响。切片改变输入注入或未读清理时，不能要求两次运行无条件相同。

无效输入测试应覆盖名称、类型、边界、溢出、thenable、失效 context 和错误控制效果。

语言、IR、Builder、调度、电气及宿主接口构成实现基线，运行时场景仍需实现证据。合同类型检查及随机参考计算不替代本章场景的执行验证。
