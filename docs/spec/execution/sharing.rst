.. _spec-sharing:

================================================
资源共享与可见性
================================================

资源由实例拥有，入口共享访问，调度边界决定交错。资源的归属与入口的恢复数据是两个层次。

实例内访问
------------------------------------------------

同一实例的多个过程和 JIT 入口默认允许读写相同 state、memory；同一 pin 也可以由多个入口更新。

函数中的资源访问属于调用它的执行入口，函数本身不成为额外写入者。

入口之间的共享权限包括 JIT 绑定的数值位置状态，通常以接口字段 ``pc`` 指定。语言不为该状态增加入口级私有权限。

模型可以约定由某个入口集中更新特定状态，该约定属于模型组织方式，而非仿真系统的默认访问限制。

板和其他实例保持资源封装。生成 IR 可以引用所属实例私有资源，普通 JavaScript 则通过 context 授权接口访问，见 :doc:`/javascript/interfaces`。

即时读写
------------------------------------------------

同一同步片段中的 state、memory 读写按执行顺序立即生效。

两个同时就绪入口各执行一次读取、加一、写回，且期间没有实际等待时，将按确定顺序累计两次更新。

对同一位置直接赋值时，后一次成功写入覆盖前一次结果。

memory 单次操作的参数检查及完整性由 :doc:`/memory` 规定；即时共享不使整个函数或整条指令成为事务。

等待与局部值
------------------------------------------------

局部值保存计算时的结果。``const`` 与 ``let`` 都必须初始化，前者不可重赋值，后者可重赋值；局部名称不能遮蔽已有名称。跨等待恢复时，局部值不会自动重新读取共享资源。

.. code-block:: text

   读取 counter，保存为 old
   等待一个尚未满足的条件
   将 old + 1 写入 counter

等待期间其他入口可能修改 ``counter``；恢复后的写入仍基于 ``old``，可能覆盖其间的更新。需要最新状态的模型应在恢复后重新读取。

非空通道接收不实际挂起，因此它不会在读与写之间引入交错；空通道接收则可能引入交错。

pin 与通道
------------------------------------------------

同一 pin 保留一份完整 intent，后写替换先写，而非按入口保留独立驱动。不同 pin 的支路分别参与网络求解。

需要同时存在的多条支路由模型组合在一份 intent 中，或通过多个独立 pin 表达。

通道保持单消费者约束；state 和 memory 的默认共享不授予多个入口竞争接收同一 FIFO 的能力。

JIT 位置更新
------------------------------------------------

其他入口在当前 JIT 指令等待期间修改绑定位置状态时，当前指令继续完成剩余阶段与耗时。

指令完成后按实际最终位置决定下一路径；离开旧路径时抛弃未执行的编译块后缀，已发生副作用保持有效。

普通位置赋值不立即取消当前执行路径。需要终止当前 JIT 路径时，模型使用 :doc:`/jit/interrupts` 定义的 ``redirect``。

边界钩子同样可以普通赋值，正常返回后按最终位置准备执行，不在原地重复检查钩子。

优化约束
------------------------------------------------

编译器可以内联函数、合并代码或缓存资源读取，但 MUST 保留其他入口在调度边界可观察到的变化。

跨等待继续执行时，不得以过期的优化缓存替代一次语义上要求的重新读取。显式保存的局部值则继续遵守值快照语义。

JIT 的代码版本变化是路径有效性条件，不改变实例内资源的共享权限，见 :doc:`/jit/code-memory`。
