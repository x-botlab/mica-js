================================================
执行与虚拟时间
================================================

仿真运行时根据模型规定的时间和依赖关系调度执行入口。入口可以消费仿真时间、等待条件，或在当前时刻完成同步操作。

   :maxdepth: 2

   scheduling
   sharing
   random

时间表示
------------------------------------------------

仿真时间使用 ``number`` 表示整数皮秒，分辨率为 1 ps，起点为 0。

时间戳表示相对起点的位置，时长表示两个位置之间的间隔。两者的合法范围均为 0 至 7_200_000_000_000_000 ps，包含端点。

时间接口 MUST 校验数值类型、有限性、整数性及范围。时间加法、减法和单位换算的结果也必须满足该范围。

.. list-table:: 单位换算
   :header-rows: 1
   :widths: 35 65

   * - 单位
     - 对应皮秒数
   * - 1 ps
     - 1
   * - 1 ns
     - 1_000
   * - 1 µs
     - 1_000_000
   * - 1 ms
     - 1_000_000_000
   * - 1 s
     - 1_000_000_000_000

``ticks(duration)``、JIT 的 ``elapse(duration)`` 和 ``redirect`` 的 ``delay`` 均使用上述时间单位。名称中的 tick 不引入另一种可配置时基。

``now()`` 读取当前板级仿真时间，返回上述整数皮秒时间戳，不增加时间或让出执行。同一同步片段内时间保持不变；实际挂起后新读取观察恢复时刻。它仅用于普通执行上下文，完整效果与优化边界见 :doc:`/language/builtins`。

普通数值运算不自动增加仿真时间；操作的耗时由模型显式表达。

宿主执行耗时与仿真时间独立。入口的先后顺序不由宿主执行速度决定。

执行入口
------------------------------------------------

DDL 的启动过程、反应式过程和注册的 JIT 入口由同一运行时调度。

``process start { ... }`` 是可选且唯一的启动过程。其他过程均使用 ``process name on source { ... }``，其中 ``source`` 是静态的 ``state``、``derived``、``pin.sample`` 字段或 input notification 路径。通知触发事件，其余触发源观察值变化；复杂条件先定义为 ``derived``，再订阅其名称。``start`` 保留给启动过程；其他名称的过程省略 ``on source`` 时属于语法错误，不具有隐式启动含义。过程不能作为普通函数调用。

初始化只建立观察基线；变化在同步片段结束时按最终值检测，反应过程忙碌时至多记一次待再运行。比较、初始化与排队规则见 :doc:`scheduling`，条件等待的保守静态订阅见 :doc:`/jit/interrupts`。intent 与 intent? 不作为变化触发源。

普通函数属于调用它的入口，同步调用本身不增加执行入口。函数参数类型全部显式声明且参数不可重赋值，调用图 MUST 无环。普通函数可使用 ``random()``，纯函数以 ``pure fn`` 标记，其效果边界见 :doc:`/language/functions`。

入口实际挂起时保存恢复位置和局部值，满足恢复条件后从该位置继续。恢复 MUST NOT 重复已经执行的前缀操作。

入口等待期间，其他就绪入口可以执行。一次函数调用、一次 JIT 指令及一个编译块分别有不同的边界，不能将它们一概视作一次原子执行。

DDL ``await`` 仅作为独立语句、``const`` / ``let`` 的初始化或赋值的完整右侧。``ticks`` 没有返回值，使用 ``await ticks(duration);``；``receive`` 返回消息值。等待不能嵌入算术、调用实参或 ``return``。

``return;`` 可结束当前过程运行或无值函数；有值函数的每条正常结束路径均返回值。``if`` 或穷尽 ``match`` 的所有分支终结时，该路径终结，之后追加语句报错。可能控制转向的函数调用不是必然终结，规则见 :doc:`/language/statements`。

推进调用
------------------------------------------------

宿主通过 ``runUntil(T)`` 将仿真推进到目标时间 ``T``。成功返回时，当前仿真时间为 ``T``；失败时保留已经实际发生的时间与状态。

推进目标 MUST 是合法时间戳，且不得早于当前时间。

一次正常推进的外部批次顺序由 :doc:`/channels` 规定，目标时刻的内部执行边界由 :doc:`scheduling` 规定。

反复以同一个目标时间调用，不会使仿真时间自行增加。是否处理新输入由批次注入规则决定，不能据此启动终点处被延后的 JIT 代码。

``runUntil(target): void`` 的宿主签名、调用阶段、返回与错误接口由 :doc:`/javascript/host` 定义；输出批次统一通过 sync 交付。

错误时间值
------------------------------------------------

非 ``number``、非有限值或非整数报告类型错误；负值、越界值及越界时间运算报告范围错误。

错误携带输入名称、非法值或涉及的运算，以及允许范围。

仿真执行中的未捕获时间错误遵循 :doc:`/errors` 的整板故障规则。宿主推进调用先检查对象有效性、当前阶段与同板重入、所需板状态，通过后才校验目标；非法目标抛 TypeError 或 RangeError。拒绝该调用本身不改变板状态；若异常逸出器件回调，则按该回调的未捕获异常处理，见 :doc:`/javascript/host`。
