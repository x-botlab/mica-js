.. _spec-scheduling:

================================================
调度与片段边界
================================================

调度在同一仿真时刻完成就绪行为、边界采样发布与反应，然后推进到后续时刻。阶段顺序和阶段内顺序共同决定可观察结果。

初始化
------------------------------------------------

全部工厂成功后，首次推进在执行模型前完成初始电气求解，并为所有反应源建立观察基线。建立基线本身不触发反应过程；求解值与求解失败的合同见 :doc:`/electrical`。

随后按实例顺序将各启动过程排入模型阶段队列，再按批次规则注入本批暂存输入，最后执行队列。启动过程能读取已注入输入；输入通知产生的反应按入队顺序排在此前已入队的启动过程之后。销毁会清理旧观察、排队与等待状态；新板首次推进独立执行此顺序。

同步片段
------------------------------------------------

同步片段从入口开始或恢复执行，持续到实际挂起、过程本次运行结束或逻辑 JIT 指令结束。片段内其他入口 MUST NOT 插入执行。

普通函数调用、state 与 memory 写入、消息发送和通知发送不隐式让出执行权。

从非空 FIFO 接收消息立即返回，仍在当前片段；从空 FIFO 接收消息实际挂起，结束该片段。

正时长等待将后续执行留到相应时刻，等待期间其他入口可以运行。

``await ticks(0)`` 必须结束当前片段，仿真时间保持不变。边界求解与变化检测产生的反应先入队，当前过程的恢复任务随后排在模型阶段队尾。恢复时可以读取该边界发布的新采样，但其他反应之后仍可能改变网络。

``ticks(0)`` 跨过一次边界，不等待反馈网络全局稳定。阶段稳定由调度器确定，不作为模型内可等待的事件。

JIT 的 ``elapse(0)`` 不挂起，也不形成额外边界。边界处理函数正常返回后继续当前指令片段，期间其他入口不能插入；指令结束、正时长耗时、实际条件挂起、stop 与 redirect 按各自规则结束片段。``redirect`` 的零延时仍结束当前路径，经调度重新进入边界。

边界与微轮
------------------------------------------------

state 与 memory 的成功写入立即生效，当前片段后续读取能观察到新值。pin 意图赋值立即替换本 pin 的完整描述；同片段多次替换只保留最后一份。片段内 sample 保持最近一次发布的快照。

每个同步片段结束时按以下顺序处理边界：

#. 根据最终意图完成必要的电气求解，通过后统一发布本边界全板 sample；任一分量求解失败则按 :doc:`/electrical` 停机，所有新采样均不发布，不进入后续边界步骤。
#. 维护派生依赖，以当前已生效的 state、memory 与新 sample 取得反应源最终值。
#. 与该源上一个边界的观察值比较，更新观察基线，并为变化的源触发过程；input notification 则按通知触发。
#. 标记受影响的条件等待需要复查，按阶段规则继续处理队列。

观察基线在过程忙碌期间同样更新。一个片段内 x 从 0 改为 1 再改回 0，不触发 ``on x``；从 0 改为 1 再改为 2，只形成一次变化触发。变化合并不延迟状态写入，同片段新读取仍立即看到每次成功写入。

边界产生的反应在同一仿真时刻执行，形成后续微轮。当前阶段的模型事件与反应队列清空后，才处理条件等待复查或后续 JIT 阶段。derived 表达式可调用 pure fn，静态依赖图 MUST 无环；读取始终反映已生效依赖，缓存维护不得改变可见性。

变化判定
------------------------------------------------

反应源使用以下稳定值比较，而非直接调用语言 ``==``：

* number 的 NaN 与 NaN 视为相同，正负零视为相同，其余按数值比较。
* bool、string 与同一具名枚举按值比较。
* 同一具名记录与 sample 按各字段递归使用此规则比较；bytes 按长度和字节内容比较。
* 可空值先比较是否为 none，非空时再比较内容。

intent 没有内容比较合同，intent 与 intent? 不能直接作为变化触发源；模型可声明返回可比较类型的 derived。电气数值容差只用于候选解的残差接纳，不为采样生成死区，也不改变这里对已发布值的比较规则。

反应式过程状态
------------------------------------------------

每个过程拥有独立运行状态及至多一个待再运行标志：

.. list-table:: 触发处理
   :header-rows: 1
   :widths: 24 76

   * - 当前状态
     - 新触发的处理
   * - 空闲
     - 排入所属阶段队尾，成为已排队。
   * - 已排队、尚未开始
     - 合并到该任务，不增加排队次数。
   * - 已开始运行或正在等待
     - 设置待再运行标志，不打断当前运行，也不提前恢复等待。
   * - 本次运行结束
     - 有标志则清除标志并从头排队一次；否则回到空闲。

过程从头运行时读取当前资源，不携带触发时的历史值。两个不同片段分别把 x 从 0 改为 1 再改回 0，即使过程尚未执行，已经排入的任务仍保留并可读到 0。过程自身在结束边界造成的变化也遵守此表，不能递归同步调用自身。

input notification 使用相同的排队合并机制，不积累触发计数。过程的 ``return`` 只结束本次运行。初始化仅建立观察基线，不自动安排反应式过程首次运行。

同刻顺序
------------------------------------------------

同一时刻按以下阶段处理：

#. 到期的模型事件、输入事件及其反应，处理至该阶段稳定。
#. 恢复已到期的当前 JIT 指令阶段，并处理其产生的反应。
#. 在当前指令完成、仍有推进预算时，进入下一条指令的边界检查。

阶段内已经就绪的入口保持稳定入队顺序。同时产生的一组入口按稳定实例顺序和入口顺序入队；这些顺序来自装配和声明或注册顺序。

稳定入队顺序在所属阶段内生效，不将后续 JIT 阶段提前到模型事件之前。

例如，一个条件变化与 JIT 耗时阶段在同一时刻到期，先处理条件变化及其反应，再恢复该阶段后的代码。指令完成后，边界钩子读取的是已经生效的条件。

目标时刻
------------------------------------------------

``runUntil(T)`` 将耗时推进到 ``T``，并处理 ``T`` 到期的模型事件、输入事件及其反应。

在 ``T``，运行时 MUST NOT 开始新的 JIT 指令、调用 JIT 边界处理函数，或恢复 JIT 指令的后续代码。

耗时阶段在 ``T`` 到期与执行其后的代码是不同动作。阶段可以到期，但后续代码留到下一次目标大于 ``T`` 的推进中执行。

条件等待在 ``T`` 满足时可以记录就绪状态，其后 JIT 代码同样延后。再次调用 ``runUntil(T)`` 不解除这一终点限制。

该限制针对 JIT 执行；不能据此推定所有普通过程在目标时刻也暂停，普通模型事件仍按上述第一阶段处理。

同刻工作量
------------------------------------------------

板级 ``sameTimeBudget`` 为正安全整数，默认 1_000_000，用于防止同刻执行持续占用宿主。全板实例共享同刻计数器；它衡量实际工作量，不是模型时间或优化无关的语义成本。每次实际执行下列动作前消耗 1：

* 一个模型事件或入口调度任务开始执行，包括反应运行、过程恢复与条件等待复查任务。同一任务不因内部排队封装而重复计为两个任务。
* 一条 JIT 指令开始。
* 一个实际调用的 JIT 边界处理函数进入。
* 一次 redirect 执行。
* 一次 while 条件求值，包括结果为 false 的检查；continue 返回下一次条件检查。
* 一次 loop 迭代开始，包括 continue 引起的下一轮。

类别叠加：例如调度任务内开始指令，再执行 redirect，分别消耗相应额度。未选中分支、被取消任务、跳过的边界函数不计数。等待期间本身不计数，调度其恢复时计数；零等待循环因此受到防护。

上限为 N 时，前 N 个动作可执行；下一动作开始前若已用计数等于上限，则报告 ``SAME_TIME_BUDGET_EXCEEDED``，该动作不执行，整板进入 faulted，保留已发生的状态和当前仿真时间，停止后续 sync。诊断携带阶段、时刻、上限、已用计数、待执行动作，以及可用的实例与来源位置；宿主错误事件的字段与分类由 :doc:`/javascript/host` 维护。

时间真正增加时清零计数；跨 runUntil 调用保留。同一时刻开始新批次或注入新输入均不清零；新板从零建立独立执行计数。改变调用切片不能仅靠返回宿主重置已用额度。

普通算术、派生缓存管理和订阅维护不逐条计数。实际执行的模型循环仍逐次检查，包括 pure fn、derived 与等待谓词内循环；优化后的无界同步执行仍须受防护，不能移除唯一的有效检查点。

缓存命中、公共子计算复用或其他优化实际跳过的计算不补扣额度。优化配置和缓存策略因此可以改变总计数、是否超限及超限位置；预算故障不属于跨优化等价的结果。只要未触发防护，资源、时间、消息、反应顺序及模型错误等可观察行为仍须满足相同合同。

创建期求值另设全板共享计数器，使用同一个上限，仅按上述 while 条件和 loop 迭代检查计数。每次新板创建期从零开始，不继承或消耗运行期同刻计数。创建期超限使用同一诊断码并标明创建阶段，使创建失败；尚未创建成功的板不作为运行中故障板返回。宿主 JavaScript 工厂和 Builder 构造回调不受 IR 循环预算约束。
