.. _spec-scheduling:

================================================
调度与片段边界
================================================

调度在同一仿真时刻完成就绪行为、边界采样发布与反应，然后推进到后续时刻。阶段顺序和阶段内顺序共同决定可观察结果。

初始化
------------------------------------------------

全板初始引脚意图已在任何工厂调用前建立为当前支路；省略初值的 pin 为空意图。全部工厂成功后，首次推进在执行模型前使用这些支路完成初始电气求解，再求值全部已订阅的静态值源（state、derived、pin.sample 及其字段），为普通过程与同步边界反应建立 previous/current 的初始观察基线。建立基线不执行捕获或反应体，也不触发普通过程；求解或源求值失败可在任何启动过程执行前使推进失败。求解值与求解失败的合同见 :doc:`/electrical`。

随后按实例顺序将各启动过程排入模型阶段队列，再按批次规则注入本批暂存输入，最后执行队列。启动过程能读取已注入输入；输入通知触发的普通过程按入队顺序排在此前已入队的启动过程之后。销毁会清理旧观察、排队与等待状态；新板首次推进独立执行此顺序。

每个启动过程结束片段后先完成同步边界反应闭包，才执行下一个普通入口。因此，较早实例的启动变化可以使较后实例的反应先于其自身启动过程执行；反应可访问创建期已建立的资源，但不能假定该实例的启动过程已经执行。

同步片段
------------------------------------------------

同步片段从入口开始或恢复执行，持续到实际挂起、过程本次运行结束或逻辑 JIT 指令结束。片段内其他入口 MUST NOT 插入执行。

普通函数调用、state 与 memory 写入、消息发送和通知发送不隐式让出执行权。

从非空 FIFO 接收消息立即返回，仍在当前片段；从空 FIFO 接收消息实际挂起，结束该片段。

正时长等待将后续执行留到相应时刻，等待期间其他入口可以运行。

``await ticks(0)`` 必须结束当前片段，仿真时间保持不变。边界变化触发的普通过程先按规则入队，当前过程的恢复任务随后排在模型阶段队尾；同步边界反应闭包先于这些任务执行。恢复时可以读取闭包最后发布的采样，但其他入口之后仍可能改变网络。

``ticks(0)`` 结束一个普通片段，其恢复必须经过该边界的同步反应闭包；它不等待尚未执行的普通模型队列全局稳定。阶段稳定由调度器确定，不作为模型内可等待的事件。

JIT 的 ``elapse(0)`` 不挂起，也不形成额外边界。边界处理函数正常返回后继续当前指令片段，期间其他入口不能插入；指令结束、正时长耗时、实际条件挂起、stop 与 redirect 按各自规则结束片段。``redirect`` 的零延时仍结束当前路径，经调度重新进入边界。

边界与微轮
------------------------------------------------

state 与 memory 的成功写入立即生效，当前片段后续读取能观察到新值。pin 意图赋值立即替换本 pin 的完整描述；同片段多次替换只保留最后一份。片段内 sample 保持最近一次发布的快照。

每个同步片段结束时按以下顺序处理边界：

#. 根据最终意图完成必要的电气求解，通过后统一发布本边界全板 sample；任一分量求解失败则按 :doc:`/electrical` 停机，所有新采样均不发布，不进入后续边界步骤。
#. 维护派生依赖，以当前已生效的 state、memory 与新 sample 取得全部已订阅的静态值源最终值，并冻结各源上一轮与本轮的 previous/current。
#. 比较各源的 previous/current，更新所有观察基线；为变化源触发的普通过程按既有规则排队或合并，并确定本轮同步边界反应集合。input notification 仍按通知触发普通过程。
#. 标记受影响的条件等待需要复查，执行下述捕获屏障与反应体；完整反应轮的效果共同形成下一发布边界，重复上述步骤，直至没有同步边界反应需要执行。
#. 闭包结束后，才按阶段规则执行下一个普通模型入口或进入等待复查与 JIT 阶段。

观察基线在过程忙碌期间同样更新。一个片段内 x 从 0 改为 1 再改回 0，不触发 ``on x``；从 0 改为 1 再改为 2，只形成一次变化触发。变化合并不延迟状态写入，同片段新读取仍立即看到每次成功写入。

每个发布轮都更新普通过程的源基线，即使过程已经排队、正在执行或等待。跨发布轮的 0→1→0 产生两次变化；排队合并可以合并触发，但不能撤销已排任务。derived 表达式可调用 pure fn，静态依赖图 MUST 无环；读取始终反映已生效依赖，缓存维护不得改变可见性。

同步边界反应
------------------------------------------------

同步边界反应订阅静态值源的变化，捕获与反应体共同构成一个反应声明。它与可挂起、可忙碌的普通过程独立。input notification 不加入同步边界反应集合。

每个发布边界确定本轮集合后，运行时 MUST 按稳定实例顺序、实例内反应声明顺序、声明内捕获表达式的文本顺序求值全部捕获。每个反应独立获得本轮源的 previous/current 与其 pure 捕获结果；捕获只读取该轮已发布的资源，不继承其他反应的捕获局部值。整个集合的捕获全部成功后，才能开始任何反应体，不能交错执行一个反应的捕获与另一个反应的体。

捕获结果及 previous/current 是不可变的值快照；bytes 等内容值也保持捕获时内容，不能因后续 memory 写入而变化。捕获中的 pure 调用遵守语言的纯性规则，包括允许的读取、局部计算与断言。

反应体按同一稳定实例与声明顺序同步执行，可执行普通同步副作用并调用相应函数；MUST NOT 执行 await、receive 或 redirect，此限制沿调用关系传播。state 与 memory 的成功写入立即生效，后续反应体的普通资源读取可见这些更新，但已捕获输入保持不变。pin intent 的后写替换前写，sample 保持本轮快照。两个反应体之间 MUST NOT 求解、发布或执行普通入口。

本轮全部反应体正常结束后，将整轮效果作为一个边界统一求解、发布与检测，再完成下一轮捕获屏障。反应自身造成的源变化在下一发布轮再次触发该反应，不使用普通过程的忙碌状态或待再运行合并。每一轮都在同一仿真时刻执行，闭包完成前不进入下一个普通入口。

捕获失败时保留本轮已发布输入、采样和观察基线，本轮任何反应体均不执行。反应体失败时停止本轮剩余反应体，保留此前成功的 state、memory、intent 及其他副作用；不为失败轮继续发布下一边界。两类失败均按 :doc:`/errors` 使整板故障。

变化判定
------------------------------------------------

反应源使用以下稳定值比较，而非直接调用语言 ``==``：

* number 的 NaN 与 NaN 视为相同，正负零视为相同，其余按数值比较。
* bool、string 与同一具名枚举按值比较。
* 同一具名记录与 sample 按各字段递归使用此规则比较；bytes 按长度和字节内容比较。
* 可空值先比较是否为 none，非空时再比较内容。

intent 没有内容比较合同，intent 与 intent? 不能直接作为变化触发源；模型可声明返回可比较类型的 derived。电气求解允许浮点舍入误差，已发布采样仍使用上述精确稳定值比较，不引入变化死区。

普通过程触发状态
------------------------------------------------

每个过程拥有独立运行状态及至多一个待再运行标志：

.. list-table:: 触发处理
   :header-rows: 1
   :widths: 24 76

   * - 当前状态
     - 新触发的处理
   * - 空闲
     - 排入所属阶段队尾，成为已排队。
   * - 已排队、尚未开始
     - 合并到该任务，不增加排队次数。
   * - 已开始运行或正在等待
     - 设置待再运行标志，不打断当前运行，也不提前恢复等待。
   * - 本次运行结束
     - 有标志则清除标志并从头排队一次；否则回到空闲。

过程从头运行时读取当前资源，不携带触发时的历史值。两个发布边界（包括同步反应轮）分别把 x 从 0 改为 1 再改回 0，即使过程尚未执行，已经排入的任务仍保留并可读到 0。过程自身在结束边界造成的变化也遵守此表，不能递归同步调用自身。

input notification 使用相同的排队合并机制，不积累触发计数。过程的 ``return`` 只结束本次运行。初始化仅建立观察基线，不自动安排反应式过程首次运行。

同刻顺序
------------------------------------------------

同一时刻按以下阶段处理：

#. 到期的模型事件、输入事件及其触发的普通过程，连同每个发布边界的同步反应闭包，处理至模型队列清空。
#. 在全部模型队列与同步反应闭包完成的稳定点，按注册顺序复查待检查的条件等待。
#. 恢复已到期或已满足等待的当前 JIT 指令阶段，并处理其结束边界产生的反应及模型队列。
#. 在当前指令完成、目标时刻允许继续时，进入下一条指令的边界检查。

阶段内已经就绪的入口保持稳定入队顺序。同时产生的一组入口按稳定实例顺序和入口顺序入队；这些顺序来自装配和声明或注册顺序。

稳定入队顺序在所属阶段内生效，不将后续 JIT 阶段提前到模型事件之前。

例如，一个条件变化与 JIT 耗时阶段在同一时刻到期，先处理条件变化及其反应，再恢复该阶段后的代码。指令完成后，边界钩子读取的是已经生效的条件。

目标时刻
------------------------------------------------

``runUntil(T)`` 将耗时推进到 ``T``，并处理 ``T`` 到期的普通模型事件、输入事件及全部同步边界反应闭包，完成后才允许本批 sync。sync 不重新进入模型执行。

在 ``T``，运行时 MUST NOT 开始新的 JIT 指令、调用 JIT 边界处理函数，或恢复 JIT 指令的后续代码。

耗时阶段在 ``T`` 到期与执行其后的代码是不同动作。阶段可以到期，但后续代码留到下一次目标大于 ``T`` 的推进中执行。

条件等待在 ``T`` 满足时可以记录就绪状态，其后 JIT 代码同样延后。再次调用 ``runUntil(T)`` 不解除这一终点限制。

该限制针对 JIT 执行；不能据此推定所有普通过程在目标时刻也暂停，普通模型事件仍按上述第一阶段处理。

终止性与宿主隔离
------------------------------------------------

模型循环、pure 求值、同步反应闭包及同刻任务可能不终止，创建或推进调用因而可能永不返回。核心不以逐循环或逐任务计数限制执行。正常输入、类型、范围检查及显式断言仍在对应操作处快速失败，优化 MUST 保留资源、时间、消息、反应顺序与模型错误的可观察合同。

宿主可将执行放入 Worker 或其他执行容器，并在容器外按墙钟时间终止它。墙钟终止属于宿主隔离策略，不是确定性的模型故障；强制终止不承诺执行 dispose、交付诊断或恢复模型状态。此策略不改变模型时间、调度顺序或宿主核心接口。
