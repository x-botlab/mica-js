================================================
错误边界与恢复
================================================

本章规定整板故障、部分交付及清理失败的行为。宿主接口、稳定错误码表及诊断类型的主定义见 :doc:`/javascript/host`，精确签名见 :download:`contracts/host.d.ts <contracts/host.d.ts>`。装配前置条件见 :doc:`/assembly`，JavaScript 调用与代次边界见 :doc:`/javascript/lifecycle`，时间及推进边界见 :doc:`/execution/index`。

本文使用 **MUST / MUST NOT** 表示必须满足的要求与禁止行为，**SHOULD / SHOULD NOT** 表示有充分理由才可偏离的建议，**MAY** 表示允许的选择。

错误分类
------------------------------------------------

.. list-table:: 错误及影响
   :header-rows: 1
   :widths: 27 73

   * - 情形
     - 可观察结果
   * - 装配静态校验失败
     - 拒绝装配，尚未调用任何器件工厂。
   * - 模型自身定义的异常
     - 按模型的状态变化与控制路径处理，与框架故障区分。
   * - 已创建对象的外部输入或宿主调用校验失败
     - 非法类型抛出 ``TypeError``，非法数值范围抛出 ``RangeError``；重入、失效对象和阶段违约抛出带稳定 ``code`` 的 ``SimulationError``。调用被拒绝本身不使板故障；异常逸出器件回调时，按该回调的故障规则处理。库和板创建入口的参数、模型及初始化失败统一封装为 ``SimulationError``，保留底层原因，见 :doc:`/javascript/host`。
   * - DDL 或 JIT 执行期间的框架错误
     - 执行合同无法继续满足，整板进入 ``faulted``；已经发生的时间与状态保留。
   * - 运行期电阻意图构造参数非法
     - 整板 faulted，尚未执行的 intent 赋值不发生；此前资源效果保留。阈值与固定电位配置的创建期错误在工厂调用前拒绝。
   * - 电气数值求解失败
     - 整板 faulted，本边界全板新采样均不发布，保留上次成功快照与已发生资源效果；不继续派生、反应或 sync。首次求解失败不启动模型。详见 :doc:`/electrical`。
   * - 同刻工作量预算超限
     - 运行期报告 ``SAME_TIME_BUDGET_EXCEEDED``，整板 faulted，停止后续执行与 sync；创建期使用每板从 0 开始的独立计数，超限使创建失败，见 :doc:`/execution/scheduling`。
   * - 工厂、``sync`` 或器件话题回调未捕获异常
     - 整板立即进入 ``faulted``；初始化失败时同时执行初始化清理。
   * - 工厂、``sync`` 或器件话题回调返回 thenable
     - 同步接口违约，按整板故障处理。
   * - 宿主话题回调或 ``onDidError`` 监听器抛错
     - 隔离单个监听器异常，继续其他允许的分发，通过非致命 ``onDidDiagnostic`` 报告；板的状态不因此改变。
   * - ``onDidDiagnostic`` 监听器抛错
     - 通过 ``console.error`` 兜底，继续其他监听器，不递归分发诊断。
   * - ``Overflow.error`` 队列溢出
     - 整板立即进入 ``faulted``，即使发送处异常被捕获也保持故障。
   * - 当前有效 context 调用 ``reportError``
     - 首次上报立即记录故障并封锁副作用，故障后上报为附加诊断；上报调用自身正常返回。
   * - ``dispose`` 或资源释放失败
     - 尽力继续清理并汇总错误；进入本章的清理失败路径。

已创建对象的调用守卫 MUST 依次检查 context 或对象有效性、当前阶段与同板重入、操作所需的板状态，最后才校验参数。因而 ``disposedBoard.runUntil(NaN)`` 报 ``OBJECT_DISPOSED``，``onDidError`` 回调中同板 ``runUntil('x')`` 报 ``INVALID_CALL_STATE``，均不进入参数校验。已销毁板的 ``dispose`` 优先作为无操作返回；``reportError`` 保留其失效上报特例。创建入口的失败封装继续以 :doc:`/javascript/host` 为准。

输入端点的同步校验失败使该消息不入队，具体规则见 :doc:`/channels`。调用方捕获这种校验异常与捕获 ``Overflow.error`` 不同：后者在抛错前已经使整板故障。消息类型与投影见 :doc:`/language/types` 与 :doc:`/javascript/interfaces`。

可选字段仅在省略时采用默认值；显式传入 ``undefined`` 或 ``null`` 时按原值校验，只有语言允许可空的位置接受 ``null``。宿主装配的 ``instances`` 与 ``nets`` 必填，均可为 ``[]``；省略 ``props`` 等价于 ``{}``。参数校验与错误码的完整对应以 :doc:`/javascript/host` 为准。

整板故障
------------------------------------------------

板的公开状态只有 ``ready``、``faulted`` 与 ``disposed``，状态转换以 :doc:`/javascript/host` 为主定义。运行时检测到首个整板故障时 MUST 先标记 ``faulted``，再同步分发本板唯一一次 ``onDidError``。故障发生在两次推进之间时同样立即生效，不等待下一次 ``runUntil``。

故障后运行时停止向器件分发新的话题回调，停止后续正常执行步骤。context 拒绝继续发送输入、发布话题、改写代码等新增副作用。适配对象与资源保留到销毁，以便保留故障现场；初始化失败的清理是例外，见下文。

正在执行的 ``runUntil`` MUST 报告失败；已经故障的板再次调用 ``runUntil`` MUST 立即失败。若故障是在仿真到达目标时间后的 ``sync`` 中发生，时间保持在该目标位置，但本次推进仍然失败。

失败保留已经发生的仿真时间、状态修改和外部副作用。运行时 MUST NOT 回滚这些结果，也不得自动重试失败推进。器件自行启动的外部任务不会随故障标记自动暂停，其结果通过代次与 context 边界隔离。

批次的部分交付
------------------------------------------------

一次成功推进的输入注入、执行、清理和 ``sync`` 阶段由 :doc:`/channels` 定义；各器件 ``sync`` 按装配的 ``instances`` 顺序调用，但这一调用次序不构成跨器件的全局消息顺序承诺。

若 A 的 ``sync`` 成功，B 的 ``sync`` 抛错或显式上报：

#. A 已交付的消息和已经发布的话题保持有效。
#. B 在故障前已经产生的副作用保持有效。
#. 运行时停止后续 ``sync``，例如 C 的 ``sync`` 不再调用。
#. 尚未交付的输出 MUST NOT 在之后补发；本次调用不交付整次推进成功的结果。

故障不会把已交付部分变为可撤回事务，也不会把未交付部分移入下一次推进。当前 ``sync`` 上报后仍可正常返回；运行时 MUST 在进入下一处理步骤之前检查故障状态。

溢出的立即故障
------------------------------------------------

DDL 发送输出或 JavaScript 暂存输入时，若有效消息触发 ``Overflow.error``，运行时 MUST 立即使整板 ``faulted``，拒绝该条消息入队，并保留先前已经发生的状态。

JavaScript 的 ``try/catch`` 只能捕获发送操作的异常，不能解除故障状态。允许正常丢弃消息的端点应选择 ``drop_new`` 或 ``drop_oldest``；溢出策略与消息校验的先后关系见 :doc:`/channels`。

同步异常与异步上报
------------------------------------------------

框架捕获由它调用的工厂、``sync`` 和器件话题回调中的同步异常。脱离这些调用栈的异步错误，由器件 JavaScript 捕获并决定是自行处理还是调用 ``ctx.reportError(error)``；宿主监听器异常按下文的隔离规则处理。

在 ``ready`` 状态通过调用守卫并开始投递的合法 ``publish`` 中，器件监听器抛错、返回 thenable 或调用 ``reportError`` 时，运行时捕获并记录故障，先标记 ``faulted``，再同步分发唯一一次首故障 ``onDidError``，停止后续器件分发。该 ``publish`` 自身正常返回，不向发布者重抛已捕获的器件异常；嵌套 ``publish`` 同样遵守此规则。发布者当前 JavaScript 栈可继续返回；若发生在 ``sync`` 中，后续 ``sync`` 停止，当前 ``runUntil`` 仍失败。发布者自身的参数错误、失效调用或板已 ``faulted`` 后发起的新 ``publish`` 仍按守卫顺序抛错，与投递期间捕获器件异常区分。

板处于 ``ready`` 时，当前有效 context 调用 ``reportError``，运行时 MUST 立即记录主故障、标记 ``faulted`` 并封锁副作用，然后同步分发 ``onDidError``；上报调用自身正常返回。已故障但尚未销毁的 context 后续上报只产生附加 ``onDidDiagnostic``，不得再次分发 ``onDidError`` 或替换首故障。当前 JavaScript 栈可以正常返回；框架在返回后停止下一处理步骤。器件应在上报后直接返回，避免继续执行自行持有的外部操作。

若 ``sync`` 中调用 ``reportError`` 后返回，当前推进失败，后续 ``sync`` 不执行。预期的外部服务失败可以由器件自行处理，并非每个异步失败都必须上报为整板故障。

已经失效的 context 调用 ``reportError`` 仅产生过期诊断，正常返回；MUST NOT 改变新板或任何活动实例的故障状态。原板诊断事件分发仍有效时通过 ``onDidDiagnostic`` 报告；分发已经停止时通过 ``console.error`` 兜底。失效 context 的其他副作用调用仍被拒绝。代次与失效边界见 :doc:`/javascript/lifecycle`。

同步钩子返回 Promise 或其他 thenable 时，框架立即报告接口错误，不等待其完成。对于错误返回的 Promise，框架 MUST 接住其后续 rejection，避免由同一违约产生额外的未处理拒绝。``dispose`` 的 thenable 返回按清理失败处理。

初始化失败
------------------------------------------------

工厂尚未返回适配对象就失败时，运行时 MUST 清理该实例通过 context 获得的 SDK 资源，包括已经建立的订阅与 JIT 注册，并清理此前成功创建的适配对象。此清理不依赖失败工厂成功返回对象。

工厂通过 ``reportError`` 或错误返回 thenable 造成的初始化故障，同样使装配失败。初始化期间已经广播的话题保留为既成副作用。器件自行建立的外部资源，仍由器件在失败路径中负责释放。

本次装配不得返回可运行的半成品。清理本身失败时，继续执行下述尽力清理规则，并保留初始化的首个故障主因。

清理失败与恢复
------------------------------------------------

``faulted`` 的恢复方式是先 ``dispose`` 旧板，再通过 ``createBoard`` 创建新的板对象。新板从创建期初始状态开始；运行时不提供复位功能或运行快照。种子与随机流规则以 :doc:`/javascript/host` 和 :doc:`/execution/index` 为准。

销毁时，运行时 MUST 先使全板所有 context 失效，再按实例创建顺序的逆序清理。每个实例先调用已经返回的适配对象的 ``dispose``，再按 SDK 资源注册顺序的逆序清理该实例所属资源；失败工厂没有返回适配对象时，直接清理其资源。初始化失败也使用同一顺序。

运行时 MUST 尽力完成清理：某一步抛错或违反同步返回约束后，继续尝试剩余步骤，并汇总清理错误。每个步骤至多尝试一次（at most once），包括已经失败或提前释放的步骤。

无清理错误时，``dispose`` 正常返回，即使板此前已经 ``faulted``。有清理错误时抛出汇总的 ``SimulationError``：已有首故障保留为主因，清理错误按发生顺序加入 ``related``；没有既有故障时，以首个清理错误为主因，后续清理错误归入 ``related``。已经交付的诊断对象保持只读，不为追加清理记录而修改旧事件对象。

销毁结束时板 MUST 为 ``disposed``，即使本次调用因清理汇总而抛出 ``SimulationError``。此后再次 ``dispose`` 是无操作，不重试已经尝试的步骤。``time``、``status`` 及诊断信息仍可读取，板事件停止分发，其余板能力、context、端点与借用句柄失效。已交付只读值快照及自有字节副本仍可留存；完整生命周期见 :doc:`/javascript/lifecycle`。

错误报告
------------------------------------------------

``RuntimeDiagnostic`` 为只读诊断记录，其字段如下；准确类型及稳定 ``code`` 表以 :doc:`/javascript/host` 为主定义：

* ``code``：稳定、可由程序判断的错误码。
* ``message``：英文诊断消息。
* ``phase``：``library``、``assembly``、``initialize``、``execute``、``translate``、``sync``、``topic``、``dispose``、``host`` 或 ``report``。
* ``time``：发生时的仿真时间，板尚未创建时为 ``null``；时间单位见 :doc:`/execution/index`。
* 可选 ``instanceId``、``resource``、``path``、``source`` 与 ``cause``：关联实例、资源、结构路径、源码位置及原始原因；定位复用 :doc:`/ir/validation` 的 D2 ``SourceInfo`` 与 ``path`` 规则。
* ``related``：附加诊断的只读数组，无附加项时为空数组。

``SimulationError`` 携带主 ``RuntimeDiagnostic``；附加错误归入主诊断的 ``related``，首故障主因不被后续错误替换。``runUntil`` 内的故障既同步分发 ``onDidError``，也使当前调用抛出 ``SimulationError``；推进之外的首故障通过同一事件报告。后续 ``reportError`` 通过 ``onDidDiagnostic`` 报告附加诊断，清理错误保留为附加记录。

``onDidError`` 与 ``onDidDiagnostic`` 都是真实的 ``@mica-js/core/lifecycle`` ``Event<RuntimeDiagnostic>``，订阅返回 ``Disposable``。每板仅首故障分发一次 ``onDidError``；``onDidDiagnostic`` 用于附加、过期及非致命诊断。创建期尚无可交付板时直接抛出带完整诊断的 ``SimulationError``，不通过 ``options.onDiagnostic`` 或诊断中心回调交付。

运行时 MUST 包装需要隔离的宿主监听器：单个 ``onDidError`` 监听器异常转为非致命 ``onDidDiagnostic``，继续其余监听器；诊断监听器异常只交给 ``console.error``，不再递归产生诊断。核心 ``Emitter.fire`` 本身会因监听器异常中止，不能替代此隔离包装；本合同不修改 core 实现。

板事件及话题分发采用本轮注册快照：本轮新增订阅从下一次分发生效，已在快照中的订阅即使中途释放仍在本轮调用。整板故障后停止后续器件分发的要求优先于此快照规则。整个分发栈内禁止推进或销毁同一板，调用以 ``INVALID_CALL_STATE`` 的 ``SimulationError`` 拒绝；拒绝本身不使板故障。重入封锁按板隔离：板 A 的回调可以操作独立板 B，B 的调用仍须满足其自身守卫，不设全局锁。销毁后事件不再分发，旧异步上报通过 ``console.error`` 兜底并正常返回。

一致性核对
------------------------------------------------

下列场景应纳入 :doc:`/conformance`，它们是验收目标而非现有实现的测试结论：

* 工厂建立订阅与 JIT 注册后抛错：该实例所属资源与此前实例均得到清理。
* A 发布话题、B 同步失败：消息保留、C 不调用、未交付输出不补发。
* 输入 ``Overflow.error`` 被 ``catch`` 捕获：整板仍故障，后续推进立即失败。
* ``sync`` 上报后正常返回：当前推进失败，后续同步停止。
* 同步钩子返回 Promise：立即接口错误，后续 rejection 被接住。
* 一个释放步骤失败：先失效全部 context，再逆序尽力清理；调用抛出汇总错误后仍为 ``disposed``，再次销毁无操作。
* 旧 context 的异步结果晚到：副作用被拒绝，过期上报正常返回，不影响新板；事件停止后通过 ``console.error`` 兜底。
* 宿主监听器抛错：其他监听器继续，产生非致命诊断；诊断监听器再次抛错只调用 ``console.error``。
* 首故障事件分发时，监听器观察到 ``faulted``；后续上报只产生附加诊断，每板 ``onDidError`` 至多一次。
* 在事件或嵌套话题分发栈内推进或销毁同板：调用被拒绝；异常被宿主捕获时板不新增故障。独立板的合法操作不受该重入封锁影响。
