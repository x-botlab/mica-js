================================================
语句与控制流
================================================

语句将计算、资源更新与控制流组织为函数体或过程体。代码按所在路径执行；调度器只在实际挂起或入口结束等边界交出当前同步片段。

顺序执行与赋值
------------------------------------------------

局部声明、调用和赋值按源码顺序执行。可重赋值的 let 与 state 使用 ``=``，不提供复合赋值或自增、自减。引脚意图用 ``<-`` 整体替换：

.. code-block:: text

   let saved = count;
   count = saved + 1;
   probe.intent <- [];

state 赋值立即生效。引脚赋值更换该 pin 的当前意图；空意图释放该 pin 的支路，网络求解与采样发布发生在调度边界。意图提交和采样可见性见 :doc:`/electrical`。

const、函数参数、属性、derived、记录字段与 sample / bytes 字段均不可赋值。普通赋值的目标为可写名称，右侧与声明类型匹配；赋值不产生值，不能连续赋值。memory 的字节内容通过 :doc:`/memory` 的显式操作访问，不通过索引赋值隐式截断。

条件与选择
------------------------------------------------

``if`` 根据布尔条件选择一个分支，``else`` 给出另一条路径：

.. code-block:: text

   if enabled {
     count = count + 1;
   } else {
     count = 0;
   }

条件及各分支必须使用花括号；支持 ``else if``。match 只作为语句，被匹配值求值一次，按源码顺序选择匹配分支，完成后 MUST NOT 贯穿：

.. code-block:: text

   match mode {
     Mode.idle => { count = 0; }
     Mode.active => { count = count + 1; }
   }

模式为数值字面量（可带一元正负号）、字符串字面量、true、false、枚举成员、none 或兜底 ``_``。模式不执行函数，不提供解构或守卫。重复模式拒绝；正负零视为重复数值模式。兜底必须是最后一支。

match 必须穷尽。bool 和枚举可以列出全部值；可空类型还须覆盖 none。number、string 以及不能逐项列举的值类型需要 ``_``；bytes 不提供内容模式。只有兜底的 match 也可使用，但不产生新的模式能力。NaN 与 Infinity 不是数值字面量模式。

局部被匹配值在具体非空分支收窄；若前支已排除 none，后续 ``_`` 分支可按非空类型使用。match 本身不返回值；需要计算分支结果时使用外层 let 或三元表达式。

循环与返回
------------------------------------------------

``while condition { ... }`` 每轮先求 bool 条件；条件可产生所在上下文合法的同步效果，但不能挂起。``loop { ... }`` 无条件重复。``break;`` 跳出最近一层循环，``continue;`` 开始该循环的下一轮；在 while 中重新求条件。循环外使用两者静态拒绝。首版不提供 for 或带标签跳转。

循环本身不推进仿真时间，时间来自显式等待。局部声明每次执行重新初始化，循环外 let 可保存累计值。所有上下文实际执行的 while 条件求值与 loop 迭代开始均计入工作量预算，包括 pure fn 与创建期求值，见 :doc:`/execution/scheduling`。

``return;`` 结束无返回值函数或过程的当前一次运行。``return expression;`` 仅用于有返回值函数，交付与声明匹配的一个值。过程的结束不永久注销反应入口。函数返回后调用者继续，与跨调用栈的 redirect 不同。

return、break、continue、redirect 后继续追加同路径语句属于静态错误。if 或 match 全部分支终结时，外层路径也终结。没有可达 break 的 loop 不形成正常结束路径；while 不通过一般常量计算证明其必然进入或不结束。可能转向的辅助调用不自动终结正常路径。

等待
------------------------------------------------

过程可以显式等待时间或 input channel 输入。await 限于独立语句、const / let 初始化或可写名称赋值的完整右侧：

.. code-block:: text

   await ticks(period);
   const value = await incoming.receive();
   let next: number = 0;
   next = await incoming.receive();

接收结果类型由通道决定，也可使用 ``await incoming.receive();`` 丢弃结果。ticks 无返回值，不能用于初始化或赋值。有返回值的等待结果仍须匹配目标类型，不能写入只读名称。await 不能嵌入算术、实参、短路条件或 ``return`` 的右侧；普通 fn 中所有等待形式均拒绝。

等待期间，运行时保存恢复位置与所需局部值。若操作立即完成，过程继续当前同步片段；若实际挂起，其他就绪入口可以执行。恢复后已经完成的前缀不会再次执行。

等待的时间单位、合法范围与调度先后见 :doc:`/execution/index` 和 :doc:`/execution/scheduling`。到达推进终点时，JIT 的代码恢复规则由 :doc:`/jit/execution` 定义，不能据此推定所有 DDL 过程在终点都停止执行。

``await ticks(0);`` 显式结束当前片段，在同一仿真时刻排队恢复。恢复前已完成该边界的电气求解与采样发布，但其他反应仍可能继续改变网络；它不是全局电气稳定等待。JIT 的 elapse(0) 不挂起，见 :doc:`/execution/scheduling`。

断言
------------------------------------------------

``assert condition;`` 检查 bool 条件，``assert condition, message;`` 另外提供 string 消息：

.. code-block:: text

   assert count >= 0, "expected a nonnegative count";

条件为真时继续，消息不求值；条件为假时才计算消息并报告失败。消息表达式接受所在上下文的类型与效果检查。pure fn 也可断言，创建期 assert 失败阻止实例创建；执行期失败遵守 :doc:`/errors`，没有模型内捕获、重试或回滚。

JIT 控制转向
------------------------------------------------

``redirect`` 是内置控制操作，在已绑定 JIT 入口的上下文中更新绑定位置、终止当前路径，并由调度器接管指定延时：

.. code-block:: text

   redirect(target, delay: duration);
   redirect(target);

``target`` 是位置参数，值为有限 number；``delay`` 是可选命名参数，省略时为零，合法性遵守 :doc:`/execution/index` 的非负时长规则。这是专用控制语法，不将位置和命名实参混用扩展到普通函数调用。

控制转向可以跨过嵌套同步函数的返回层。已经发生的状态修改保留，未执行的后缀与其正常耗时被跳过。

直接给绑定位置状态赋值只更新值并继续当前路径，即使发生在边界钩子中也是如此。它与 ``redirect`` 的区别是控制效果，而非目标数值是否发生变化。完整行为见 :doc:`/jit/interrupts`。

检查要点
------------------------------------------------

* 分支只执行被选中的路径，match 不贯穿。
* 在实际等待前完成的资源效果，在恢复后不重放。
* 函数正常返回、位置状态赋值与 JIT 控制转向具有不同的后续路径。
* 等待不是隐含事务边界，已经生效的资源修改遵守 :doc:`/execution/sharing` 与 :doc:`/errors`。
