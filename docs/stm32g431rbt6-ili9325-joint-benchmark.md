# STM32G431RBT6 + ILI9325 联合仿真基准记录

- 日期：2026-11-15
- 测试基线：`a50b345`（本次 benchmark 改动前的 HEAD）
- 测试对象：`examples/ili9325/test/fixtures/HAL_06_LCD.bin`
- 基准入口：`examples/ili9325/bench/joint-perf.test.ts`
- 联合板夹具：`examples/ili9325/test/joint-harness.ts`
- 运行环境：Linux x64、Node.js 24.20.0、Vitest 5.0.5

## 1. 目的

验证 STM32G431RBT6 与 ILI9325 不只是完成初始化寄存器写入，还能在真实 Keil 固件控制下持续写入
GRAM 并通过 `framebuffer` 话题发布。基准从复位推进到 **440 ms**，因此覆盖 220 ms 以上窗口、
多个 `HAL_Delay`、LCD 初始化和首帧之后的持续绘图。

## 2. 板级配置

- MCU：STM32G431RBT6，`clockFrequency = 80 MHz`
- LCD：ILI9325，`refreshRate = 60`
- 执行模式：默认 `throughput`（直接 JIT 后端）
- 数据总线：`PC0`–`PC15` → `D0`–`D15`
- 控制线：`PB5`→`WR`、`PB8`→`RS`、`PB9`→`CS`、`PA8`→`RD`
- `RST` 接 `VDD`，`VSS`/`VDD` 网络与参考板一致

全部实例、电气网络、适配器与话题发布均走真实 `createBoard`，没有替身器件。

## 3. 测量口径

| 维度       | 取值                                                               |
| ---------- | ------------------------------------------------------------------ |
| 仿真区间   | 0 → 440 ms                                                         |
| 时间量子   | 200 µs                                                             |
| 轮次       | 3 轮，每轮创建新板                                                 |
| 主指标     | 进程 CPU 时间，三轮取最小值                                        |
| 辅助指标   | 墙钟、实时倍率、帧数、发布像素数、GRAM 非零像素数、Direct JIT 统计 |
| 模块预热   | 先创建并释放一块空运行板，预热 DDL 编译与模块装载                  |
| 冷启动定义 | 第一轮建板并执行 0 → 200 µs；同时承担模块级 Thumb 块缓存冷启动     |

窗口划分：

- 冷启动：0 → 200 µs
- 活跃窗口：200 µs → 220 ms
- 后段窗口：220 → 440 ms
- 总窗口：0 → 440 ms

时间量子不能大于 SysTick 周期（本固件约 200 µs）。本固件当前运行路径下，使用 5 ms 等大切片
会少计 `uwTick`，使固件错误地停在延时循环。基准因此以 200 µs 步长推进。

复现命令：

```bash
cd examples/ili9325
./node_modules/.bin/vitest run --config vitest.perf.config.ts bench/joint-perf.test.ts
```

每次运行的逐轮 JSON 读数追加写入 `examples/ili9325/bench/results.jsonl`。该文件是本地测量日志，
不进入版本库。

## 4. 正确性断言

benchmark 在计时之外同时校验：

1. 板状态保持 `ready`，`errors` 与 `faults` 为空；
2. 200 µs 时尚未发布帧；
3. 220 ms 时至少发布 1 帧；
4. 440 ms 时帧数多于 220 ms；
5. 每个 `framebuffer` 载荷的宽高与像素体长度一致；
6. 每个发布帧与发布瞬间抓取的 GRAM 快照逐像素一致；
7. 最终 GRAM 含非零像素，发布帧含非零像素。

这些断言证明数据确实经过「MCU GPIO → 电气网络 → ILI9325 总线锁存 → GRAM → 合帧发布」链路。

## 5. 三轮原始读数

CPU 与墙钟单位均为 ms。实时倍率 = 仿真时间 / 对应 CPU 时间。

| 轮次 | 冷启动 CPU | 活跃 CPU | 后段 CPU | 总 CPU | 总墙钟 | 活跃倍率 | 后段倍率 | 总倍率 |
| ---- | ---------: | -------: | -------: | -----: | -----: | -------: | -------: | -----: |
| 1    |   4366.153 | 1428.569 |  211.803 | 6006.5 | 3819.9 |    0.154 |    1.039 |  0.073 |
| 2    |    324.808 |  568.506 |  248.097 | 1141.4 |  662.8 |    0.387 |    0.887 |  0.385 |
| 3    |    214.877 |  410.875 |  169.419 |  795.2 |  508.9 |    0.535 |    1.299 |  0.553 |

第一轮包含模块级 Thumb 块缓存冷启动，CPU 时间显著高于后续轮次。三轮中的最好值：

| 窗口                   | 仿真时间 | CPU 最好值 | 实时倍率 |
| ---------------------- | -------- | ---------: | -------: |
| 0 → 200 µs 冷启动      | 200 µs   |     215 ms |        — |
| 200 µs → 220 ms        | 219.8 ms |     411 ms |   0.535× |
| 220 → 440 ms           | 220 ms   |     169 ms |   1.299× |
| 0 → 440 ms（含冷启动） | 440 ms   |     795 ms |   0.553× |

完整 440 ms 墙钟最好值为 509 ms。进程 CPU 时间包含 V8 并发编译线程，因此可能高于墙钟。

## 6. 帧与 GRAM 数据

三轮的帧数和像素统计一致：

| 指标                       | 结果 |
| -------------------------- | ---: |
| 220 ms 时已发布帧数        |    4 |
| 440 ms 时累计发布帧数      |   10 |
| 累计发布像素               |  132 |
| 发布像素中的非零像素       |  131 |
| `framebuffer` 载荷总字节数 |  344 |
| 最终 GRAM 非零像素         |  135 |

本次固件绘制的是窄条文字/图形，不是整屏填充，因此这些数据表示真实帧发布流水线，不用来计算
整屏像素吞吐。每个发布帧都与发布瞬间的 GRAM 快照逐像素一致。

## 9. 限制

- 读数来自共享 Linux x64 宿主，绝对时间随 Node/V8、CPU 负载与宿主状态变化；只用于同机前后对照。
- 活跃窗口包含 LCD 初始化和前 4 帧，不是纯稳态渲染窗口。
- 当前固件只生成稀疏窄条帧，不能据此推导整屏 `px/s` 或帧率。
- benchmark 只测默认 `throughput`，未提供同一联合场景的 `precise` 对照。
