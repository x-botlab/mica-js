## 1. 目的

验证 STM32G431RBT6 与 ILI9325 不只是完成初始化寄存器写入，还能在真实 Keil 固件控制下持续写入
GRAM 并通过 `framebuffer` 话题发布。基准从复位推进到 **440 ms**，因此覆盖 220 ms 以上窗口、
多个 `HAL_Delay`、LCD 初始化和首帧之后的持续绘图。

## 2. 板级配置

- MCU：STM32G431RBT6，`clockFrequency = 80 MHz`
- LCD：ILI9325，`refreshRate = 60`
- 执行模式：默认 `throughput`（直接 JIT 后端）
- 数据总线：`PC0`–`PC15` → `D0`–`D15`
- 控制线：`PB5`→`WR`、`PB8`→`RS`、`PB9`→`CS`、`PA8`→`RD`
- `RST` 接 `VDD`，`VSS`/`VDD` 网络与参考板一致

全部实例、电气网络、适配器与话题发布均走真实 `createBoard`，没有替身器件。

## 3. 测量口径

| 维度       | 取值                                                               |
| ---------- | ------------------------------------------------------------------ |
| 仿真区间   | 0 → 440 ms                                                         |
| 时间量子   | 200 µs                                                             |
| 轮次       | 3 轮，每轮创建新板                                                 |
| 主指标     | 进程 CPU 时间，三轮取最小值                                        |
| 辅助指标   | 墙钟、实时倍率、帧数、发布像素数、GRAM 非零像素数、Direct JIT 统计 |
| 模块预热   | 先创建并释放一块空运行板，预热 DDL 编译与模块装载                  |
| 冷启动定义 | 第一轮建板并执行 0 → 200 µs；同时承担模块级 Thumb 块缓存冷启动     |

窗口划分：

- 冷启动：0 → 200 µs
- 活跃窗口：200 µs → 220 ms
- 后段窗口：220 → 440 ms
- 总窗口：0 → 440 ms

时间量子不能大于 SysTick 周期（本固件约 200 µs）。本固件当前运行路径下，使用 5 ms 等大切片
会少计 `uwTick`，使固件错误地停在延时循环。基准因此以 200 µs 步长推进。

复现命令：

```bash
cd examples/ili9325
./node_modules/.bin/vitest run --config vitest.perf.config.ts bench/joint-perf.test.ts
```

每次运行的逐轮 JSON 读数追加写入 `examples/ili9325/bench/results.jsonl`。该文件是本地测量日志，
不进入版本库。

## 4. 历史正确性断言

benchmark 在计时之外同时校验：

1. 板状态保持 `ready`，`errors` 与 `faults` 为空；
2. 200 µs 时尚未发布帧；
3. 220 ms 时至少发布 1 帧；
4. 440 ms 时帧数多于 220 ms；
5. 每个 `framebuffer` 载荷的宽高与像素体长度一致；
6. 最后一个发布帧与 adapter 发布时抓取的 GRAM 快照逐像素一致；
7. 最终 GRAM 含非零像素，发布帧含非零像素。

这些断言证明至少部分数据经过了该链路，不能证明每个 WR 周期都被锁存。
帧与快照来自同一份 GRAM，漏写可以同时缺失于两边；GRAM 快照还可能晚于模型复制帧体的时刻。

## 11. 修复后的完整工作量基准（2026-11-14）

基于 `297b03f` 的工作区修改，环境与板级配置保持一致。实际改变 pin intent 时，Direct
在下一次非零 `elapse` 开始前返回并发布，保留 prefix 时刻、局部值与续体；零时长路径在
指令结束时发布。同一指令内的多引脚更新仍在同一个边界求解。实例共用常驻数值状态银行，
解释器、reaction 与普通 process 的写入同步该银行；写回按脏位枚举，消除逐调用的全银行
读取和全写槽扫描。编译器同时降低变量压缩中的扫描与分配成本。

基准仍为三轮新板、200 µs 步长；逐 intent 的独立对账在计时轮次之外执行。

| 轮次 | 冷启动 CPU | 活跃 CPU | 后段 CPU |   总 CPU |   总墙钟 |
| ---- | ---------: | -------: | -------: | -------: | -------: |
| 1    |   4414.783 | 2954.254 | 1656.301 | 9025.338 | 6593.389 |
| 2    |    280.045 | 2146.075 | 1705.068 | 4131.188 | 3510.808 |
| 3    |    181.324 | 2100.745 | 1692.718 | 3974.787 | 3548.910 |

CPU 与墙钟单位为 ms。各窗口最好值：冷启动 **181.324 ms**，活跃 **2100.745 ms**，
后段 **1656.301 ms**，总 CPU **3974.787 ms**，总墙钟 **3510.808 ms**。对应活跃、
后段、总 CPU 实时倍率为 **0.105×、0.133×、0.111×**。首板仍承担模块级翻译冷启动。

三轮一致的完整工作量：

- WR sample 变化 **545,004**，等于 MCU 发出的 WR 电平变化；CS、RS 也逐变化对齐。
- MCU `0x22` 数据写与 LCD GRAM store 均为 **272,007**。
- 最终 GRAM **76,800** 个非零像素，与独立 MCU 总线 oracle 逐像素一致。
- 独立 oracle 识别到 **3 次 76,800 像素的蓝色清屏**。
- 220 ms 已发布 **5 帧**，440 ms 共 **10 帧**；累计矩形面积 **436,480 像素**，非零发布像素 **435,715**，载荷 **873,040 字节**。
- 每帧均与模型发送载荷一致；计时外对账还将每帧与发送时刻的独立总线 oracle 比较。60 Hz 合帧可以包含清屏后的绘图，因此不要求某一发布帧为纯蓝整屏。
- Direct 缓存 **311 块 / 72 shards**，**92 次编译、2,184,168 次调用、1,057 次回退**。发布前缀与恢复续体分别返回，调用次数不能直接与历史块尾诊断探针对比。

完整路径尚未实时。第 5 节的 795 ms 只处理了 136 次 GRAM store，不能将本节较大的耗时
称为同工作量性能回退。旧 `yield-on-intent` 探针约 2.3 s 的后段读数包含插桩且发布时刻
不同，也不用于计算正式修复的精确加速比。

验证：编译器 79 项、运行时 43 项、相关电气/MCU 86 项、真实适配器符合性 419 项、
生成 oracle 两个 domain 各 50 次、ILI9325 示例 19 项、正式基准及逐窗口诊断均通过；
相关包类型检查与构建通过。

## 12. 器件热路径优化后的完整工作量基准

本轮继续修改两个器件的生产实现：ILI9325 将像素写入、脏矩形维护和地址推进合并到
`writeData`，一次锁存内复用地址、窗口、模式和行宽的局部值；STM32 的 ODR 全部读写
统一使用既有 state，取消静态、动态和延迟写路径中的 `periph` 重复存储。配置寄存器
仍保留原后备存储。ODR 的旧后备字节不再是寄存器副本，调试应读取 `gpioOdrN` 状态。

按相同三轮新板、200 µs 量子、无逐 intent 探针计时，分阶段的各窗口最好值如下。
各阶段是分别运行的三轮，较小的增量可能受 V8 与宿主波动影响。

| LCD + MCU 优化     |    174.104 | 1660.495 | 1447.774 | 3282.373 |
