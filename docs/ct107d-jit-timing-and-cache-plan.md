## #309 时间准入与逐指令语义

### 宿主声明与编译候选

建议在 JIT 注册增加 `directTiming`。器件通过同步翻译的可选标记提供候选，返回值仍是普通 `BlockIR`。标记不随候选去执行，也不保存本次推进的时限。接口如下，均以皮秒为时间单位。

```ts
interface JitDirectTiming {
  readonly service?: { readonly elapsed: string; readonly deadline: string };
  readonly blocked?: string;
}

type JitLoopCandidate =
  | { readonly kind: 'spin' }
  | {
      readonly kind: 'decrement8';
      readonly memory: string;
      readonly address:
        | { readonly kind: 'constant'; readonly offset: number }
        | {
            readonly kind: 'maskedByte';
            readonly memory: string;
            readonly offset: number;
            readonly mask: number;
            readonly bits: number;
          };
    };

interface JitDirectTimingInput {
  readonly markDirectSpan?: (pc: number, instructionCount: number) => void;
  readonly markDirectLoop?: (pc: number, candidate: JitLoopCandidate) => void;
}
```

- `JitOptions.directTiming?: JitDirectTiming` 绑定本模型中的 number 状态和可选无参、返回 bool 的 `pure fn`。`blocked` 为真表示按通常边界执行。编译器沿调用图证明守卫为同步、确定、无抛错且只读，读取限于已绑定标量状态及证明范围内的内存字节。注册期检查字段、资源和签名。守卫证明失败时使用普通路径并记录原因。
- `JitTranslateInput` 扩展两个标记回调，生效区间与 `markDirectBodyShareable` 一致。`markDirectSpan` 选择从返回块指定 PC 开始、含最后一条终结写的连续 `2–8` 条指令。前缀各条 `nextPc` 必须等于下一条 PC，终结写及各后续 PC 仍保留普通入口。`markDirectLoop` 指向一个自回跳候选。同一 PC 的合块和折叠标记互斥。编译器从绑定后的规范 IR 证明时长、读写和控制流，标记只缩小搜索范围。错误、重复或无法证明的标记按条目拒绝，普通 IR 继续可执行。
- 吞吐模式、主代码内存和当前单 JIT Direct 准入条件成立时消费标记。`precise`、多 JIT 公平调度、轮询、附属代码或暂不能直编的入口依照原路径。已有 `translate`、`codeMetadata` 与 `delays` 调用形式可继续使用。派生候选随来源内存、版本、辅助函数表和关联条目的身份保存。同 PC 被后续翻译替换时，撤销所有引用旧条目的合块和循环计划。

### 执行上限

在已完成边界检查、第一条指令尚未写 PC 或产生效果时，取 Direct 帧当前时间 `t`。以 `min(runUntil 终点, 下一模型事件时刻, 当前已设的执行段终点)` 为宿主上限。`2.9.0` 的 `runDirect` 传递前两项，首版继续复用同一入口。执行段有额外调度上限时将其纳入，未设置时视为 `Infinity`。若当前有待处理的队列、发布或恢复，当前合块守卫直接失配，交回原有路径。

`service.deadline` 与 `service.elapsed` 是相对同一上次结算点的时刻和已累积量。期限为 `0` 时视为当前无定时服务。正期限的绝对上限为 `t + max(0, deadline - elapsed)`，计算时将结果夹到宿主上限，避免时间超出 `MAX_TIME`。两个有效状态值须为非负安全整数。非法值、守卫为真、观察者掩码冲突、入口钩子未证明可省略、失效代际或发布状态未清理时，执行当前 PC 的普通指令。定时状态读取用当前 Direct 状态槽，和帧时间同一检查点。以上计算只在候选入口执行。

记两种上限的最小值为 `H`。合块要求 `t + ΣdurationPs < H`，循环只折叠在 `H` 前完整完成的轮次。使用剩余预算做减法比较，和调度器的独占终点一致。`H` 只控制优化准入，普通指令仍使用实际宿主截止和自身的服务/结算逻辑。`T` 恰在终结指令开始时，普通路径先处理该时刻模型事件，且 `runUntil(T)` 返回前没有终结写。`T` 恰在终结指令尾部时，已开始的前缀正常可见，其到期后的代码留到下一次推进。 [调度终点和同刻顺序](./spec/execution/scheduling.rst)、[吞吐模式](./spec/jit/throughput.rst)

### 纯前缀与终结写

1. 器件收集连续定长、固定时长的顺序指令，首版沿用现有 8 条/16 字节上限。每个成员用 `translateInstruction` 的原逻辑生成，禁止以一条含两套分支的 IR 表达退化路径。CT107D 的候选以融合后的 IR 为准，同步辅助函数、`fusedSeq`、端口镜像和观察依赖都参与判断。
2. 编译器复用已有 `Instruction` 发射的前缀和后缀。对前缀逐条提取唯一的正整数常量 `elapse`，并用 `analysis.ts` 的操作效果、调用图和常量传播证明无可观察中间发布、无控制转向、无异常，内存访问有范围证明。允许只影响 CPU 私有标量或已验证的 RAM 地址，且写入不会使入口守卫在跨度内失效。前缀排除采样、引脚写、消息、随机数、时钟读取、动态 SFR/`MOVX`、代码写入和不透明调用。安装时从依赖和实际写集合生成掩码，执行前检查观察者、钩子和等待者。失配时执行普通入口。
3. 编译器先保留逐指令 `nextPc` 与尾部资源更新，按 `F.time` 递增组合前缀，省去中间派发。单独消除可证明无观察且值语义相同的重复时间账。`accumulatePs` 与 `tickTailPs` 在无定时服务时的 `clockPs` 更新不同，按原有尾部顺序合成，遇到未知模式保留原更新。取消派发时不顺带改变 PC、定时值、IRQ 保护次数或尾部故障点。
4. 安装合块前，确认终结指令已有有效的普通 Direct 路由。到达它原本的起始时刻时，把帧交给同一个入口，保持提交、`publishCheckpoint`、电气求解、捕获先于反应体及异常冲刷。先覆盖普通固定时长的 GPIO/SFR 写。支持前置结算后，准入只需证明普通终结指令的耗时上界。若原入口请求 `0xfffd`，此时结束合块，由原调度器执行结算并重新进入终结指令。结算先于读旧值和写入，已完成前缀保留。终结体执行后按现有规则计算下一条的边界，设备期限与事件在下次准入时重新读取。
5. 准入失败只执行该逻辑 PC 的原指令，普通 Direct 可用时优先使用它，否则走通用体。失败按时间、调度、观察者、器件或形状分类。动态失配不设置 `directSkip`，也不把入口加入永久拒绝集。保留 span 内部 PC 的普通路由和既有代码恢复行为。

### `DJNZ Rn`、`SJMP $` 与忙等期限

候选从 8051 译码结果登记，编译器在规范 IR 中验证固定时长、真实自跳、退出条件、读写全集和调用效果。`decrement8` 仅接受 `r ← (r - 1) & 255` 和基于同一新值的自跳，附带的尾部时间账须能直接归纳。`maskedByte` 的内存地址为 `(selectorByte & mask) | bits`，绑定时穷举选择字节确认目标在计数内存范围内。8051 使用 `(PSW & 0x18) | Rn`；选择字节在折叠区间内稳定。`spin` 只接受无计数器的无副作用自跳及可归纳尾部。位轮询、依赖外部读取的分支、`DJNZ direct` 等走正常 IR。

- 设 `d` 为一轮时长，`H > t` 时 `Ktime = floor((H - t - 1) / d)`，否则为 `0`。`DJNZ` 的退出轮之前最多折叠 `Kdata = (r === 0 ? 256 : r) - 1` 轮。取 `k = min(Ktime, Kdata)`，`SJMP $` 取 `k = Ktime`。例如从 `r=0` 开始，折叠 255 次后 `r=1`，由原指令完成最后一次递减并退出。
- 若 `k > 0`，以标准脏位提交路径将计数器写为 `(r - k) & 255`，PC 保持环头，精确推进 `k*d`，并按原忙等尾部更新时间累积。对 CT107D 的节拍尾部，在定时服务活跃且未到期时 `clockPs += k*d`，未激活且无紧急服务时原尾部每轮清零。只有 `IRQ_HOLD=0`、`IRQ_DIRTY=0`、无 UART 唤醒/T0 边沿/IAP 待处理且写目标无相关观察时，首版才折叠。保护窗口处于倒计时的轮次交给原指令处理，保持递减次数和 IRQ 准入。`SJMP $` 依然按原节拍推进时间驱动的外设。
- 折叠后回到普通的单轮入口处理边界轮，含到期服务和最后一次递减。若 `runUntil` 在该轮中间，按原指令在真正开始时写入 Rn/PC 并捕获 `resume`，到期后执行尾部一次。函数内的下一次普通入口不得立即再次递归进入同一折叠分支。借助 `H` 的严格上限，同刻事件或目标时刻仍由已有调度器解释。
- `JitDelay.pending` 的现有通用 paced 路径单独修正。服务激活且 `remaining = period - state` 时，可折叠预算为 `remaining > 0 ? floor((remaining - 1) / cycles) : 0`，与时长和退出预算取最小值，消除 `+1` 跨服务轮。折叠后的真实边界轮仍由原 IR 决定何时请求服务。CT117E-M4 的 SysTick、UART 累加器与共享体 delay 指纹列入回归。新 8051 候选经前述证明单独安装，已有 `JitDelay` 的 number 状态声明继续有效。

### 板侧接入与失效

`mica-devices` 在 `iap15f2k61s2/src/index.ts` 拆出逐条收集和标记逻辑，`kernel/tick.ts` 注册只读的安静条件，选择 `serviceDeadline` 和 `clockPs` 为上限来源。IRQ、UART1 wake、已捕获 T0、IAP 和任何必须逐条确认的情形走普通路径。CT107D 包装层对每条规范 IR 做 `fuseBlock`，宿主验证最终 IR 的标记和依赖。标记在板级缓存命中时也重新提交，候选工程开关与已有 `batchInstructions` 试点独立。

代码装载、IAP 编程或擦除经 `memoryChangedSlot` 撤销普通路由及引用该代码的优化计划。翻译过程记录取指源版本与各成员身份，提交前按同一快照验证。元数据与钩子守卫代际变化复用 `invalidateDirect`，旧帧只完成已开始的真实逻辑指令。纯前缀和折叠段在严格准入下原子完成，停在区间内部的调用由普通指令的续跑状态表示。 [代码写入与续跑合同](./spec/jit/code-memory.rst)、[指令执行合同](./spec/jit/execution.rst)

## #310 跨实例模板与两级执行

### 稳定现有键并延迟通用编译

1. 在真实板基准按板、JIT、逻辑 PC 记录五层计数。板级解码/翻译及 `fuseBlock`、函数表绑定、块绑定校验、通用 `body()`、Direct 指令体与分片分别记录查询、命中、实际构建和独占时间。装配单列，诊断在受控采集时开启。先验证缓存命中变化，避免只看工作区中 AST/IR 对象数量。
2. 在器件构建层为 `serviceFunctions` 和 CT107D 拼接的 `rtcDirectFunctions` 复用同一不可变声明数组，键为规范模型身份及真正改变函数 IR 的配置。以实际函数 IR 校验特化键，涵盖时钟、外围配置、融合和试点相关模式。`bindJitFunctions` 继续使用已有 `jitModels`，优先稳定 `DeviceIR` 身份。板级 `blockCache` 和 `fusedBlocks` 已存在，保留定宽字节、PC、代码跨度与模式隔离，修正命中后仍发生的重复解码、翻译或重写。仅在确认查键比原路径便宜后才移动查找位置。
3. 复用 `device-model` 的规范快照与成功校验缓存。在稳定的绑定模型下，以规范 `BlockIR` 对象为首选键共享不可变绑定计划，其中仅含逻辑 PC、`nextPc`、规范 Region、资源引用、传递依赖和编译准入信息。运行时为每个注册新建 PC 条目、代码版本、捕获资源槽与等待状态。首次选择通用后端时再查 `body(region)`，在设置 `nextPc` 或写资源之前完成编译并将成功结果放入已有通用体缓存。Direct 独占路径省去通用体预编。继续在翻译期完成 IR 和绑定校验，首次通用体编译失败沿用 `JIT_FAILED` 与 `translate` 的错误包装。
4. 若同结构函数/块经板侧优化仍频繁以新对象返回，在已校验不可变快照上对布局、函数表及 IR 做缓存摘要，命中后用完整结构相等确认。对象身份命中保持常数开销。比较保留类型、操作及声明顺序、函数传递依赖、字节内容、`Object.is` 数字语义和源码位置。失败绑定继续走规范校验器，避免把一个实例的诊断及来源带到另一个实例。

### 缓存身份与隔离

| 层               | 缓存身份与内容                                                                                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 器件翻译         | 生成器 ABI、模型布局、功能与时钟、逻辑 PC、跨度和全部影响 IR 的代码字节。独立虚拟入口以服务角色与同一配置命名。常量池、前置上下文或全固件预分析是翻译输入时，一并纳入依赖 |
| 绑定计划与通用体 | 引擎/IR ABI、规范模型和函数环境、块与源位置；跨对象按结构确认。惰性通用体只捕获不可变 IR 常量，宿主、参数、绑定句柄和生成器每次执行传入值属于当前实例                     |
| Direct 指令模板  | 引擎 ABI、指令的规范 IR 与逻辑 `pc`/`nextPc`、代码依赖身份，外加状态/内存/引脚槽及其类型、静态入口守卫、辅助函数绑定、宿主能力、延时和优化模式                            |
| Direct 分片工厂  | 同一 Direct 上下文、分片预算及规范排序后的入口模板与路由形状。可复用产物为未绑定的生成工厂、续跑布局和常量配方，执行帧及派发表由每个会话单独创建                          |

板侧继续为 `blockCache` 提供完整字节键。需要按内容复用 Direct 产物的注册，建议增加 `JitOptions.translationIdentity?: { readonly abi: string; readonly configuration: string }`，并在本次同步翻译用 `markTranslationDependencies?(ranges: readonly { readonly offset: number; readonly length: number }[]): void` 报告影响结果的借用视图物理字节区间。`abi` 标明生成器或融合规则版本，`configuration` 包含特化和时钟。每次翻译都登记，包括板级缓存命中。运行时在校验后确认偏移和长度为安全整数，覆盖范围有效，并对这些区间做有限拷贝或可确认字节相等的比较。工件只保留快照或内容身份，借用视图随翻译结束释放。空区间只用于确知与代码无关的虚拟入口，键含其逻辑 PC 和角色。跨视图、无标记或依赖范围不可界定时，保留已校验对象身份快路径及本地 Direct 会话。内容命中须通过规范 IR 和字节的结构确认，哈希只筛选候选。

`codeVersion` 属于实例代码内存，保护可进入的本地 PC 路由、晋升状态、轮询和忙等元数据。同一版本号在不同实例中并不标识相同代码。写入后失效该实例相关路由及编译选择，另一个实例继续使用它自己的旧版本。当前实例重新翻译并按新代码计算键后，可以再次命中确实等价的不可变产物。重新装载、销毁、容量淘汰或布局/ABI 变化各自按所属层处理，只有正在恢复的旧指令持有旧执行内容到下一有效边界。用 [宿主共享合同](./spec/execution/sharing.rst) 约束状态、RAM、寄存器银行、观察者掩码、钩子读集、时间、待处理事件、`due`、`resume` 和命中计数的实例隔离。

### Direct 模板与分片的实现

- 在 `compiler` 将 `Instruction` 的共享内容拆成不可变发射结果与会话内绑定。发射结果保存前缀/后缀、局部槽规格、效果和常量配方。常量及可静态绑定的调用用模板局部索引，绑定时安装各自的辅助函数、数据及电阻槽。会话内的逻辑 PC、常量值、分片所有者和可变 `resumeId` 留在本地。缓存不保存 `Instruction` 可变对象或 `DirectJitFrame`。
- 扩展 `compileDirectJit` 的编译器级会话接口，以 `createArtifactCache()` 创建有界的 opaque cache，`createSession(binding, localCache?, artifactCache?)` 传入。现有 `createCache()` 仍供单会话拥有。模板查找在发射前执行，分片查找在生成源码前按完整入口顺序和签名执行。内部生成相同排序的局部 case/续跑号，会话通过独立的 `local → session resumeId` 参数表绑定；恢复表将全局 ID 指向同一分片的局部续跑函数。`C`、辅助函数、守卫掩码及运行时宿主各自绑定。固定派发器继续追加已验证的路由并执行已有检查点。
- 先用现有未绑定 `residentShardFactory` 验证形状重用，再铺开模板与分片配方缓存。分片序列不同可命中单体模板，继续按既有预算装片。同一新批次局部修改只影响其开放尾片或对应分片。#308 共享体和 #309 合块/折叠具有额外的资格和续跑形状，首版仍按会话发射这些特例，普通入口走跨实例复用。
- 工件缓存作用于同一运行环境中的 compiler 模块实例，运行时可向多个板的会话传入同一个缓存。对强引用工件采用 LRU，起点复用现有分片工厂的 `128` 项、`4 Mi` 源码字符总预算及 `64 Ki` 单项入口上限，保留的键和常量配方也计入预算，并用 RSS 复核。弱键身份缓存随规范对象回收。超预算通过本地编译，淘汰只解除工件的缓存持有，活动会话及续体保持引用。记录模板、分片工厂和已实际绑定的次数，杜绝将同一个底层命中计两次。

### 两级执行与晋升

建议 `JitOptions.directTier?: { readonly promoteAfter: number }`。省略沿用 `2.9.0` 的即时 Direct 策略。设置后仅在 `throughput` 和已有 Direct 准入条件内生效。每个本地路由按 `{pc, codeVersion, IR 身份及绑定上下文}` 记录成功完成的指令次数。首个实验值取 `8`，在 `4/8/16/32` 和当前即时路径之间测量选择。该值按正安全整数校验，试验与观测结果决定生产使用的阈值。

| 当前状态 | 条件及动作                                                                                                       | 后继状态                                  |
| -------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 未翻译   | 调用翻译、校验并查询绑定计划，只提交成功结果                                                                     | 通用                                      |
| 通用     | 走共享通用体，有真实完成且符合晋升条件时计数，暂停、元数据待刷新、普通轮询和已失效后缀均不增加晋升计数           | 未达阈值留在通用，达到阈值标为待晋升      |
| 待晋升   | 下一次同一 PC 完成边界和准入检查，优先复用已存在的 Direct 工件。需要编译时同步增量提交该入口，无需扫描整张翻译表 | 已装入 Direct，或因静态不支持回到通用     |
| Direct   | 按固定派发器执行。遇到仍属通用级或守卫失配的 PC，按既有边界退出，使用实际 PC 继续                                | Direct 路由保留，当前通用指令按其状态推进 |
| 任意状态 | 字节写入、IR 重叠替换或编译上下文变化，先撤销旧路由和晋升状态。暂停的真实指令先完成旧后缀                        | 新版本按正常入口重新选择                  |

高频虚拟服务入口优先做共享通用函数和完整模板命中验证。虚拟 `SERVICE`、`SETTLE` 的身份使用独立角色；IAP 改写服务走既有写代码屏障。每个边界先处理当前恢复、钩子、轮询和发布，再尝试晋升。动态失配与尚未晋升单列，静态拒绝缓存到该入口身份失效。计数饱和，折叠跳过的轮次单列，避免用并未执行的 PC 把候选提升为热点。多 JIT 共板时复用通用模板，Direct 执行仍受本版单 JIT 准入限制。首次陌生 HEX 仍可能需要构建通用体，因此冷段同时报告避免的 Direct 编译和实际新增的通用执行。若剩余热点是大量一次性通用发射，再用归因数据决定是否引入按 opcode 形状参数化的模板。
