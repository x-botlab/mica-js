## #277 按需编译与增量派发

### 编译产物与缓存

为模拟器增加编译会话入口，沿用 `Instruction` 发射器、常驻 step/resume 分片、源代码预算和同步辅助函数绑定。保留 `compileDirectJit(instructions, binding, cache?)` 的公开返回结构、快照语义和调用方测试，新会话提供按批提交增量及固定 `run` 入口。会话在单个 JIT 注册内使用，其编译上下文由稳定槽布局、绑定模型、同步函数表、宿主能力及静态入口屏障代际确定。

| 对象     | 所有者   | 身份与职责                                                                                                                                                |
| -------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 翻译缓存 | 模拟器   | `pc → JitInstruction`。保存绑定校验后的不可变 IR、`nextPc`、逻辑区域、取指源内存和翻译时版本。通用 `execute` 首次走通用路径时再用现有 `body(region)` 获取 |
| 编译状态 | 编译会话 | 逻辑 PC 处于待编译、可派发、已拒绝之一。拒绝结果对应当前 IR、延时描述和编译上下文，相关输入更新后重新评估                                                 |
| 派发路由 | 编译会话 | `pc → 分片入口`。派发器在分片交接时查表，分片内保留现有 `switch`、顺序落入和控制流链。已开始指令由原分片的续跑函数完成                                    |
| 活动帧   | 模拟器   | 引用实例的资源银行，每个 JIT 独立保存脏位、局部槽、`due` 与 `resume`。局部槽在安装更大分片前按需扩容。挂起时持有所属分片的续跑函数及其闭包                |

- `runJit` 先完成现有调度准入、元数据、边界钩子和显式轮询，再按处理后的 PC 定位入口。钩子改写 PC 后按最终位置确定当前元数据和版本。Direct 遇到未派发 PC 时返回内部结果，交还调度器处理该 PC 的边界。调度器在当前指令尚未开始的前提下执行必要的翻译，并用验证后的结果重新尝试 Direct。该次边界已运行的钩子和轮询 `consume` 只执行一次。自动轮询、钩子已处理、多 JIT 或 Direct 拒绝时进入通用路径。Direct 准入覆盖主代码内存的所有窗口和回退到该内存的服务入口，要求条目也由该内存提供翻译输入。
- 翻译先完整校验，再原子提交 PC 条目。重复 PC 取块内首项，重叠翻译替换旧条目。记录翻译批次，首次需要其中一个入口时只处理该批新条目和它影响的分片。入口和单独出现在同一批次的后继依据绑定、轮询、延时及区域分别判定。
- 新条目按现有源码预算和 `DIRECT_SHARD_SIZE` 界限装入分片。新批可以并入满足预算的开放尾片，优先保留控制流链。封存后的分片在追加时原样复用。超预算单体沿用独立分片和冷分支提取。一次增量只更新新路由和实际改动的分片路由。固定派发器直接查表，移除随翻译增长的整表 `switch` 生成、全量资源汇总和增长步长重建。
- 重叠替换及代码派生元数据变更先撤销整个受影响分片的路由，再按需用它的仍有效条目与新条目重新装片。这样分片内跳转和 `resume` 后的围栏都只会看到有效入口。待装片项按新快照安装，提交异常由原有错误包装处理，已撤销路由保持失效。
- 发射时给每个指令体分配局部常量表。新分片只引用所属条目的常量表，无常量的 case 省去装载。提取的冷分支显式接收相同常量表。同步辅助函数每个上下文绑定一次，指令常量表保存其函数引用。电阻快速缓存的索引按编译上下文分配，活动帧在停稳后切换对应缓存。撤销路由后，分片的常量与函数随最后一个路由或续跑引用释放。
- 保留板包翻译回调更新 `delays` 的用法。在首次 Direct 准备、翻译提交或元数据刷新后，读取延时描述并按 PC 比较其值快照，包括 `counter`、`cycles` 和 `pending` 内容。只撤销有效描述变动的已编译入口所在分片。`codeMetadata` 仍采用现有区域刷新事务及主内存别名的一致刷新规则。快照比较遍历延时声明，增量装片遍历当前批次和受影响分片。

### 守卫、调度与恢复

- 继续使用 `DirectJitLayout` 和按 `slot >>> 5` 定位的订阅者位掩码。各分片共享同一布局和两个就地更新的遮罩。订阅增减只刷新遮罩并清除受其影响的 `directSkip`，观察者集合从新编译会话的静态键中移除。`beforeInstruction` 新发现状态或内存依赖时切换入口屏障代际，撤销旧编译入口，下一次需求触发重新编译。第一个实现按代际清理，事件发生频率由诊断报告验证。
- `directSkip` 绑定出错 PC 和当前入口有效性，用于防止同一条件下反复进入 Direct。译码或适用布局、代码版本、延时描述、守卫变化时允许重试。固定派发器区分未翻译、待编译、正常离开 Direct 和真实拒绝。前两个是装配请求，计为 `dispatchMisses`。真实拒绝沿用回退统计，同时独立报告所有通用指令的来源及数量。
- `run` 仍以推进终点和下一事件的最小值为截止。`time` 等于截止时留待下一次推进，保留零耗时、延时折叠、隔离循环围栏和重定向的语义。跨分片时保留脏位及待发布状态，继续执行前按现有围栏和时间条件准入。动态发布检查点先以 `frame.time` 提交效果和同步反应，再检查当前代际、有效路由、钩子、事件和截止。`finally` 在异常路径也提交已发生效果。空后缀的现有快速路径沿用相同的准入判断。
- Direct 退回调度器时按实测的写入和时间进展区分未开始和已有前缀。出现进展时只使用发布后的 PC 继续。挂起时固定原分片和恢复标识，保留局部槽与绝对到期时间。失效时允许当前指令按时完成其旧后缀一次，随后回到调度器选取新版本。内联发布回调即使发生在 `resume` 清零前后，也检查活动分片的代际，拒绝旧分片开始下一条指令。

### 写入失效与释放

在 `memoryChangedSlot` 统一处理代码存储的成功非空写入，经 `loadBytes`、通用写入或 Direct 脏位提交均走这里。沿用实例内存的 `codeVersion`。主内存写入一次撤销其所有窗口的翻译、派发和共享索引，并刷新各窗口的代码元数据。服务 PC 沿用主内存的失效范围。附属内存的写入按本内存清理缓存，并撤销以该内存借用视图为翻译输入的条目，包括翻译块跨区域时生成的条目。条目所属逻辑区域也参与失效判定。附属内存和服务 PC 的现有执行准入规则保留。

失效交换可进入的缓存代际，并标记正在执行或已挂起的旧帧仅完成当前指令。任何仅由该旧续跑持有的分片在恢复完成或取消时释放。`stop` 保留注册和代码装载权限，显式释放注册或销毁板时同步清理缓存、等待订阅及挂起引用。每条写入路径按现有合同覆盖相同字节写入、空写入及失败写入。

## #308 代码地址别名复用

### 诊断与器件接入

- 同一个 `attachJit` 注册内，用实例存储身份、`codeVersion` 和 `pc - region.base` 对入口归组，记录各组的不同逻辑 PC。涉及 Thumb 指令对齐、窗口映射或取指地址归一化时，由器件翻译器处理。共享候选排除服务 PC、跨借用视图的取指、未获 Direct 准入的入口。无共享模式也输出候选、译码次数及归属于候选的累计生成字节。沿用 `Board.jits` 的诊断读法。在项目测试台隐藏底层板的情况下，由测试专用的 simulator 构建将相同的快照输出给探针，公开 `Testbench` 接口继续用于行为断言。
- #308 引用提交 `0d6709d` 的 CT117E-M4 翻译器通过板级取指地址折算支持两个 Flash 窗口，`attachJit` 仍只绑定主 `code`。先在器件侧用 `codeRegions` 将 `0x08000000` 声明为同一 Flash 的附加窗口，原隐式窗口从 `0x00000000` 开始。用 `codeBase` 和物理偏移读取 `input.code`，PC 继续用于 IR 和板级缓存。显式映射、Flash 版本处理和诊断在 A/B 两侧都启用。用 `codeVersion` 使板级译码缓存和代码派生分析同时失效，重新生成内容指纹、寄存器事实、IT 上下文及受写入影响的轮询或延时信息。 [板级缓存实现](https://github.com/x-botlab/mica-devices/blob/0d6709dd82f72b401615ce5a2b0559f38b2bc665/boards/ct117e-m4/src/mcu.ts#L859)
- 建议给 `JitTranslateInput` 增加可选成员 `readonly markDirectBodyShareable?: (pc: number, byteLength: number) => void`。启用候选诊断或复用时，回调在同步翻译期间有效。`pc` 对应返回块的一个指令入口，`byteLength` 是从该入口连续取指的实际字节数，合批时取合批总长度。器件在板级缓存命中时也报告。模拟器在块绑定校验后关联标记，检查入口唯一、偏移与长度为安全整数、长度为正且范围完全位于本次借用的区域。缺少或无效标记的翻译按普通入口执行，诊断记录原因。API 确定后同步宿主类型合同、Builder 文档和器件 SDK 的类型导出。 [宿主类型合同](./spec/contracts/host.d.ts)、[Builder 翻译边界](./spec/ir/builder.rst)

### 共享判定与执行

首版使用显式标记加等价 IR 验证。把逻辑 PC 和隐式 `nextPc` 写入从共享体的固定源码移到路由参数。IR 中已经具现的地址、数据和分支目标仍按普通值比较与执行。器件继续独立翻译两个窗口。

| 检查项     | 复用条件                                                                                                                                                              |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 取指       | 两个入口都明确标记，位于同注册的不同逻辑窗口，存储身份、代际、物理偏移和标记长度相同                                                                                  |
| 编译上下文 | 绑定模型、状态/内存/引脚槽、PC 槽、函数声明与传递调用依赖、静态入口屏障和宿主能力相同。函数或资源绑定发生变化时切换编译上下文                                         |
| 指令行为   | 校验后的 IR 操作、顺序、类型、数字及其他常量、资源名称和嵌套区域结构相等。以 `Object.is` 保留数字语义。首版保守比较源码位置信息，指纹只用于分桶，命中后做结构比较确认 |
| 路径特征   | 各自通过 Direct 准入，具有相同的有效延时描述、发布和恢复形状。当前订阅者掩码跟随活动帧，始终在实际写入时生效                                                          |

1. 第一个通过准入的标记候选使用可共享的单体分片，编译出接收帧、截止和该入口 `nextPc` 的 step 函数，以及需要时的 resume 函数。普通入口沿用增量分片。第二个等价候选只添加独立路由，该路由保存自己的逻辑 `pc`、`nextPc`、版本和恢复归属。两条路由共用同一函数对象及闭包，步进返回后按真实 PC 继续派发。
2. step 在现有顺序点写入本入口的 `nextPc`，再执行等价 IR。恢复使用原路由保存的函数与局部值，结束后再解析实际 PC。任何仅由某一个窗口导致差异的 PC 相对寻址、分支、LR、IT 状态或异常帧都保留其各自的 IR。可共享的例子是两个窗口在同一偏移执行相同的通用寄存器加法，且顺序后继仅通过隐式 PC 写入。相对地址被翻译为不同常量的指令使用各自的专用体。诊断输出这些拒绝分类，为后续评估由翻译器显式表达重定位参数提供依据。
3. 共享索引只包含当前可进入版本。Flash 编程或擦除走 #277 的失效路径，清理两个窗口对旧体的引用。翻译重叠时移除被替换入口的共享引用，同版本的其他等价入口可以继续使用共享体。挂起期间保持主动续跑的旧引用，按原窗口语义完成后，再从新版本重新派发。

### 性能 A/B

每次固定 Node 24/V8 版本、板包与固件 SHA-256、输入、推进步长、执行模式、构建入口和机器。A/B 交错启动独立进程，先做最小窗口，再扩大验证。冷启动记录至少五对样本的中位数和范围，同时保存原始样本。热执行测量先做一组基线对基线，候选在同窗口内的中位耗时须落在该基线重复测量范围内。若机器噪声或热态入口分布改变，报告原始分布并重测。
