# 器件 IR 核心规范

- Start Date: 2026-10-20
- Reference Issues: [#26](https://github.com/x-botlab/mica-js/issues/26)
- Implementation PR: [#64](https://github.com/x-botlab/mica-js/pull/64)

本文描述器件执行 IR 的核心语义与最低校验要求。规范性用语：「必须」「不得」为强制要求，「可以」表示保持可观察行为的实现自由。作者层简写、可读输出与规范化核心 IR 共享同一套执行语义。

## 范围

核心覆盖：

- 标量类型、SSA、多结果、基本块、静态函数调用。
- 显式状态字段、固定数组与字节存储区。
- 数值运算、虚拟时间访问、普通事件与可复用整数 ID。
- 公共控制阶段与生命周期入口的通用执行边界。
- 静态资源引用、显式领域指令的链接合同、Provider、故障、效果与等价性规则。

只使用核心指令的程序可以独立校验与执行；使用领域指令的程序按实际引用的资源与指令完成链接。

范围之外：通用堆、协程、通用联合、option、64 位整数、宿主裸指针、共享内存并发、递归与通用动态函数指针。领域能力通过明确的指令与受校验资源提供，普通 `call` 只调用 IR 函数。

## 程序、实例与静态引用

模块由以下声明组成：状态与资源声明；普通函数、普通事件入口、生命周期入口；入口与内核触发源的绑定；静态调用引用、Provider 声明与获准使用的显式内核指令及其资源引用。

实例创建时固定字段、数组元素类型、容量、静态资源与签名；工厂配置可以决定这些声明，不同实例的可变状态相互独立。

`state.x`、`ram`、`resource.input`、`tick`、`provider.code` 在静态引用位置表示资源、函数、入口或 Provider。可读写法用名称本身，局部 SSA 值写作 `%value`，基本块标签写作 `^block`。链接器按操作签名与符号类别解析静态名称；成功链接要求引用属于当前实例的授权范围。静态引用与普通标量分别表示，算术与数值转换只操作普通标量。普通事件 ID 是普通 `u32` 值，与静态引用不同。

作者层结构体统一展开为标量操作数、结果、入口参数或块参数；核心中不存在 `struct.make`、`struct.get` 或运行时结构体对象，调试元数据可以保留原字段名。

```ir
func scheduleNext(%deadline: f64) {
  %old = state.load counter
  %next = int.add %old, 1
  state.store counter, %next
  %id = event.at onValue, %deadline, %next
  jump ^done
^done:
  return
}
```

## 类型与常量

| 类型         | 值域或语义                                  |
| ------------ | ------------------------------------------- |
| `bool`       | `true`、`false`，无隐式真假值               |
| `u8/u16/u32` | 对应位宽无符号整数                          |
| `i8/i16/i32` | 对应位宽补码有符号整数                      |
| `f32/f64`    | IEEE 754 对应精度，允许 NaN、无穷大、正负零 |

- 时间使用 `f64` 表示整数皮秒，不设独立 time 类型；普通 `f64` 运算不自动执行时间校验，时间接口按[虚拟时间](./0001-virtual-time.md)校验。
- 事件 ID 使用 `u32`，`0` 表示没有事件。
- 首版不得要求 `u64`、`i64`、eventHandle 或 option 类型。

`const<T> literal -> T` 构造常量，整数必须在声明类型范围内（`const<u8> 300` 拒绝，不自动截断）；浮点字面量按目标精度舍入。需要精确保留数据位时使用 `const.bits<F> hexBits`（f32 为 32 位模式，f64 为 64 位模式）。

可读写法允许在普通操作数位置使用字面量（如 `int.add %value, 1`），类型由已声明操作数、资源类型、目标签名或显式结果类型唯一确定；存在歧义时作者必须显式给出类型。规范化核心中每个值与操作都具有确定类型，字面量简写展开为常量定义与引用。

字段、数组与字节区默认清零（bool 为 `false`，浮点为正零），可以显式提供合法初值；不存在可读取的未初始化值。芯片的未定义或随机上电行为必须由模型显式表达，随机性必须有明确输入或种子。

## 函数、SSA 与基本块

| 类别         | 触发方式                     | 普通返回值     |
| ------------ | ---------------------------- | -------------- |
| 普通入口     | 调度器、外部输入或已捕获事件 | 无             |
| 生命周期入口 | 内核公共控制阶段             | 无             |
| 普通函数     | 静态同步 `call`              | 零个或多个标量 |

所有签名静态固定，不允许变参。入口不得被当作任意同步回调调用，共用逻辑应提取为普通函数。`call` 不产生事件、不推进虚拟时间、不保存等待栈；普通调用图不得递归，基本块循环允许。

SSA 规则：

- 每个局部结果只定义一次并具有明确类型；操作可以产生零个、一个或多个独立命名的结果。
- 使用必须被定义支配；函数参数在整个函数内有效。
- 分支合流与循环通过块参数传值，没有隐式 phi 或可变局部变量。
- 类型转换必须显式，不存在数字类型间的隐式扩缩位。
- 状态可变，但只能通过存储操作访问。

每个基本块必须以终结指令结束，不允许 fallthrough，终结后不得再有指令。

| 终结指令                                 | 规则                                    |
| ---------------------------------------- | --------------------------------------- |
| `jump ^block(args...)`                   | 目标块存在，实参与块参数数量、类型一致  |
| `branch condition, ^yes, ^no`            | condition 必须为 `bool`，两条边各自校验 |
| `return values...`                       | 与函数返回签名一致，入口返回空列表      |
| `dispatch provider, key(...), args(...)` | 受限尾部派发，不增加同步调用栈          |
| `trap code`                              | 显式模型异常，code 为静态诊断标识       |

```ir
func countdown(%count: u32) -> u32 {
  jump ^loop(%count)
^loop(%remaining: u32):
  %done = int.cmp<u32,eq> %remaining, 0
  branch %done, ^exit(%remaining), ^step(%remaining)
^step(%current: u32):
  %next = int.sub %current, 1
  jump ^loop(%next)
^exit(%zero: u32):
  return %zero
}
```

`call function(args...)` 的目标必须可静态链接且属于同一实例执行上下文，不得同步执行另一器件实例的入口。

## 指令族

### 布尔与选择

`bool.not`（`bool -> bool`）、`bool.and/or/xor`（`bool, bool -> bool`）、`select<T>`（`bool, T, T -> T`）。`select` 只选择已计算好的操作数，不提供短路求值；带副作用或可能异常的条件计算必须走基本块分支。

### 整数

| 操作                   | 签名与语义                         |
| ---------------------- | ---------------------------------- |
| `int.add/sub/mul<I>`   | `I, I -> I`，按位宽回绕            |
| `int.div/rem<I>`       | `I, I -> I`，按有无符号规则解释    |
| `int.and/or/xor<I>`    | `I, I -> I`                        |
| `int.not<I>`           | `I -> I`，仅反转声明位宽内的位     |
| `int.shl/lshr<I>`      | `I, u32 -> I`                      |
| `int.ashr<I>`          | 有符号 `I, u32 -> I`               |
| `int.cmp<I,predicate>` | `eq/ne/lt/le/gt/ge`，结果为 `bool` |

- 有符号除法向零截断，余数与被除数同号或为零；商溢出回绕（`i8` 的 `-128 / -1` 得 `-128`，余数 `0`）。
- 整数除零、取余零产生模型异常；移位数不按位宽取模——移位数达到或超过位宽时，左移与逻辑右移得 `0`，算术右移得 `0` 或 `-1`。
- 普通整数运算不隐式更新 CPU 标志；`u32` 乘法的低 32 位必须精确，不能用宿主浮点乘积代替。

转换：`int.zext<S,D>`（补零扩位）、`int.sext<S,D>`（符号扩展）、`int.trunc<S,D>`（保留低位，不检查可容纳性）、`int.reinterpret<S,D>`（同位宽重解释有无符号）。不满足宽度或类型关系时必须静态拒绝，这些操作不能构造静态资源引用。

### 浮点与数值转换

| 操作                       | 签名与语义                       |
| -------------------------- | -------------------------------- |
| `float.add/sub/mul/div<F>` | `F, F -> F`                      |
| `float.fma<F>`             | `F, F, F -> F`，只做一次最终舍入 |
| `float.cmp<F,predicate>`   | `F, F -> bool`                   |
| `float.isNaN/isFinite<F>`  | `F -> bool`                      |

- 每条运算按声明精度、最近值且居中取偶数舍入；连续 f32 运算不得一直保留为 f64 后统一舍入。
- FMA 必须支持（允许精确软件实现）；普通 `mul` 后 `add` 保留两次舍入，不得隐式融合或做改变结果的不安全重排。
- 浮点除零遵循浮点规则，不采用整数除零异常。NaN 的有序比较与 `eq` 为 `false`、`ne` 为 `true`；正负零数值相等。
- 算术产生的 NaN 必须规范化（f32 `0x7FC00000`，f64 `0x7FF8000000000000`）；赋值、状态／数组／字节移动、传参、选择与按位重解释必须保留原始数据位。

转换操作：`convert.int_to_float<I,F>`（最近值居中取偶）、`convert.float_to_int<F,I>`（先向零截断再检查范围，NaN、无穷大或越界异常）、`convert.float<F,D>`（f32→f64 有限值精确，f64→f32 按目标精度舍入，NaN 规范化）、`bitcast<S,D>`（仅整数与浮点同宽重解释，首版允许 f32 与 u32/i32）。

### 状态、数组与字节区

| 操作                                                          | 签名                        |
| ------------------------------------------------------------- | --------------------------- |
| `state.load field` / `state.store field, value`               | `() -> T` / `T -> ()`       |
| `array.load array, index` / `array.store array, index, value` | `u32 -> T` / `u32, T -> ()` |
| `bytes.load<T,endian> region, offset`                         | `u32 -> T`                  |
| `bytes.store<T,endian> region, offset, value`                 | `u32, T -> ()`              |
| `bytes.copy dst, dstOffset, src, srcOffset, length`           | `u32, u32, u32 -> ()`       |

必须满足：

- 索引不隐式取模，偏移计算不得通过 `u32` 回绕绕过范围检查。
- 多字节访问必须指定 `little`/`big`；8 位访问没有字节序差异。多字节访问允许非对齐，先验证完整范围再读写。
- `bytes.copy` 先验证完整源／目标范围与目标可写性，再按源字节快照语义复制，允许重叠。
- 对只读资源执行普通 store/copy 写入是模型错误；客体 ROM 写入、总线错误与未映射访问由芯片模型表达。
- 单个批量操作的完整校验不等于整个入口是事务；此前合法效果不因后续异常回滚。
- 普通 store 只更新目标存储，不隐式执行其他资源效果或隐藏的缓存失效。
- 不同可变资源不别名；后端只读去重不能暴露额外身份。

字节 `T` 只能为整数或浮点，不直接编码 `bool` 或资源引用；时间值可按普通 `f64` 保存，字节存取本身不检查时间语义。

### 版本化资源更新

作为生成依赖的可变资源，其写入来源必须经过受确认的版本化更新路径，或模型中受校验的更新与失效路径；更新路径声明所修改的资源与范围，并在新内容实际可见的提交边界同步更新所涉版本单元。

| 操作                                                           | 静态操作数                 | 运行期参数      | 结果 |
| -------------------------------------------------------------- | -------------------------- | --------------- | ---- |
| `resource.update_bytes dst, dstOffset, src, srcOffset, length` | 目标字节资源、可读字节资源 | `u32, u32, u32` | 空   |
| `resource.fill_bytes dst, offset, length, value`               | 目标字节资源               | `u32, u32, u8`  | 空   |

两项指令先校验完整源／目标范围、资源类别、读取与独立更新权限，再在当前操作提交点原子更新内容与覆盖单元的版本；目标不能是宿主管理的只读输入槽位。校验失败时本操作不改变任何目标字节或版本，此前其他已提交效果不回滚。零长度仍校验权限及 `offset ∈ [0, 容量]`，不读写字节、不改变版本。相同值更新允许保守地改变版本。两项操作不推进时间、不创建事件、不改变调用栈，也不自动模拟 Flash 的 BUSY、页规则或 1→0 编程限制。

```ir
resource.update_bytes flash, 2, pageBuffer, 0, 4
resource.fill_bytes flash, 4, 4, 255
```

### 时间

时间参数采用核心已有 `f64`；单位、范围与边界错误分类统一按[虚拟时间](./0001-virtual-time.md)。普通 `f64` 常量、字段、参数与数组元素保持普通数值语义，只有提交到事件或其他时间接口时才校验。

| 操作                             | 签名与语义                                      |
| -------------------------------- | ----------------------------------------------- |
| `event.now`                      | `() -> f64`，当前入口虚拟时刻，满足整数皮秒合同 |
| `float.add/sub/mul/div<f64>`     | 复用浮点运算，不逐条隐式执行时间检查            |
| `float.cmp<f64,predicate>`       | 复用浮点比较                                    |
| `convert.int_to_float<I,f64>` 等 | 复用数值转换                                    |

中间数值可以为负数、非整数、无穷大或 NaN，只有被提交为时间参数时才必须满足约束。入口、普通 `call` 与块跳转不推进时间。

```ir
func schedule(%duration: f64) {
  %now = event.now
  %deadline = float.add %now, %duration
  %id = event.at onTick, %deadline
  return
}
```

### 普通事件与 ID

| 操作                                | 签名                          |
| ----------------------------------- | ----------------------------- |
| `event.at entry, deadline, args...` | `f64, 入口标量参数... -> u32` |
| `event.cancel id`                   | `u32 -> ()`                   |

目标是当前实例的普通事件入口，参数数量、类型与权限静态检查；生命周期入口不能通过 `event.at` 被提升工作优先级。安排前完整检查期限与参数，过去期限非法；成功安排后分配非零 ID 并捕获当时的参数值（没有隐式闭包、状态引用或字节区别名）。

ID 规则：

- ID 是实例内的普通 `u32`，`0` 表示没有事件，不同实例可以同号。
- 首次分配从 `1` 递增；有空闲 ID 时优先复用，多个空闲按释放顺序 FIFO 取用。
- 待执行事件取消生效即释放 ID；正常执行完成后在入口返回时释放；正在运行的事件仍占用 ID。
- 只有同时未释放事件占满非零 `u32` 空间时才缺少 ID，不限制实例累计安排次数。
- 实例身份不复用；芯片复位不自动清空事件分配器；销毁实例的旧消息不能转投新实例。

`event.cancel` 语义：

| ID 当前情况                      | 行为                                |
| -------------------------------- | ----------------------------------- |
| `0`                              | 无操作                              |
| 当前实例待执行事件               | 取消并释放 ID，即使已到期限仍可取消 |
| 当前实例正在执行的事件           | 无操作，不中断当前入口              |
| 曾分配、已释放、尚未复用         | 无操作                              |
| 已被新事件复用                   | 针对当前新事件，不识别旧副本        |
| 从未分配或数值不合法（当前实例） | 模型错误                            |

内核队列必须保存具体事件记录及其状态，取消后的旧队列项不能仅按复用后的数字 ID 查找并执行新事件。

排序按逻辑 `(timePs, round, sequence)`：不同时间先执行早者；新安排的未来时刻事件进入该时刻起始轮次；在轮次 r 的入口内安排当前时刻事件进入后续普通轮次而不递归执行；边界接纳的当前时刻事件不得插回已执行过的因果层；同轮已排队 A、C 时 A 安排的 B 在两者之后执行；ID 数值与空闲池顺序不参与调度优先级。选择下一普通入口前先完成公共控制工作。

## 公共控制阶段与生命周期

当前入口不会被递归回调或外部请求从指令中途打断。普通入口 A 产生生命周期通知 P 而普通入口 C 已排队时，执行顺序为 A → P → C，P 不在 A 中途回调、也不递归进入。公共控制不是按器件种类设置的优先级，器件与 Provider 无权创建此类特权工作。

新的控制变化进入后续控制轮次，不递归执行；完成当前时刻的公共控制工作后才选择下一普通入口。无限控制反馈按预算诊断处理。生命周期入口采用与普通入口相同的运行至返回边界，后续延时工作使用普通定时事件或合法外部消息继续。

```ir
func initialize() {
  state.store ready, false
  %now = event.now
  %deadline = float.add %now, 1000.0
  %id = event.at onReady, %deadline
  return
}
```

## 领域能力接入

领域能力可以声明实例期固定的静态资源与具体指令。资源引用按静态引用规则解析，指令操作数与结果采用核心已有标量与静态引用。链接时验证指令定义、资源类别、实例授权、签名、入口类别与依赖；动态 Provider 产物沿用同一检查。

领域指令必须明确声明其读取、写入、提交、传播、捕获与异常边界；核心按这些合同保持程序顺序、公共控制与普通入口调度。需要延后执行的业务以普通入口表达，触发事实的捕获规则由所属能力规定。同一虚拟时间的不同效果可以具有可观察顺序，效果等价的证明依据完整轨迹而非仅比较最终状态。领域指令的原子边界只覆盖其明确声明的写集合，入口整体继续采用已提交效果保留规则。

## 显式指令与内核改写

IR 核心与领域能力统一采用显式指令体系：每项内核功能由具体指令表达，其定义明确类型、静态资源操作数、访问权限、状态效果、提交时机、原子性与异常规则。指令名称与普通 IR 函数引用分别解析。

内核可以使用统一指令定义表复用校验、解释与编译实现；定义表是组织方式，器件代码使用经规范确认的指令集合。新增指令先评估既有指令组合的表达能力，存在明确的新增语义或实现需求时再提议。

器件与 Provider 提交的代码不得直接使用 kernel-only 操作。编译器必须保留状态、时间、资源读取与变化、捕获载荷、ID 分配顺序、事件顺序、外部通知及异常前已提交效果；纯结果未使用不代表可以删除可能异常的操作；跨状态、资源或调度效果移动代码必须有保持行为的证明。

`resource.update_bytes` / `resource.fill_bytes` 的内容与版本必须在操作提交点同步可见；编译器必须保留或插入当前产物的依赖检查点，无法静态排除重叠时保守检查，检查不得被移动到使用旧假设的步骤之后。

```ir
func checkDivisor(%divisor: u32) {
  %unused = int.div<u32> 1, %divisor
  return
}
```

`divisor = 0` 时必须异常，不能因结果未使用而删除除法。

## 动态 Provider

Provider 声明静态 key 参数布局、生成函数签名、可访问资源与权限。每个生成产物分别记录本次生成实际依赖的资源版本单元；依赖来自受追踪读取与显式登记的生成假设。可访问范围是授权上限，不自动成为每个产物的整资源依赖。key 由现有标量组成的固定参数列表表达，内核只理解类型与缓存身份，不解释 PC、指令编码或 ISA。

`dispatch provider, key(...), args(...)` 是终结指令：生成或取得目标代码后尾部进入该代码，不创建新事件、不推进时间、不增长普通递归栈，并延续当前入口预算；目标签名与返回结果必须与当前尾部上下文兼容。

```ir
func translate(%index: u32, %mode: u8, %value: u32) -> u32 {
  dispatch provider.code, key(%index, %mode), args(%value)
}
```

### 实际依赖与版本单元

- 生成只读取受追踪资源与声明假设，不执行客体副作用；受追踪读取必须记录覆盖读取范围的全部版本单元及当时版本，不能只记录起始位置所在单元。
- 字节资源可以在资源配置中按固定大小划分版本单元，单元覆盖范围在该资源存续期内固定；标量及其他资源可以把整个资源视为一个单元。核心不规定固定单元大小，也不把它等同于设备编程或擦除粒度。
- 一个产物可以依赖多个单元与多个资源；无读取与假设时依赖集合可以为空。生成时折叠的数据、影响生成选择的映射或模式等假设也必须登记并受版本保护。
- 普通运行时寄存器与 RAM 数值不是默认缓存 key，执行阶段的普通数据读取也不自动成为生成依赖；若用于翻译特化或常量折叠，则必须追踪并保护相应假设。
- 生成使用的内容与记录版本必须一致；生成、校验或编译期间依赖变化的产物不得发布为有效缓存。
- 版本标识属于内核依赖元数据，不是 IR 新增标量类型，也不要求器件拼入 key；版本回绕、重置或单元身份复用不得让旧产物误判为有效。

### 缓存查找与按需重生成

key 相同只表示找到候选产物；每次派发都要校验候选的全部依赖版本，全部匹配才可复用。任一依赖不匹配时该产物已过期，必须按当前内容重新生成、校验、链接并取得可执行产物，再替换缓存条目。运行时 `args` 的值可以在复用同一产物时变化。

更新路径只更新所涉单元的版本，不要求立即扫描或删除缓存条目；实现的失效正确性不得依赖缓存是否已被清理，旧产物引用同样必须经过有效性检查。真正不可变的资源或假设可以保持版本不变，但授权、读取追踪与产物校验仍须成立。

### 当前产物与恢复检查点

- 可能使当前代码假设失效的操作必须具有合法块边界／检查点及后继恢复目标；Provider 表达可恢复状态、已提交效果与尚未执行步骤的对应位置，内核负责检查依赖。
- 在可能相关的更新实际提交之后、继续执行依赖旧假设的步骤之前必须重新检查依赖；可证明更新只涉及无关单元时可以继续，无法排除重叠时保守检查（经普通函数调用发生的更新同样适用）。
- 依赖失效时必须退出旧产物并派发合法恢复目标，已提交效果保留且不重复执行；检查点不得切断单项操作已声明的原子提交。
- 经过调度或恢复边界再次进入产物时必须检查依赖；直接持有旧编译代码、返回地址或缓存引用不能绕过校验。检查与重新派发延续当前入口预算。
- 缓存驱逐、重编译与检查策略不能改变客体时间、ID、事件、外部输出或异常前已提交效果。

## 外部软件与消息

使用宽松同步的 Worker 时，外部消息在合法调度边界按已声明 schema 接纳，不能在入口中途修改 IR 状态，也不能回填过去时刻。

标量消息捕获值后投递。字节数据通过实例固定容量输入区／FIFO，在完整容量与范围检查后显式复制并安排通知；容量不足时拒绝本次接纳并报告背压，不覆盖未消费数据、不无限排队、擅自丢弃旧消息。需要重试时以最终成功接纳的时间为准；整数偏移不自动获得不可变快照语义。

图像、视频、Python 等软件继续运行在 JS／Worker，首版不为它们引入通用动态 IR 数据资源。确定性重放至少依赖相同的初始模型／资源、配置、种子，以及记录的外部消息内容、接纳时刻与稳定顺序。

```ir
func onBytes(%offset: u32, %length: u32) {
  bytes.copy savedInput, 0, input, %offset, %length
  state.store savedLength, %length
  return
}
```

## 校验、故障与预算

### 必须静态拒绝

- 类型、指令、资源或目标函数缺少声明及认可的定义项。
- 常量越界、签名或结果数量不匹配、错误位宽转换。
- SSA 非法定义或使用、不满足支配、块参数不匹配、缺少终结指令。
- 普通调用递归、非法跨实例访问、器件使用 kernel-only 操作。
- 非法初始化、资源描述、所属能力的静态约束或未授权能力。

只有依赖运行值的约束才延后检查，例如动态越界、整数除零、过去期限或非法事件编号。

### 故障

模型错误暂停整个仿真，保留已提交状态、资源效果与队列，报告实例、入口、调用链／IR 位置、虚拟时间与原因；不自动回滚、撤销已提交效果或继续推进其他实例。硬件结果、资源状态与模型异常的分类由所属能力或器件合同定义；客体固件的非法寄存器操作由芯片模型解释，不直接等于宿主 IR 类型或范围错误。

首版不支持失败入口的中间恢复：修复后重建，或在未来具备合法检查点时重放。实例销毁在内核边界停止输入、取消待执行事件并执行所持资源的清理与必要传播，不中断当前入口的半条指令；销毁不是故障，复位也不自动等同于销毁。

```ir
func failsAfterStore() {
  state.store counter, 1
  bytes.store<u32,little> ram, 14, 7
  state.store counter, 2
  return
}
```

第二条指令越界时仿真暂停，`counter` 保持 `1`，`ram` 没有本次不完整写入，第三条指令未执行。

### 预算

- 每入口 1,000,000 个参考 IR 步骤，含普通同步调用与尾派发。
- 同一虚拟时刻 1,000,000 次入口执行，普通与生命周期入口均计入。

上限可配置；超限暂停并诊断，不插入 1 ps、不改变周期、不按机器快慢决定模拟结果。「参考 IR」指完成链接、校验与内核语义降低后、后端优化前的程序；后端必须保留相应逻辑计数／检查点，不能以优化后的机器指令数替代。

## 一致性验证

参考解释器、内核改写与编译后端必须用同一输入与相同初始状态比较：

1. 有类型状态与存储中的原始数据位。
2. 所链接能力声明的资源效果、读取结果及触发时载荷。
3. 普通事件顺序、公共控制顺序、ID 分配／释放／复用。
4. 外部通知、虚拟时间、模型异常及异常前效果。
5. Provider 命中、驱逐、失效或重新生成不改变上述行为。

首批必测边界包括：窄整数回绕与除法特例、超宽移位、严格转换、f32 逐操作舍入、显式 FMA、NaN 数据移动、非对齐／重叠／越界、同刻 `A/C/B`、`A/P/C`、值捕获、`cancel(0)`、复用旧 ID 及旧队列项残留。

动态 Provider 还必须验证：一次生成包含多条客体指令的基本块；生成本身没有客体状态与时间副作用；条件分支在运行时求值；缓存命中复用整块；按固定版本单元修改固件后只有相关单元依赖的产物过期并在下次请求时重生成；周期累计、状态与表格一致。合成块级模型的验证不能代替真实 MCU 的中间观察与恢复边界时序验证。

规范化程序的 TypeScript 数据结构、文本与持久化编码，以及静态资源引用、指令定义与链接元数据的通用编码属于后续工作；profile 独立版本化并声明依赖。
