# 原理图格式（.sch）

- Start Date: 2026-10-14
- Reference Issues: [#6](https://github.com/x-botlab/mica-js/issues/6)
- Implementation PR: [#74](https://github.com/x-botlab/mica-js/pull/74)

原理图使用 `.sch` 文件描述，采用 UTF-8 JSON，`version` 固定为整数 `1`；原理图标识为宿主工程内的 POSIX 相对路径。文件可位于工程内任意目录（如 `boards/`、`schematics/`）。canvas 布局使用独立的 `.cnv` 文件，见 [Canvas 格式](./0013-canvas-format.md)。

工程配置、依赖声明与 `.sch` 的发现规则由宿主定义，格式层不规定工程配置入口。

## 结构

`sheet` 包含三个图元数组，每项以 `id` 标识：

| 字段              | 类型    | 必填 | 说明                                                   |
| ----------------- | ------- | ---- | ------------------------------------------------------ |
| `version`         | integer | 是   | 格式版本，固定为 `1`                                   |
| `sheet`           | object  | 是   | 图页图元容器                                           |
| `sheet.symbols`   | array   | 是   | 器件、网标、电源／地、文本注释图元，允许空数组         |
| `sheet.wires`     | array   | 是   | 导线图元 `{ id, points }`，`points` 至少两个有限坐标点 |
| `sheet.junctions` | array   | 是   | 用户主动创建的交点 `{ id, x, y, wires }`               |

symbol 必填 `{ id, device, x, y, rotation }`，可选 `designator`（仅器件）、`net`（仅 `builtin:label` / `builtin:power` / `builtin:ground`）与 `properties`。`id` 是 UUID v4 形式的稳定标识，位号与网名是独立字段，改它们不改变 `id`。

原理图没有顶层 `id`：工程内 POSIX 相对路径即其标识，同名文件可按路径共存；顶层出现 `id` 按未知字段报错。

## 符号角色

符号按 `device` 分为五种角色，字段按角色约束。

| 字段         | 类型   | 必填               | 说明                                                                                                                          |
| ------------ | ------ | ------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| `designator` | string | 可选               | 器件位号（`U1`、`R2`），仅器件可写；省略时取 `id`；在全部器件实例间唯一                                                       |
| `net`        | string | 网标／电源／地必填 | 网名（`D0`、`3V3`、`GND`），非空；同名即同网，不要求唯一                                                                      |
| `properties` | object | 可选               | 属性键到属性值的映射；值为字符串、有限数值、布尔值、image／binary 的资源引用 `{ src, mode }`，或 `nullable` 属性的显式 `null` |

| 角色 | `device`          | 位号 | 网名           | 可编辑实例属性                                |
| ---- | ----------------- | ---- | -------------- | --------------------------------------------- |
| 器件 | `<包ID>:<器件ID>` | 有   | 无             | 由[器件定义](./0005-device-definition.md)声明 |
| 网标 | `builtin:label`   | 无   | 有             | 无                                            |
| 电源 | `builtin:power`   | 无   | 有，缺省 `VCC` | 无                                            |
| 地   | `builtin:ground`  | 无   | 有，缺省 `GND` | 无                                            |
| 文本 | `builtin:text`    | 无   | 无             | 仅 `text`                                     |

- 属性键与值类型取自器件定义（[器件定义](./0005-device-definition.md) · [属性定义](./0009-device-properties.md)），文件只保存实例覆盖值，未出现的键使用器件默认值。
- `properties` 与位号不参与拓扑推导，只供编辑器、运行器与器件实现读取；`net` 参与网络命名。
- 资源引用只出现在 image／binary 属性上：`file` 为工程内 POSIX 相对路径，`inline` 为 base64，`store` 为宿主资源标识；文档只保存引用，不保存宿主绝对路径与网络地址。违反 `mode` 的路径或编码返回 `schema/invalid-value`，未知字段返回 `schema/unknown-field`。
- `builtin` 是保留命名空间，其他包 ID 由宿主按其依赖声明解析。

### 内建符号

| `device`         | 连接端             | 显示文本与网络命名   |
| ---------------- | ------------------ | -------------------- |
| `builtin:label`  | symbol 的 `(x, y)` | 取 `net`             |
| `builtin:power`  | symbol 的 `(x, y)` | 取 `net`，缺省 `VCC` |
| `builtin:ground` | symbol 的 `(x, y)` | 取 `net`，缺省 `GND` |
| `builtin:text`   | 无（不参与连接）   | 取 `properties.text` |

内建符号由加载器识别，不需要在包索引中注册，图形由编辑器提供。

## 导线与交点

- 每条导线的 `points` 首项与末项为几何端点，相邻点之间为连续线段；同一导线的所有线段电气连通。
- 器件引脚图页坐标由器件定义提供的引脚局部坐标，结合 symbol 的位置与旋转计算；`.sch` 不保存引脚几何。
- 内建符号的连接位置为其 `(x, y)`，显示文本为 `net`；`builtin:text` 不参与连接。
- 交点由用户主动创建，记录坐标与被选中的导线 ID；每个交点引用至少两条 ID 唯一的有效导线，坐标位于每条被引用导线的折线上（线段内部或端点均可）。
- 交点失效时保留数据并报 error 级诊断：引用不足两条有效导线报 `junction/unknown-wire`，坐标不在被引用导线上报 `junction/off-wire`。
- 加载是只读操作，不修改文档内容；修复只在用户显式编辑并提交时发生，且可撤销。
- 样例中交点位于第一条导线的竖直线段与第二条导线的首端点，显式连接两条导线；器件侧首尾坐标须与器件定义中的目标引脚位置一致。

## 连接语义

- **器件与引脚来源**：`device` 使用 `<包ID>:<器件ID>`，两侧均为非空且采用明确字符规则的标识；`builtin:label`、`builtin:power`、`builtin:ground`、`builtin:text` 由加载器识别。实例引脚来自[引脚声明](./0006-device-pins.md)。
- **图元标识与引用**：三类图元的 `id` 为各自数组内唯一的 UUID v4，作为选择、撤销与 canvas 绑定的键；多个 symbol 可以引用同一 device。`designator` 在全部器件实例间唯一，改位号不改变 `id`；交点引用稳定导线 ID。
- **引脚与网标连接**：导线首尾坐标与引脚或网标连接位置重合时接入对应连接端；线段内部采用几何经过语义；多条导线接入同一连接端时归入同一连通分量。
- **导线之间连接**：显式交点合并 `wires` 列表中的导线连通分量；共同接入引脚或网标的导线通过该连接端连通；交叉、首尾重合、T 形接触与重叠一律采用显式交点规则。
- **拓扑判定**：连续折线、首尾与引脚或网标的位置关系、显式交点共同确定连通性。网络成员为 symbol 的具体连接端，每个器件引脚独立参与连接；拓扑按稳定 ID 与显式连接数据构建。
- **网络生成范围**：至少接入一个器件引脚或网标的导线连通分量生成网络；纯绘图分量保留为几何数据，孤立引脚与网标保留独立连接端状态。孤立的同名标签不会凭空生成网络，只有已连通的连通分量才参与同名合并。
- **网络命名与合并**：网络名取自接入的 `net`。同一连通分量内出现两个不同网名时产生 `net/naming-conflict` 诊断；不同连通分量使用同一网名时合并为同一个网络（名称即连通键）；其余网络保持匿名。匿名网络不写入文件，运行器与诊断使用成员稳定 ID 排序后的哈希生成内部标识（如 `net:3f6c1e28`）。
- **开放连接状态**：孤立器件引脚具有开放连接状态，自由导线端点具有悬空状态。
- **无电气与域属性**：推导出的网络只表达拓扑连接。

## 校验

- 使用单个完整 JSON 对象，键唯一，字段属于对应 schema 且值类型匹配。
- `version` 使用整数 `1`，版本校验错误返回结构化诊断。
- 唯一性：symbol、wire、junction 的 ID 为 UUID v4 且在各自数组内唯一，非 UUID v4 返回 `schema/invalid-value`；网标与器件实例共享 symbol ID 作用域，`device` 允许被多个实例引用；`designator` 在全部器件实例间唯一（缺省值参与比较）；网标／电源／地的 `net` 非空且允许重复。
- 角色字段：`designator` 只能出现在器件上，`net` 只能出现在网标／电源／地上，违者返回结构化诊断；网标缺少 `net` 视为错误。
- 引用闭合：`device` 解析为有效器件或内建符号；交点引用当前原理图至少两个唯一的有效导线 ID，否则报 `junction/unknown-wire` 或 `junction/duplicate-wire`；其余引用错误返回结构化诊断。
- 几何校验：`points` 至少两个有限坐标点；坐标重合与点在线段上的判定默认精确匹配，容差由加载选项给出，缺省 `0`；引脚坐标按整数旋转换算；交点不在被引用导线上返回 `junction/off-wire`。几何错误保留原始数据并返回结构化诊断。
- 只读加载：解析与校验不修改文档；失效图元保留在文件中，由编辑器在用户显式编辑时修复。
- 兼容范围：`version: 1` 为起点，不提供旧文件迁移与向后兼容。
- 拓扑构建：索引图元并计算引脚位置，依据导线接入与显式交点生成连通分量，再按网名合并同名连通分量，提取并去重 symbol 连接端形成网络成员；连通分量内出现不同网名时返回诊断。
- 加载、拓扑构建与编译按文件路径、图元类型及稳定 ID 确定性排序。
