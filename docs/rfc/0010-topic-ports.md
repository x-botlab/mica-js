# 话题端口定义

- Start Date: 2026-10-15
- Reference Issues: [#10](https://github.com/x-botlab/mica-js/issues/10)
- Implementation PR: [#115](https://github.com/x-botlab/mica-js/pull/115)

话题端口定义实例参与话题通信的逻辑端口，包括方向、载荷类型与绑定状态。Widget 与器件在各自核心描述中声明端口字段并引用本文规则。

端口描述通信接口，属性描述持久配置，两者是相互独立的集合：属性不是话题，话题不承载配置。

## 端口描述

| 字段          | 类型   | 约束                         |
| ------------- | ------ | ---------------------------- |
| `title`       | string | 可选，省略时消费方使用端口键 |
| `description` | string | 可选，仅展示                 |
| `direction`   | string | 必填，`input` 或 `output`    |
| `type`        | string | 必填，取自下方载荷类型清单   |

端口以稳定端口键索引；同时需要输入和输出时分别定义两个端口。

## 载荷类型

载荷类型是**封闭清单**，只有以下 8 种：

| 类型              | 载荷                                        | 说明                                  |
| ----------------- | ------------------------------------------- | ------------------------------------- |
| `boolean`         | `true` / `false`                            | 电平、按键、开关                      |
| `number`          | 有限数值                                    | 不区分整数与浮点                      |
| `string`          | 文本                                        | 名称、命令、单值文本                  |
| `vec2d`           | `{ "x": number, "y": number }`              | 二维坐标、位移、速度                  |
| `vec3d`           | `{ "x": number, "y": number, "z": number }` | 三维坐标、位移、速度                  |
| `bytes`           | 字节序列                                    | 无结构，语义由通信双方约定            |
| `bytes<rgb565>`   | 字节序列                                    | 像素帧，带 8 字节像素头，支持区域更新 |
| `bytes<segments>` | 字节序列                                    | 段码帧，无头，一位一字节，整帧发布    |

规则：

- 清单之外的类型名返回 `type/unknown`，不提供用户自定义类型。
- 不提供隐式转换，也不引入万能类型；`vec2d`、`vec3d` 与 `number` 互不兼容。
- `vec2d` / `vec3d` 的键固定为 `x`、`y`（及 `z`），出现其他键返回 `schema/unknown-field`，分量非有限数值返回 `schema/invalid-value`。
- `bytes` 与带标签的 `bytes<...>` 互不兼容，避免绕过布局校验。
- `bytes` 仅用于协议帧、波形、样本批次等无结构数据；能用内置类型表达的数据必须使用内置类型。`bytes` 端口的器件定义必须写明布局：单元类型、字节序、长度与对齐。
- 数值完整性、取值范围、单位、坐标系与业务含义由通信双方约定，格式层不校验，内容正确性由器件与 Widget 的 JavaScript 层保证。
- `bytes<rgb565>` 的像素头字段固定为 `u16`，上限 65535；超大帧用区域分块表达，不扩展字段宽度。
- 标签清单目前只有 `rgb565` 与 `segments`，每个标签自带布局定义，互不共享信封。新增标签的条件是某类外设以它原生输出且实测转换影响帧率，并需附权威布局定义。

## 载荷布局

每个标签定义自己的布局，不共用统一信封。

### `bytes<rgb565>`

帧体 = 8 字节像素头 + 像素数据。头为小端 `u16 x`、`u16 y`、`u16 width`、`u16 height`。

- 每像素 2 字节小端，`RRRRRGGG GGGBBBBB`，行优先、紧密打包、无 stride。
- 总长度 `8 + width × height × 2`。
- 区域更新：整帧刷新使用 `(0, 0, width, height)`，局部更新使用对应矩形。

### `bytes<segments>`

帧体 = 纯段码字节序列，无头。

- 一位数字一个字节，下标 0 为最左位，自左向右递增。
- 位序：bit0–bit6 依次为 a–g，bit7 为小数点；`0x00` 为全灭。
- 总长度 = 位数，不需要宽度字段。
- 整帧发布：一帧通常只有几个字节，区域更新没有收益。
- 显示位数多于面板位数时消费方取前 N 个字节，少于时按需补全或留空。

### `bytes`

无头、无布局约束，语义由通信双方约定。

## 绑定

绑定把本实例的端口映射到目标端点，形如 `{ "symbol": "<symbol id>", "port": "<端口键>" }`；保存位置由宿主文档定义，Canvas 侧见 [Canvas 格式](./0013-canvas-format.md)。

- **方向**：必须 `output → input`。
- **类型**：两侧载荷类型必须相同，不可赋值返回 `topic/type-mismatch`。
- **端点**：目标 symbol 不存在返回 `canvas/unknown-symbol`；目标器件未声明该端口返回 `canvas/unknown-target-port`。
- **可选性**：所有端口的绑定均可选；已绑定端口参与投递，未绑定端口保持静默。缺失输入与 `0`、`false`、空字符串具有各自独立的语义。
- **扇出**：同一端点可被多个输入端口绑定；同一端口只绑定一个端点。
- **无话题名**：格式层不出现话题名，宿主以 `(symbol id, 端口键)` 推导通道标识。

类型不同而语义可通时，由用户编写的适配器 Widget 承担转换，格式层不参与。

## 投递信封

每条消息由宿主投递时附带信封，载荷保持纯值：

```text
{ endpoint: { symbol, port }, simTime }
```

- `simTime` 固定存在：宿主在投递时填充该消息对应的仿真时间，发布方不提供，载荷中不出现时间字段。数值口径见[虚拟时间](./0001-virtual-time.md)。
- **配对**：同一时刻的多路数据携带相同 `simTime`，消费方按时间配对，不依赖到达顺序。
- **时钟域与单位**：由仿真合同定义，本规范只要求单调且可比较。
- 因此不需要为「带时间的值」增设载荷类型；陀螺仪、电机反馈、音频采样等场景复用同一机制。

## 校验

- 端口键、`direction`、`type` 必填且类型匹配；`direction` 仅取 `input` / `output`。
- `type` 取自封闭清单，未识别返回 `type/unknown`；`bytes<...>` 的标签同样取自封闭清单。
- `vec2d` / `vec3d` 校验键集合与分量是否为有限数值：键集合不符返回 `schema/unknown-field`，分量非有限返回 `schema/invalid-value`。
- `bytes<rgb565>` 校验像素头可解析、坐标非负、宽高为正，且总长度等于 `8 + width × height × 2`，不一致返回 `schema/invalid-value`。
- `bytes<segments>` 校验总长度为位数，允许任意正整数长度，不设头部校验。
- 绑定在装载期校验方向与载荷类型（`topic/type-mismatch`），运行期不重复检查。
- 未知字段一律返回 `schema/unknown-field`；端口描述不单独版本化，版本随所在描述文件。

## 范围

编解码、通信元数据、消息合并、投递可靠性与队列调度由通信合同定义。本规范只约定同进程内按端点直连的语义，以及固定携带 `simTime` 的投递信封。
