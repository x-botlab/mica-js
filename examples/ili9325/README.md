# ILI9325 TFT 控制器器件包

ILI9325 的 Mica 器件工程：240×320 GRAM、横向安装的 320×240 面板、16 位 8080 并口。
器件 ID 是 `ili9325`，控制器只观察引脚电平，不依赖任何 MCU；同一份模型可以接
STM32、8051 或测试用总线主设备。

引脚名对应 CT117E-M4 的实际接法（参考 `HAL_06_LCD` 的 `lcd.c`）：

| 信号       | 器件引脚      | 板上连接                     |
| ---------- | ------------- | ---------------------------- |
| 数据总线   | `D0`–`D15`    | `GPIOC[15:0]`                |
| 写选通     | `WR`          | `PB5`（低有效）              |
| 读选通     | `RD`          | `PA8`（低有效）              |
| 寄存器选择 | `RS`          | `PB8`（低=命令，高=数据）    |
| 片选       | `CS`          | `PB9`（低有效）              |
| 复位       | `RST`         | 未接（参考程序不做硬件复位） |
| 供电       | `VDD` / `VSS` | 3.3 V / 0 V                  |

`device.json` 的 `VDD`/`VSS` 只用于读驱动的参考电平；板级必须把它们接到固定电位网络，
否则读周期驱动不出确定电平。

## 总线协议

- **写**：`CS` 有效时，`WR` 的上升沿锁存一次访问；锁存瞬间采样 `RS` 与 16 位数据
  总线。参考 BSP 在 `WR` 上升沿之后才拉高 `RS`，因此模型必须在上升沿这一边界完成采样
  ——测试用的总线主设备把每次访问拆成「低电平 / 高电平」两个真实片段来保证这一点。
- **读**：`RD` 与 `CS` 同时有效且不在复位时，控制器驱动数据总线；`RD` 或 `CS` 释放
  时释放总线。模型在窗口打开时求值并驱动，不做 ILI9325 的首次哑读。
- **复位**：`RST` 低有效；释放沿清空 GRAM 与寄存器，并发布一整屏黑色。参考程序不驱
  动 `RST`，悬空时模型按「非低」处理，总线访问照常有效。

## 寄存器

热路径只建模参考 BSP 实际使用的寄存器；其余寄存器写入后原样读回，不产生行为。

| 寄存器          | 语义                                                            |
| --------------- | --------------------------------------------------------------- |
| `R00h`          | 读回 `0x9325`（参考 BSP 用它与 `0x8230` 区分控制器）            |
| `R03h`          | AM（bit3）与 I-D[1:0]（bit4/5）决定 GRAM 地址推进；BGR 位只保存 |
| `R07h`          | 显示开关，只保存（端口载荷始终是 GRAM 内容）                    |
| `R20h` / `R21h` | GRAM 地址计数器，分别按 8 位 / 9 位保存                         |
| `R22h`          | GRAM 数据：写入存像素，读出返回当前像素（读出后地址推进）       |
| `R50h`–`R53h`   | 窗口边界（含端点，允许单像素窗口）                              |

地址推进按 `R03h`：`AM=0` 时 X 是快轴，`AM=1` 时 Y 是快轴；快轴到窗口边界后回卷，
慢轴按 `I-D` 指定的方向步进。写入落在窗口外或 GRAM 外时**忽略该像素**，地址计数器仍
推进。

## 面板映射与端口

GRAM 是 240（X）× 320（Y），面板横向安装成 320×240：

```text
面板列 px = 319 - GRAM Y
面板行 py = GRAM X
```

与参考 BSP 的用法一致：字符沿 X 递增（`Line0..Line9 = 0, 24, …, 216`），字符列从
`refcolumn = 319` 起每字符减 16。

端口 `framebuffer` 是 `bytes<rgb565>`，载荷 = 8 字节像素头 + 像素：

- 头为小端 `u16 x, y, width, height`，`x` 是面板列（0..319）、`y` 是面板行（0..239）；
- 像素为 GRAM 原始 RGB565 值，行优先、紧密打包；`R03h` 的 BGR 位**不做**交换
  （参考 BSP 以 BGR=1 写 `0xF800` 显示红色，与原始值一致）。

## 高性能路径

1. **只有三个观察源**：`WR.sample.level`、`readActive`（`RD` 与 `CS` 的组合）与
   `RST.sample.level`。数据总线与 `RS` 不建立观察，只在锁存时各读一次采样；每个发布
   边界的比较量从 23 项降到 3 项。
2. **热路径无函数调用**：数据总线拼接、像素偏移、地址回卷全部内联；顺序填充时每像素
   只有一次 16 位存储、一次加法、两次比较和一次脏矩形更新（只写变化的那一侧）。
3. **合帧发布**：写入只维护脏矩形；`frameSeq` 只在「上一帧已发布」后递增，过程自身
   不写这个源，因此一次连续绘图无论多少像素都只排队一帧，不会自我重触发。
4. **整段复制**：脏矩形覆盖整行（`width == 320`）或只有一行时，一次 `copyBytes` 取
   整个矩形；其余情况按行复制。整屏刷新因此只有 2 条通道消息（1 条帧信息 + 1 条
   像素体）。

| 用例               | 像素   | 仿真时间 | 墙钟   | 倍率 | 吞吐      | 消息数 |

| 整屏填充           | 76,800 | 7.68 ms  | 562 ms | 73×  | 137k px/s | 2      |
| 24 行文本带        | 7,680  | 0.77 ms  | 71 ms  | 92×  | 109k px/s | 2      |

对照行用完全相同的数据/控制引脚与总线主设备，但不做任何存储与反应：它给出

其余 285 ms 是共享的求解与主设备成本。

估算需要约 2.9 s 墙钟，对应约 39 ms 仿真时间。

## 与参考程序 / 数据手册的差异

- **不做 GRAM 首次哑读**：真实 ILI9325 读 `R22h` 的第一次返回哑数据，模型直接返回当前
  像素。参考 BSP 从未调用 `LCD_ReadRAM`，不受影响。
- **`R07h` 不门控输出**：端口语义是 GRAM 内容，显示开关只保存。需要「关屏即黑」的宿主
  应在画布层处理。
- **窗口回读返回生效值**：`R50h`–`R53h` 被约束到合法范围后写回后备存储，读回的是生效
  边界而不是最后一次写入的原始字。
- **越界写**：真实芯片对窗口外写入行为未在数据手册中完全定义；模型选择「忽略像素、
  地址仍推进」。`R20h`/`R21h` 按寄存器宽度截断（参考的 `LCD_DrawRect` 会把行地址推到
  269，模型保存为 13），因此不会把越界地址折叠到 239 造出参考画面没有的像素。
- **无时序参数**：不校验建立/保持时间与最小脉宽；每次 `WR` 上升沿都当作一次有效访问。

## MCU 联合仿真

`test/joint.test.ts` 把 `@mica-js/example-stm32g431rbt6` 的 MCU 与本器件接在同一块板
上，跑 `HAL_06_LCD` 的原始 Keil 固件（`test/fixtures/HAL_06_LCD.bin`，从
`HAL_06_LCD.axf` 的 PT_LOAD 段导出）。

```bash
MICA_JOINT=1 pnpm exec vitest run test/joint.test.ts
```

接线：`PC0`–`PC15` → `D0`–`D15`，`PB5`→`WR`、`PB8`→`RS`、`PB9`→`CS`、`PA8`→`RD`，
`RST` 接 `VDD`（参考程序不驱动复位）。`clockFrequency` 必须是 80 MHz：固件用
HSI16 → PLL M=2 / N=20 / R=2 配置主频，`HAL_Delay` 的 `uwTick` 换算依赖这个值。

用例推进到 200 µs 仿真时间，断言 LCD 的寄存器后备区已得到 `REG_932X_Init` 的序列
（`R02=0x0700`、`R03=0x1030`、`R08=0x0207`、`R11=0x0007`、`R51=0x00EF`、
`R53=0x013F`）且命令索引停在 `0x13`。这证明 MCU → GPIO → 电气网络 → 总线锁存 →
寄存器全程正确。

用例只验证到 BSP 初始化写入，以便把测试时间集中在 MCU → GPIO → 电气网络 → 总线锁存
链路。`throughput` 会识别 HAL_Delay 的 `HAL_GetTick` 轮询形态，在 SysTick 边界推进
`uwTick` 并复查终点；`precise` 仍逐指令执行同一循环。

### 联合性能基准

完整测试记录见
[`docs/stm32g431rbt6-ili9325-joint-benchmark.md`](../../docs/stm32g431rbt6-ili9325-joint-benchmark.md)。

`bench/joint-perf.test.ts` 使用同一块联合板从复位推进到 **440 ms**，覆盖多个
`HAL_Delay`、LCD 初始化、真实 GRAM 写入与 `framebuffer` 发布。每轮创建新板，进程 CPU
时间三轮取最小值；首轮同时承担模块级 Thumb 块缓存冷启动。

```bash
./node_modules/.bin/vitest run --config vitest.perf.config.ts bench/joint-perf.test.ts
```

推进窗口必须使用不超过 SysTick 周期（约 200 µs）的 `runUntil` 量子；本固件当前运行路径下，
大切片会少计 `uwTick`，从而把固件错误地停在延时循环。

当前 Linux x64、Node 24.20.0、`throughput` 读数：

| 窗口                   | 仿真时间 | CPU 最好值 | 实时倍率 |
| ---------------------- | -------- | ---------- | -------- |
| 0 → 200 µs 冷启动      | 200 µs   | 215 ms     | —        |
| 200 µs → 220 ms        | 219.8 ms | 411 ms     | 0.535×   |
| 220 → 440 ms           | 220 ms   | 169 ms     | 1.299×   |
| 0 → 440 ms（含冷启动） | 440 ms   | 795 ms     | 0.553×   |

首轮冷缓存总耗时为 6006.5 ms CPU / 3819.9 ms 墙钟；表中最好值来自后续轮次。完整
440 ms 的墙钟最好值为 509 ms。440 ms 内共发布 10 帧、132 个像素，其中 131 个非零；
220 ms 时已有 4 帧。最终 GRAM 有 135 个非零像素。基准同时断言每个发布帧与其发布瞬间的
GRAM 快照逐像素一致，因此数据确实经过 MCU GPIO → 电气网络 → ILI9325 GRAM → 合帧发布链路。

Direct JIT 统计：`programs=1`、`blocks=311`、`shards=72`、`compiles=22`、
`calls=6783`、`fallbacks=2720`。

## 验证

```bash
cd examples/ili9325
pnpm run typecheck   # mica prepare && tsc --noEmit
pnpm run test        # mica build + vitest（源码用例 + 交付产物用例）
pnpm run bench       # mica build + vitest --config vitest.perf.config.ts
```

`test/master.ts` 的时序：一次访问 = 两个半周期片段（先拉低 `WR` 并稳定数据与 `RS`，
再拉高 `WR` 触发锁存），每个片段都真实跨过发布边界。这正好复现参考 BSP 的关键约束：
`RS` 在 `WR` 上升沿时已经稳定，锁存不会被同片段合并影响。
