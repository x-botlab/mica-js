# CT117E-M4 与 CT107D 冷启动测量

CT117E-M4 的启动 CPU 采样显示，耗时主要在第一次推进 16 ms 时翻译、校验和编译指令块，不在显示 worker。生成嵌套 IR 时，Builder 曾在每一层重新遍历已检查的子区域；绑定每个块时，校验器也曾重建整份器件声明索引。

优化后，Builder 不再重复校验已经逐条检查的自有子区域；`finish()` 仍对最终 IR 快照做完整校验。声明索引仅在同一份已通过校验、递归冻结的器件定义上复用；每个块的绑定与控制流检查继续独立执行。生成的 IR、固件、步长及执行后端不变。

## 浏览器生产包 A/B

在 i7-12700K / Chromium 153 上使用本机静态 HTTP 服务。保留优化前的 CT117E-M4 Playground 和 CT107D 工作台生产包，与重建后的生产包交替运行。每次启动新浏览器进程，等文档编辑态可用后点击「运行」；每组跑三轮，不启用 CPU 采样。

| 板卡与计时终点          |     优化前中位数（范围） |     优化后中位数（范围） |
| ----------------------- | -----------------------: | -----------------------: |
| CT117E-M4：进入运行态   | 22.45 s（20.35–24.67 s） | 14.37 s（13.40–15.83 s） |
| CT117E-M4：LCD 首次蓝底 | 23.15 s（21.01–25.42 s） | 14.96 s（13.98–16.46 s） |
| CT117E-M4：完整十色带   | 27.43 s（25.13–29.77 s） | 18.39 s（17.57–20.11 s） |
| CT107D：进入运行态      |     700 ms（689–800 ms） |     647 ms（647–753 ms） |
| CT107D：数码管首次点亮  |     673 ms（663–773 ms） |     628 ms（627–725 ms） |

计时都从点击开始。像素判据分别为 LCD 区域首次出现蓝底、十条色带各自同色且互异，以及数码管 View2D 首次出现点亮段（不计静态板图或未点亮段）。CT117E-M4 使用 `HAL_06_LCD.hex`；CT107D 工作台使用 `seg7-dynamic.hex`（12 MHz）。两板均为 16 ms 固定步长。CT107D 的收益较小，优化前后范围有重叠；结果不代表实时性能保证。

重建入口如下；CT107D 的 `.sch` 只刷新了融合器件的完整性锁。

pnpm --filter @mica-js/playground build:workbench
pnpm --filter @mica-js/example-ct107d build:fused

## 稳态复核

Node.js 24.20.0 的稳态对照分别加载旧、新发布模型和对应的校验器。

- CT117E-M4 使用 `bench/ct117e-m4-perf.test.ts` 测量 360–390 ms 清屏。三组各六轮，一组先跑旧版，两组先跑新版。按原基准口径（去掉首轮），各组墙钟中位数分别为 37.39 → 53.24、35.16 → 36.65、35.79 → 38.09 ms。前几轮波动较大；另看每组六轮中的末两轮，合并后的墙钟中位数为 35.47 → 35.80 ms（范围 34.85–36.86 → 35.15–38.09 ms）。每轮均有 104,338 次 WR 变化、52,169 次 GRAM 写入和 2 帧；推进至 440 ms 的总工作量也一致。五幕 LCD 像素回归和分立总线对账已通过。
- CT107D 使用 `bench/preview.test.ts`（`digital-display-dynamic.bin`、11.0592 MHz，不是上面的工作台负载）测量仿真 512–1536 ms。三轮墙钟中位数为 571.9 → 564.5 ms，进程 CPU 中位数为 904.7 → 905.9 ms。17 个共同检查点验证通过；数码管仍为 `2018` / `--03`，话题摘要不变。

## 第二轮：首个仿真步的指令块

以 `17cb52a` 为基线。生产 Chromium 的模拟 worker 在首个 `resume()` 中推进 16 ms。单次阶段探针记录 `runUntil()` 墙钟 **13.13 s**，分为翻译（含 Builder 最终校验与融合变换）4.45 s、运行时 IR 快照与绑定校验 4.59 s、通用执行体生成 2.22 s、直接 JIT 编译 1.68 s。四项覆盖约 98.5% 的首步；包/资源装载的 `createHeadlessRuntime` 装载阶段约 0.11 s。独立 CPU 采样中显示 worker 在这段等待期间基本空闲。较晚出现的首蓝和完整图案仍以实际固件像素判定。

首步翻译了 247 个块，共 928,901 条 IR 操作（含嵌套区域）。未知地址的访存指令必须生成所有可能命中的地址分支；其中写专用的 NVIC STIR 原本也展开了一整份 NVIC 读树，而写路径则复制了同一份 NVIC 写树。STIR 的四个字节 lane 现在直接沿用系统区的默认零返回，写路径和常规 NVIC 窗口共用同一棵树。仅做这项改动，块数不变，IR 降至 **782,793** 条（−15.7%），探针下首步从 13.13 s 降至 10.69 s。第二项改动不改变 IR：校验器进入子区域时保留可见结果表，退出时只移除本区域新增的结果，不再复制整个父表；跨分支的重复 ID、作用域、结构和绑定检查仍保留。

两项改动合并后的生产包 A/B，使用相同固件、固定 16 ms 步长和上述像素判据。每组各三轮，新 Chromium 进程，不启用阶段探针或 CPU 采样：

| 板卡与计时终点          | `17cb52a` 中位数（范围） |     第二轮中位数（范围） |
| ----------------------- | -----------------------: | -----------------------: |
| CT117E-M4：进入运行态   | 13.48 s（13.31–16.99 s） |   9.44 s（9.40–14.19 s） |
| CT117E-M4：LCD 首次蓝底 | 14.05 s（13.87–17.72 s） |   9.97 s（9.94–14.88 s） |
| CT117E-M4：完整十色带   | 17.55 s（17.44–21.78 s） | 13.09 s（13.09–18.43 s） |
| CT107D：进入运行态      |     852 ms（818–883 ms） |     843 ms（802–850 ms） |
| CT107D：数码管首次点亮  |     817 ms（788–854 ms） |     818 ms（766–829 ms） |

CT117E-M4 首蓝较同批基线缩短约 29%；两边都出现慢样本，不能把中位数当作启动上限。剩余优化应先减少动态访存块对未命中系统区和外设路径的重复展开，而不是改步长、提前报告运行态或预热固件。其中首步最大的服务块（PC `0x20000`，约 4.6 万条 IR）也值得单独剖析。

同一 360–390 ms 清屏基准在 Node.js 24.20.0 按基线、候选、候选、基线各跑一组六轮。每组去掉首轮后的墙钟中位数，基线为 65.57、41.51 ms，候选为 38.01、40.98 ms。受前几轮波动影响，也比较每组末两轮：合并墙钟中位数 41.09 → 35.81 ms，进程 CPU 中位数 44.42 → 40.84 ms，未观察到稳态退化。清屏与 440 ms 总工作量一致；五幕 LCD 像素、分立总线对账和 STIR 读回/中断派发回归均通过。

## 第三轮：Flash 地址窗口与静态 LCD 引脚采样

以第二轮生产包为基线。首步探针记录的 247 个块不变；其中 238 个固件块有 705,350 条 IR，9 个服务块中最大的 `0x20000` 有 45,974 条 IR。

- 服务块里的 LCD 电平采样在翻译时已知接线，但每个采样点仍内联了 20 路电平选择树。改为只内联对应引脚的逻辑，保留 LCD 驱动读总线与 GPIO 电平之间的运行期选择。单独应用后，`0x20000` 降至 39,339 条 IR（−14.4%），全首步减少 11,946 条，固件块总量不变。
- 动态访存保留两个 Flash 地址窗口的边界判断，但映射到同一条读取或写入路径。SRAM 快路径仍优先，Flash 控制器检查、内联与延迟写的分界均不变。此项再减少 77,259 条 IR；系统区和其他外设的分派语义不变。两项合计首步从 782,793 降至 **693,588 条**（−11.4%）。

生产 Chromium 无探针 A/B 交替各三轮，仍用新浏览器进程、原始 `HAL_06_LCD.hex`、16 ms 步长和实际像素判据：

| 从点击「运行」起 |   第二轮包中位数（范围） |   第三轮包中位数（范围） |
| ---------------- | -----------------------: | -----------------------: |
| 进入运行态       |   9.43 s（9.42–10.12 s） |    8.48 s（8.44–8.49 s） |
| LCD 首次蓝底     |   9.98 s（9.96–10.66 s） |    8.99 s（8.96–9.00 s） |
| 完整十色带       | 13.14 s（13.11–13.77 s） | 12.05 s（12.02–12.13 s） |

与第二轮包同批相比，首蓝缩短约 9.9%。稳态沿用第二轮的 360–390 ms 清屏窗口与 ABBA 顺序，每组六轮。合并各组末两轮，墙钟中位数 32.11 → 31.50 ms，进程 CPU 中位数 32.89 → 32.28 ms，范围重叠，未观察到稳态退化。清屏及 440 ms 总工作量保持一致。NVIC、取指区和 Flash 回归覆盖内联 `STMIA` 与延迟 `STR`、两个窗口的读回及上界。

第三轮包剩余的 628,091 条固件块 IR 中，按动态地址命中分支的子树计数，157 个动态访存点生成了 215,381 条外设区 IR 和 214,117 条系统区 IR，合计约占固件块的 68%。这是生成量，不是运行期命中率；若继续优化，优先验证能否共享这些冷路径，同时保留现有访存顺序和 SRAM/GPIO 热路径。
