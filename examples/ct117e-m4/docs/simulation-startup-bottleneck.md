# CT117E-M4 启动瓶颈定位

基线为 `34c09f3` 的第五轮生产包，原始 `HAL_06_LCD.hex`，固定 16 ms 步长。**最值得优化的是 `memory.ts` 把动态访存分派复制到每个指令块**：同一批大分支要反复构建、校验和生成执行代码。关闭首步直接 JIT 或推迟通用执行体生成都不是量级上的解决方案。

## 重复从哪里来

[共享 MCU 内核的 `readMemory` / `writeMemory`](../../stm32g431rbt6-core/src/memory.ts) 在无法静态确定地址时，保留 SRAM、Flash、CCM 快路径，然后将外设和系统区的寄存器分派内联到每个访存点。统计 Chromium 首步完成绑定的指令块时，按完整外设区和系统区地址窗口识别命中分支，同一分支内不再重复统计嵌套窗口：

| 首步生成内容                              | IR 操作数 |
| ----------------------------------------- | --------: |
| 全部 247 个块                             |   664,271 |
| 238 个固件块                              |   598,774 |
| 固件块中 157 个动态访存点的系统区命中子树 |   207,741 |
| 同一批访存点的外设区命中子树              |   193,100 |
| 最大服务块 `0x20000`（供比较）            |    39,339 |

两个动态分派子树合计 **400,841 条，约占首步全部 IR 的 60.3%**。按分支结构分组时，忽略源码位置，将结果和局部槽编号归一化，157 份系统区分支只得到 **6 类**；每类仅保留一份的总操作数约 6,900 条。这是重复量的度量，不是已实现的 IR 缩减量，也不能换算成等比例的启动提速。

不能删掉这些分支：诊断构建令被裁掉的分支一旦命中就失败。首先在仿真 **14.55 μs** 命中动态系统区写；恢复该路径后，又在 **20.075 μs** 命中动态非 GPIO 外设读。这两个诊断构建均未跑到首蓝，不用于性能对照。

## 为什么不是先换后端

独立 Chromium 探针将[运行时块校验](../../../packages/device-model/src/validation.ts)再拆分：快照约 0.52–0.57 s，结构 schema 检查 0.48–0.55 s，无绑定的语义校验 0.60–0.67 s，绑定后的语义校验 0.59–0.64 s。这些不含翻译阶段在 Builder 内做的检查。只合并其中一次语义遍历，直接能触及的是约 0.6 s；缩小输入 IR 则能同时减少翻译、快照、校验和两个后端的工作。

另一组实验只改生产包副本的 worker，不开启阶段探针。每种配置使用新 Chromium 进程跑两次，保留真实 LCD 像素判据：

| 配置                            | 进入运行态（两轮） | LCD 首蓝（两轮） |
| ------------------------------- | -----------------: | ---------------: |
| 第五轮基线                      |      7.88 / 7.86 s |    8.37 / 8.35 s |
| 通用执行体首次回退时才生成      |      7.90 / 8.55 s |    8.38 / 9.06 s |
| 只在首个 16 ms 步内禁用直接 JIT |      7.77 / 7.78 s |    8.26 / 8.30 s |

这组小样本不用于判断几十毫秒的差异；它排除了仅推迟其中一个后端就能省掉数秒的预期。实验补丁未进入产品。

## 优先验证的改动

1. **先共享系统区访存实现**。按读写和宽度复用同步处理体；调用点保留地址判断和参数传递。保持访问发生在原指令内，尤其是 `LDM` / `STM` 的顺序、窄访问、读副作用、NVIC / SysTick 与中断检查边界。不要把内联访存统一改成指令结束后的服务。
2. **再共享非 GPIO 外设分派**。保留 SRAM、Flash、CCM 与 GPIO 的现有快路径，沿用原本允许延迟的外设服务。当前[直接 JIT](../../../packages/compiler/src/direct-jit.ts)不支持一般 `call` / `callValue`；共享实现必须能被直接后端调用，或能在命中外设分支时继续执行而不重放指令。仅把树换成普通调用，可能令整个含访存块失去快路径。
3. **用一个系统区原型先验证**：比较首步动态系统区 IR 量、无探针点击到首蓝、360–390 ms 清屏墙钟和总线/像素结果。若首步 IR 下降但清屏退化，先检查直接 JIT 覆盖率和回退，而不是继续展开到更多外设。
