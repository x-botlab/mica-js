# CT117E-M4 冷启动优化：第五轮

以 `199f70b` 的[第四轮生产包](simulation-startup-round-4.md)为基线，同批 A/B 的 LCD 首次蓝底中位数从 **8.61 s 降到 8.30 s（−3.6%）**。

## 瓶颈与改动

第四轮的独立 Chromium 阶段探针显示，装载约 0.10 s，首个 16 ms 仿真步约 7.84 s。其中翻译（含 Builder 校验和板级融合）2.78 s，运行时快照与绑定校验 2.25 s，通用执行体生成 1.49 s，直接 JIT 编译 1.18 s。首步成本仍主要在处理指令块，而非装载或显示。

本轮只改板级融合和内联：按 IR 的控制流节点遍历子区域，不再递归扫描类型、常量和源码位置等元数据。不改写的操作和子区域直接复用；各热函数和常量的索引按生成模型复用，只有存在热调用才执行内联。保留原有采样、引脚写入和帧发布顺序，以及运行时最终快照和绑定校验。

本轮独立 Chromium 探针各跑一次，首步翻译阶段从 2.79 s 降至 2.64 s，两边均为 247 个块、664,271 条 IR 操作（沿用第四轮计数口径）。另在 Node.js 中对两份生产器件包生成的首步 IR 按对象键排序后计算摘要，结果一致。阶段探针用于定位成本，启动收益以无探针 A/B 为准。

## 生产 Chromium A/B

i7-12700K / Chromium 153.0.8010.12。基线、候选各三轮，每轮新建 Chromium 进程，不启用阶段探针或 CPU 采样；使用原始 `HAL_06_LCD.hex` 和固定 16 ms 步长。从点击「运行」开始，按 LCD 实际蓝底与十条互异色带判定两个像素终点。

| 从点击「运行」起 |     第四轮中位数（范围） |     第五轮中位数（范围） |
| ---------------- | -----------------------: | -----------------------: |
| 进入运行态       |    8.10 s（7.95–8.12 s） |    7.83 s（7.82–7.85 s） |
| LCD 首次蓝底     |    8.61 s（8.45–8.65 s） |    8.30 s（8.29–8.32 s） |
| 完整十色带       | 11.60 s（11.53–11.66 s） | 11.38 s（11.37–11.46 s） |

生产包重建入口：`pnpm --filter @mica-js/playground build:workbench`。

## 稳态复核

Node.js 24.20.0 加载两份生产器件包，按基线、候选、候选、基线的顺序各跑一组六轮。合并每组末两轮的 360–390 ms 清屏数据，墙钟中位数 31.40 → 31.24 ms，进程 CPU 中位数 32.19 → 32.20 ms，样本范围重叠，未观察到稳态退化。每轮均为 104,338 次 WR 变化、52,169 次 GRAM 写入和 2 帧；推进至 440 ms 的总工作量也一致。

CT117E-M4 的 16 项测试通过，覆盖原始固件的 LCD 像素与总线对账，以及嵌套热调用只在原分支内展开。

下一轮可优先检查同一指令块的结构检查与实例绑定是否有重复工作，或继续缩小每个动态访存点生成的冷路径。两者都应以保持校验覆盖、访存顺序和 SRAM/GPIO 热路径为前提。
