# CT117E-M4 冷启动优化：第四轮

与 `bade74e` 的第三轮生产包相比，从点击「运行」到 LCD 首次蓝底的中位数从 **8.94 s 降到 8.59 s（−3.9%）**。本轮只改动动态访存分派，未修改固件、板级接线或仿真步长。[前三轮测量](simulation-startup.md)保留各轮的基线和采样口径。

## 改动与首步 IR

- GPIO 动态读取只解码一次寄存器偏移，普通寄存器按端口索引寻址。IDR 共用一条登记路径，原有延迟条件不变；内联 IDR 采样和 LCKR 锁定仍发生在原指令内，ODR 仍读端口影子状态，静态 GPIO 地址的路径不变。
- NVIC 的 ISER/ICER/ISPR/ICPR 共用一次读改写，SCB 的三个 SHPR 字共用窄写合并逻辑。不新增延迟访存，也不改 SysTick 和指令边界的中断派发。

独立阶段探针中，首个 16 ms 仿真步仍翻译 247 个块，IR 从 693,588 降至 **664,271 条（−4.2%）**。减少的 29,317 条全在固件块；其中动态访存的外设区分支从 215,381 降至 193,100 条，系统区分支从 214,117 降至 207,741 条。这些计数反映生成量，不是运行时命中量。

## 生产 Chromium A/B

基线、候选各跑三轮，每轮使用新的 Chromium 进程、不启用阶段探针或 CPU 采样。使用原始 `HAL_06_LCD.hex` 和固定 16 ms 步长，从点击「运行」开始计时。首蓝按 LCD 区域首次出现蓝底判定；完整十色带要求每条内部同色且十条互异。运行态和有效像素是两个不同的终点。

| 从点击「运行」起 |     第三轮中位数（范围） |     第四轮中位数（范围） |
| ---------------- | -----------------------: | -----------------------: |
| 进入运行态       |    8.43 s（8.42–8.86 s） |    8.08 s（8.03–8.13 s） |
| LCD 首次蓝底     |    8.94 s（8.94–9.37 s） |    8.59 s（8.52–8.63 s） |
| 完整十色带       | 12.14 s（12.09–12.54 s） | 11.67 s（11.59–11.71 s） |

## 稳态与行为复核

- Node.js 24.20.0 加载两份生产器件包，以 ABBA 顺序各跑六轮 360–390 ms 清屏基准。合并各组末两轮，墙钟中位数 32.99 → 32.49 ms，进程 CPU 中位数 33.76 → 33.52 ms，样本范围重叠，未观察到退化。
- 清屏窗口均有 104,338 次 WR 变化、52,169 次 GRAM 写入和 2 帧；推进至 440 ms 的总工作量也一致。
- CT117E-M4 的 15 项测试和 STM32G431 的 41 项相关回归通过。新增用例覆盖动态 GPIOB IDR 的延迟有符号读与内联 `LDM`、LCKR 读确认、空端口，以及 NVIC 动态窄写的字节位置、窗口上界和三个 SHPR 字的独立写回。
