# CT117E-M4 LCD 清屏性能阶段报告

本报告中的分层证据和对照读数来自旧板级夹具。当前命令使用融合宿主加载同一个器件包，
仍测 360–390 ms 固定工作量；因宿主和前置步进序列已变化，需另立基线，不能直接外推
历史测量与因果判断。

**2026-11-19 · `HAL_06_LCD` · 部署用融合版**

## 当前结论

**360–390 ms 清屏窗口尚未稳定达到 ≤30 ms 墙钟（1.0× 实时）。** 快轮约 29–30 ms，
几乎没有预算余量。慢轮的额外开销主要在执行线程；分层采样指向生成分片在较低层级的
执行及通用属性访问，不支持把长尾主因归给外层派发，也不优先改 LCD 总线重组或发布。

缩小 resident 分片、省掉最终 PC 回读、合并 MCU 批内直线段、合并 LCD 脏矩形右边界写入
均未保留。省 PC 回读和合并直线段降低了中位数，但未稳定缩短长尾；提前触发挂起也未
消除慢轮。目前只保留运行时的 `stopAfterInstruction` 初始化：两次正反序对照都缩短了
最慢暖轮，合计达标 **7/20 → 9/20**，但最慢仍为 **68.989 ms** 且中位数上升。
部署产物未变。

## 瓶颈证据

- 默认配置的独立线程诊断中，快暖轮墙钟/执行线程 CPU 中位为 **30.335 / 30.436 ms**，
  慢暖轮为 **81.129 / 79.864 ms**（以 45 ms 墙钟分组）。约 50 ms 的差距主要不是
  等待后台线程。关闭 Maglev 没有消除长尾；最高仅使用 Sparkplug 时，暖轮墙钟中位为
  **380.436 ms**。
- 独立 V8 trace 的最慢暖轮记录到 **16 次启动优化、9 次去优化**；约 30 ms 的三个
  暖轮未记录到去优化，六个窗口均未记录到 GC 暂停。trace 用来定位，不能把全部差值
  算成去优化成本。模拟器在窗口内没有新增翻译或编译，不代表 V8 已完成分层优化。
- CPU 采样中，生成分片自身占 **46–54%**，外层生成的 `run` 派发自身占 **13–19%**，
  明确归入发布和状态提交的栈不到 1%。`dataBus()` 仅占三个热点分片源码位置样本的
  **3–4%**；这不是其独占墙钟占比。

## PC 路径证明与适用范围

`nextPc` 是块入口的隐式写入，不是块尾的值。MCU 批处理在每条指令前写顺序后继；
指令分支、服务入口和 fault 可覆盖它。`tickValue` 还会读取当时的架构 PC 作为服务
返回地址。因此不能只凭 `nextPc` 或分片派发提示省掉回读，也不能删除架构写入。

候选只处理模拟器自有普通数据槽上的 resident 块：时长动态、无延时后缀、不外提分支，
块内没有可能改写 PC 的宿主回调。预绑定引脚采样是数据读取，不调用宿主。隐式写入初始化
局部值，此后每次实际执行的架构 PC 写入同时更新该值；正常推进时可直接使用它。若走
发布和 `finishCheckpoint`，反应可能改写 PC，获准继续后必须回读。截止点、拒绝发布、
观察屏障、挂起及续跑路径均保持原行为。

独立探针在清屏窗口记录到 **521,742** 次进入常规尾部派发的块完成，其中 **469,543**
次（**90.0%**）符合条件，**365,145** 次命中分片内相邻 `case`。符合条件的次数中，
**365,176** 次来自含预绑定引脚采样的块。探针在每次符合条件的正常推进上核对局部 PC 与
架构 PC，未发现不一致；不把提前退出和续跑计入分母。热点块每次实际写 PC **4–8 次**
（含隐式写入），因此高覆盖率只证明有机会省回读，不保证整体提速。

## 提前触发真实挂起的诊断

在基线产物上独立开启 V8 trace，只将 **350–360 ms** 的宿主推进由一次改为 233 次，
清屏窗口仍按原来的 10 ms 步长推进。该段 WR 变化均为 20,676；清屏窗口及 440 ms
工作量也一致。加密组观察到 **10 个不同的非零续跑 ID**，未加密组为 1 个。

加密组两个慢轮在清屏窗口内都未再看到先前定位到截止点比较或 `F.resume` 写入的
三处去优化偏移，但执行线程仍分别花了 **87.654 ms** 和 **78.015 ms**。其中一轮
`stepShard127` 仍在 LCD 路径上因 keyed access 反馈不足而去优化，另一轮在所跟踪的
热点中只记录到 `run` 的 `wrong call target`，窗口内仍有优化编译开始和完成。
这说明避免这三处去优化不足以解决长尾；不能据此认定剩余慢轮由某一处去优化造成。
诊断没有改变正式基准，也不把提前推进切点当作优化方案。

## 合并 LCD 脏矩形右边界写入（未保留）

候选只改部署模型 `src/model.ddl` 的 `writeData`：初始化与右边界扩张共用一个
`dirtyX1` 写入点，并把 `dirtyX1` 读取移到分支之前。原判定不变：尚未标脏时初始化，
已有脏矩形时只有不扩张左边界且新列超过旧右边界才更新 `dirtyX1`。因此新增了部分原本
不读右边界的状态槽读取，但未增加该槽的写入。GRAM、地址推进、帧调度和模拟器代码未改。

样本。即使避开后段这次去优化，仍需单独解决清屏入口的低层级执行。

## 清屏入口：执行帧与分片身份

在原有 10 ms 推进切点记录 direct program、执行帧和 `states` 数组的对象身份，
并打开 `--log-ic`。与同一 V8 日志中的窗口标记对齐，按生成脚本和源码位置过滤，
只保留 `stepShard` 前导区 `F.states` 的命名读取 IC 事件。

- **确有重建，但在清屏之前，快慢轮都一样。** 六轮均在 **350–360 ms 模拟时间**
  内将成功的 direct program 构建次数从 **24** 加到 **25**，替换 program 和执行帧，
  `states` 数组未换。**360–390 ms** 内构建次数和这三个对象身份均不变。
- **慢暖轮在同一窗口内的同一脚本上见到新的接收对象形状。** 两个慢暖轮线程 CPU
  为 **79.627 / 68.719 ms**。`stepShard126/127` 在入口后 **0.114–0.361 ms**
  于 `F.states` 报 `wrong map`，各次事件后 **16–27 µs**，原脚本的该读取点
  记录到 `P → P`（仍为多态，但遇到另一形状）。前 10 ms 无 TurboFan 分片叶子。
  三个较快暖轮线程 CPU 为 **30.997–40.311 ms**，前 10 ms 有 **10–39** 个
  TurboFan 分片叶子，没有上述入口 IC 更新。
- 六轮的帧都在窗口内新增了 `stopAfterInstruction` 自有属性。快轮也经历该变化，
  因而变化本身不足以解释长尾；还要看分片在入口前取得了哪种反馈和优化代码。
- 另开 `--log-maps` 的六轮复核确认了具体迁移：`F.states` 在清屏前依次更新到新增
  `blockedMemories`、`publishPending` 后的形状；慢暖轮入口反馈的新形状来自继而增加
  `stopAfterInstruction`。V8 的 transition 源码位置标到 `runDirect` 的
  `if (pending) frame.stopAfterInstruction = true`，即首次续跑路径。该慢暖轮线程 CPU
  **84.241 ms**，前 10 ms 无 TurboFan 分片叶子；另外四个暖轮 **31.759–39.418 ms**，
  前 10 ms 有 **11–41** 个 TurboFan 分片叶子。形状地址只在各自日志内比较，
  transition 记录说明形状从何而来，不是逐个帧的迁移时刻。

复现沿用前面的分层采样命令，额外设 `MICA_CT117E_M4_PROFILE_ENTRY=1`，并给 Vitest
加 `--execArgv=--log-ic`。逐轮对象快照在 `CT117E_TIER_PROFILE` 的 `entry` 中，
编号只在本轮有效；`summary.json` 的 `frameStateLoads` 含窗口前 50 ms（宿主时间）
及窗口内的 `F.states` IC 事件。未记录到 IC 事件不等于没有读取；日志记录的是反馈更新。
要核对形状，在另一组另加 `--execArgv=--log-maps`，用同一 isolate 日志中
`map,Transition` 的目标地址匹配 `frameStateLoads[].map`。

四对的最慢暖轮都缩短，每次对照多一个达标轮；但并非每一对的达标数都增加，
合并中位数也上升。这是小幅、可复现的尾部改善，不是 30 ms 验收通过。

独立六轮 V8 探针复核：六轮在 360 ms 切点都已有 `stopAfterInstruction`，
360–390 ms 内不再记录三个热点分片的 `F.states` 入口 `wrong map` 或该处 IC 更新。
仍有两个慢暖轮（执行线程 **75.155 / 73.549 ms**），前 10 ms 无 TurboFan 分片叶子。
这两轮的三个热分片在窗口前约 **19–22 ms（宿主时间）** 已于 `F.states` 掉层，
新反馈匹配到添加 `publishPending` 后的帧形状；窗口内随后仍有 `F.resume` 写入和
`F.due < deadline` 比较的反馈不足。这表明移除首次续跑的形状变化没有消除入口低层级
执行；晚出现的事件也不能解释之前的开销。

正确性：真实 `HAL_06_LCD` 构建产物推进到 440 ms，分立 LCD/MCU 对账通过。融合、分立
和历史基线的非空签名经 `cmp` 逐字节一致，含清屏窗口计数、最终 GRAM、帧内容哈希与
发布时间。编译器 **100/100**、运行时 JIT 电气/屏障/重建 **18/18**、STM32 裸板
回归 **108/108**、真实适配器符合性 **423/423** 及两个生成 oracle 各 **50** 例通过。
