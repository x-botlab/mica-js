# CT107D EEPROM 与预览优化验收记录

日期：2026-11-15。起始 HEAD：`e908d78c48224b3ab0bca19362cddc7fec661b18`，基线包含原有未提交修改。

评估来源：`/tmp/opencode/ct107d-eeprom-preview-optimization-2026-11-15.md`。

## 结论

- P1、P2、P3 已由指定子代理模型实施，主代理检查实际差异并独立运行回归、类型检查和基准。
- 预览 Node CLI 三轮实时比均大于 `1.0`，中位 `1.063`；未达到建议的 `1.2` 余量。
- 官方 EEPROM 中位实时比由 `0.175` 提升到 `0.337`，仍未达到实时目标；还需要约 `2.97` 倍吞吐。
- E1 未完成。指定模型 `DeepSeek V4.1 Flash 1017 (opencodego)` 的多次实现和设计请求报 `fetch failed` 或服务端长连接关闭。部分请求虽然报错，仍留下了 P1/P2/P3 代码，因此验收依据实际文件和独立验证，而非调用成功状态。未替换子代理模型，主代理未编写生产代码。
- E2、P4 保留为待重新归因的候选；浏览器端未验收。整体“两份负载均超过实时”的目标尚未完成。

## 瓶颈核查

| 项目                      | 核查结论                                                               | 本轮结果                                                                                  |
| ------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| P1：SFR 访问来源混淆      | 属实。指令访问探针把 SFR 钩子内的控制寄存器读取也算作架构访问          | 增加可嵌套、异常后恢复的钩子来源上下文；探针排除内部访问，两份 MCU 镜像一致               |
| P2：fallback 重复静态扫描 | 属实。编译和 fallback 都递归扫描同一 IR，部分 unsupported 分支也先扫描 | 按 `RegionIR` 身份使用 `WeakMap` 缓存摘要；改码的新 IR 重新分析，动态守卫保持独立         |
| P3：叶路径后清空数值缓存  | 属实。`blocksStale` 路径清空所有分解，即使耦合块未改变                 | 保留缓存，复核节点布局、参考和边；矩阵与 anchors 相同才复用分解，成功后提交并清除陈旧标志 |
| E1：空闲 UART 高频服务    | 源码支持归因。REN 空闲期限仍为位时间的 `1/8`，帧内返回保守期限         | 尚未实现边沿唤醒；本轮没有重新计数服务入口，不能把文档中的历史次数当作优化后统计          |
| E2：共享全外设服务        | 现有统一推进结构支持该归因                                             | 尚未实施独立外设时间账本，收益未证明                                                      |
| P4：锁存器无效观察        | `followState` 仍读取 `dataByte()`                                      | 没有测得可消除的独立占比，未修改模型                                                      |

原文所述 `topologyPrepares` 既有失败不适用于本轮起始工作区：`electrical.ts` 起始无未提交修改，优化前 `electrical.mjs --verify-only` 已通过。

P1 的源码 IR 回归确认五个普通 GPIO 热块均无期限写入、无引脚采样，仍发布 8 个引脚意图，递归操作数低于 1000；时间相关 SFR 访问仍带结算。未增加第二份 opcode 分类表。

P3 命中结果缓存时依赖既有不变量：同布局、同参考、同边配置下，已发布电压与当前配置一致。独立审查未发现当前叶路径违反该条件；未来扩展动态参考电压或新的局部更新路径时应重新验证。缓存只保留当前分块，拓扑快照不持有数值缓存链。

## 性能结果

宿主为当前 Linux，Node `24.20.0`；MCU 时钟 `11,059,200 Hz`，`throughput`。重建 simulator 与 CT107D 器件后测试，性能运行串行执行；固件、模型语义、波特率和 host 步长未变。

- EEPROM：预热 120 ms，测量 200 ms，host 步长 2 ms。固件 SHA-256：`c18450f53571913647854cb3a5cd8a73be6014b499cfe5c02e1d663f1b8ec501`。
- 预览：预热 512 ms，测量 1024 ms，host 步长 64 ms。固件 SHA-256：`b15a9f9f4232a70d88d080e2f6336359c701777951685a93177e3264b829bd25`。

### 组合优化：相同 CLI 口径的三轮独立测量

前后三轮分别成组执行，并非交替 A/B；下表描述本次观测差异，不能给 P1/P2 各自分摊收益。

| 负载   | 阶段     | 三轮实时比            | 墙钟中位 ms | CPU 中位 ms | 冷启动墙钟中位 ms |
| ------ | -------- | --------------------- | ----------: | ----------: | ----------------: |
| EEPROM | 基线     | 0.183 / 0.170 / 0.175 |    1143.719 |    1672.786 |         16735.698 |
| EEPROM | P1/P2/P3 | 0.340 / 0.336 / 0.337 |     593.583 |    1113.829 |          7952.745 |
| 预览   | 基线     | 0.759 / 0.774 / 0.764 |    1340.450 |    1616.986 |          1620.477 |
| 预览   | P1/P2/P3 | 1.076 / 1.051 / 1.063 |     963.733 |    1237.522 |           952.805 |

预览墙钟中位下降约 28.1%，吞吐约提升 39.1%；EEPROM 墙钟中位下降约 48.1%，吞吐约提升 92.7%。全部 12 次 CLI 运行故障数为 0。冷启动独立列出，不与稳态混算。

使用已有 `test-results/ct107d-paired.mjs`，`BASELINE_FILE` 指向本轮保存的 `electrical.ts` 基线，P1/P2 和其他输入在两侧保持一致。该夹具与 CLI 不同，其绝对实时比单独报告。

这证明 P3 对当前预览存在可测收益，但不代表原文列出的全部热点成本都被消除。本轮未重新采集完整整板 profile 或分解次数。

## 正确性与质量验收

- Simulator runtime：9 个文件，46 项通过；包含摘要稳态扫描不增长、改码、迟到热 PC、观察者屏障回归。
- 电气 `--verify-only`：通过。新增小网络中 7 次叶更新后的完整求解新增分解均为 0；参考切换复用、阻值变化重新分解、故障注入原子重试均通过；既有浮空、所有权边界和数值 oracle 检查通过。
- 传播计划：18 项通过。
- MCU 定时器、UART、外中断、布局：39 项通过；P1 访问 IR 回归 2 项通过；PCA、SPI、源码夹具 24 项通过。
- 预览轨迹与稳定提交：6 项通过；保留 `2018 / --02…--05`、连续 50 µs 稳定提交，以及 1 ms 观测下的启动瞬态。
- 官方 EEPROM 仍在约 6 ms 写入 `U4[8] = 0x1E`；RTC 仍在约 14 ms 初始化到 `08:30:00`，与基线 CLI 轨迹一致。
- 真实 adapter：419 项符合性场景全部通过；PR 级生成 oracle 的 expressions、electrical 各 50 轮通过。
- Simulator、独立 MCU、CT107D 三包类型检查通过；双 MCU 镜像一致；相关新文件格式检查、`git diff --check` 与编辑器诊断通过。

构建存在 API Extractor 内置 TypeScript 5.9.3 与项目 TypeScript 6.0.3 的既有版本提示，构建成功。未以放宽断言隐藏失败。
